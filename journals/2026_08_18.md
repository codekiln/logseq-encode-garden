- ## No Google Drive surface resolves a relative Markdown path
	- [[Q]]: Does Google Drive render relative [[Markdown]] links and image embeds, for a directory of notes kept beside their images?
	- No, and on none of the three surfaces the question collapses together: Drive's own file preview, import into Google Docs, and paste-from-Markdown into an open document. Only the latter two read the syntax at all, and the documented syntax list has no image form on it.
	- The cause is structural rather than a missing feature. A relative path needs a base directory to resolve against, and no Drive surface supplies one — a converted document is identified by a file ID rather than by a position in a folder, and a paste has no source file even in principle.
	- Which leaves a vault of notes with sibling images choosing what to give up. Keeping it a vault means Drive becomes sync and storage while rendering moves to [[Obsidian]], [[Logseq]], or a static build, where paths resolve against a real filesystem.
- ## Claude for Excel, and No Claude for Sheets
	- [[Q]]: What can Claude actually do with [[Google]] Drive, Docs and Sheets, and what can reach inside a file that already exists?
	- Search and retrieval are mature on nearly every surface. Writing is where they diverge, and the divergence is the answer: the first-party connector uploads, creates folders, shares, moves and trashes, and file creation authors a new document. None of it edits a Doc or Sheet already in the drive.
	- [[Anthropic]] ships in-place editing for Excel, Word, PowerPoint and Outlook, and nothing equivalent for the Google applications. Google's own Drive MCP server carries one write tool, `create_file`, and no Docs or Sheets server exists at all.
	- So the capability exists only where something calls Google's APIs directly — [[Claude/Code]] against the Docs and Sheets REST APIs, or clasp and Apps Script, or a community Workspace [[MCP]] server, which is a trust decision rather than a feature.
- ## The tmux status line was repeating one session, not listing four
	- [[Q]]: Why does the [[tmux]] status-right repeat one session name instead of listing every session?
	- It was never counting sessions. tmux expands `#{...}` across the whole format string before handing `#(...)` to the shell, so the inner `list-sessions -F` template has already collapsed to the drawing client's own session by the time the command runs. `list-sessions` then prints that identical string once per session it finds.
	- Escaping the inner hashes as `##{...}` passes the template through intact. Better still, the `#{S:...}` modifier loops a format over every session with no subshell, no escaping puzzle, and no once-a-second shell job.
	- The option was never in `~/.config/tmux/tmux.conf`. It came from a runtime `tmux set -g` in an unrelated project's layout script, and `set -g` is server-global, so every session on the server inherited it, including ones started later for different work. `set -gu` restores the default.
