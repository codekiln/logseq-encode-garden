- # Depth Over Detection
	- [[herdr]] is out after two weeks, and not because the blocked/working/done pane label stopped working. A workspace holds panes, and one 32-character agent name had to carry the repository and the work item together.
	- [[tmux]] names five levels instead and lets each one be short: session, window, pane, `claude` session, branch and worktree. `C-b w` walks the lot in one picker. Written up as [[My/AI/Agent/Fleet]].
	- The trade is real, though. Nothing in [[tmux]] tells you which agent is blocked; the state now comes out of the session's own transcript rather than off the pane border.
- # Whose Equals Sign Is It
	- To [[tmux]], `-t =session` means match this name exactly. To [[Zsh]], `=word` means go find that command and substitute its path. They collide on precisely the argument where the tmux reading is wanted, and zsh wins, because it never hands the word over.
	- The error says `hayward-2026-08-24 not found` and mentions nothing named tmux, which is what makes it read like a missing session. [[tmux/Q/Why does a tmux -t =session target fail in zsh?]]
- # Ahead of What, Exactly
	- Six commits sat unpushed here since [[2026/08/17]]. `git status` called it six ahead, which was true, and said nothing about the thirty commits that had arrived behind them — because the ref it compares against is a local one that no read command updates.
	- One `git fetch` turned six-ahead-and-clean into six-ahead-and-thirty-behind. The instrument was not wrong; it answered the question it was built for, and the missing half was one command away. [[git/Q/Does an ahead-behind count against origin reflect the remote's current state?]]
- # Forty Columns, On Loan
	- [[tmux/Option/status-left-length]] is `40` on the running server, which is the only reason a session name like `hayward-2026-08-24` renders instead of stopping at `[hayward-2`.
	- It is nowhere in `~/.config/tmux/tmux.conf` — that file's whole stated intention is to stay close to stock. So the setting is a runtime `set -g`, server-global and durable right up until the server dies, at which point the cap quietly returns to `10`.
