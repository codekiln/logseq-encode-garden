GitP/A/Log/26/11/09-Mon/B2 Asset Links

  • Garden pages can link B2 files by relative path, as ../assets/.remote/logseq-encode-garden/<file>, once all of these are true:
    • Logseq desktop shows files linked that way.
    • gitpa's website and feed builds turn those links into public URLs, and so does the garden's site build.
    • The proxy sync stops copying linked media into gitpa.
    • Every linked file can be restored locally.
  • This page answers #348 Analyze B2 asset links across the garden and gitpa: it lists where each of those changes goes, so that #347 Link B2 assets by relative path and publish them as public URLs can be built. Code links below point at garden commit 590b8ea docs: plan the Forevertron pack repo and gitpa commit 2efc165 Merge pull request #169 from codekiln/claude/lsg-v0.0.46.

  • Inventory

    • About 1,500 garden pages link about 800 distinct B2 files, nearly all through https://s3.us-east-005.backblazeb2.com/logseq-encode-garden/<file>. Most file names contain spaces, written as %20. Most of the files are MicroFreak preset .bin files and manual screenshots; the rest are session recordings, MIDI files and a few photos.
    • In the design in #347 Link B2 assets by relative path and publish them as public URLs, a mount is an entry in a checked-in TOML file at a garden's root that ties a folder under assets/.remote/ to a bucket, a DVC remote and a public base URL. Nobody has named that file yet. gitpa's proxied pages link only files the garden links too, so a mount declared in the garden covers every gitpa link.
    • Every linked file is a public object at the bucket root, with these exceptions:
      • Four log pages written before the file names settled link through the older https://f005.backblazeb2.com/file/logseq-encode-garden/… form: GitP/A/Log/26/09/26 Sat - RSS Project, GitP/A/Log/26/10/04 Sun, GitP/A/Log/26/10/04 Sun/Dvc for Knowledge Gardens/Plan and GitP/A/Log/26/10/04 Sun/Podcast/Plan. On the October 4 page, GitP___26___09___24___24-Thu___Asset___Synth___Full.mp3 and GitP___26___09___24-Thu___Asset___Synth___Full.mp3 have no object behind them, and the September 24 and September 25 episode MP3s sit under gitpa/episodes/ instead of the bucket root. These are historical log entries; the migration can leave them as written.
      • GitP/How To/Draft an Episode from Session Assets and GitP/A/Log/26/10/08 Thu - rename October 6 session/Plan show the B2 URL form with a placeholder file name (<page-derived filename> and <new name>). They are templates, so the migration leaves them as written.
    • Only two public objects have no page linking them: GitP___A___Session___26___10___24-Sat___Asset___MIDI___Full.mid and IMG_0528.PNG. They get DVC pointers too.
    • About two in five linked files have a DVC pointer in assets/.remote/. The rest, mostly the preset .bin files and about 70 screenshots, exist only as public objects, so DVC cannot restore them yet. Every B2 file gets a DVC pointer: each of these goes through asset:add (download, add, push) before its page switches to a relative link.
    • Four WAV pages already link ../assets/.remote/<file> by relative path. Their files are DVC backups with no public object. They move into the garden's mount folder along with everything else.
    • The bucket holds about 5.5 GB: about 1.4 GB of public objects at the root and about 4 GB of DVC cache under dvc/. A full local copy of every linked file is about 1.4 GB plus the WAVs, which fits on the Mac with room to spare.
    • The root checkout currently holds six local copies under assets/.remote/: three MP3s, two WAVs and one MIDI file.

  • Rendering in Logseq desktop

    • codekiln opens GitP/A/Log/26/11/09-Mon/B2 Asset Links/Render Test in Logseq desktop in the root checkout, where its files are already restored, and records here whether each image shows, whether the MP3 plays and whether the plain link opens the image. The test page links the same image twice, once with spaces written as %20 and once inside angle brackets. About 730 linked files keep spaces in their names until an agent working on #347 Link B2 assets by relative path and publish them as public URLs copies them to hyphenated names. An agent that links one of those files before then writes each space in the form whose image Logseq showed. If neither image shows, Logseq cannot follow relative links into the dot folder assets/.remote/, and the folder layout needs rethinking before any page switches.

  • Where gitpa's builds must turn relative links into public URLs

    • The website build reads the proxied graph through prepare in prepare_site.py. A new step will replace the ../assets/.remote/logseq-encode-garden/ prefix of each link with the mount's public URL, https://s3.us-east-005.backblazeb2.com/logseq-encode-garden/; neither gitpa nor the garden does this yet. The step goes where prepare loads each page body, before listener_body runs: listener_body accepts only https:// links in an asset page and stops with "Expected one public media URL" on a relative one.
    • prepare ends with shutil.copytree(source, output). copytree follows symbolic links by default, so on the Mac it would copy the whole garden folder behind assets/.remote/logseq-encode-garden into the temporary graph. The copy needs to skip assets/.remote/.
    • compile_episode in audio_chapters.py finds the recording with an https:// pattern. The website build calls it on the prepared graph, after the new step has turned links into public URLs. test_source_publication calls it on the checked-in page directly, so that test has to turn the page's links into public URLs first.
    • The feed reads the checked-in graph directly in load_episodes in build_rss.py. Both MP3 patterns there, on the episode page and on its asset page, require https://, so load_episodes has to turn each body's relative links into public URLs before those patterns run.
    • Tests to extend: test_prepare_site, test_build_rss, test_audio_chapters and test_source_publication.

  • What CI reads

    • No CI step in gitpa reads a local media file. The feed takes each enclosure's length and type from a HEAD request to the public URL (audio_metadata). Chapters come from page text. The only local file a build reads is the podcast artwork under gitp-garden/assets/gitp/, which Git tracks.
    • The garden's site build runs lsg publish on the checkout itself (main in mise-tasks/site/build). It has no step that edits page text. To publish relative links as public URLs, the site build task will copy pages/ and journals/ to a temporary folder, rewrite the links in that copy, and run lsg publish on it. Leaving assets/.remote/ out of the copy keeps media files off the published site.
    • lsg publish keeps only the label of an image, audio embed or plain link whose ../assets/ target is missing. When it builds the render test page in a checkout without the page's files, the published page shows the image, the MP3 and the link as plain-text labels. Until the site build turns relative links into public URLs, any page switched to a relative link loses its media on the garden's site the same way.

  • Proxy sync

    • add_page in core.py copies the target of every ../assets/ link into the destination. The garden's copy of the task matches gitpa's.
    • Under the design in #347 Link B2 assets by relative path and publish them as public URLs, add_page will stop copying the file behind a link under ../assets/.remote/<mount>/. It will look up <mount> in the source garden's mount file and add the same path and public to the destination's mount file, with source naming the garden that owns the files. When the source garden declares no such mount, the sync will stop and name the page and the mount.
    • When the destination's mount file already declares that mount with the same path and public, the sync will leave it alone. When either differs, the sync will stop, since the destination's published URLs would change.

  • A clean checkout

    • An agent working without local copies or B2 credentials sees links to missing files. Once the mount file exists, it will give each mount's public URL, so the agent can turn any relative link into a public URL and read or download the file over HTTPS. asset:fetch needs the encrypted fnox cache in the main checkout and stops early without it.
    • Logseq in such a checkout shows broken images until the files are fetched.

  • Path convention

    • A page links ../assets/.remote/<owning garden>/<file>. <file> is the page-derived name and the object's key at the bucket root.
    • On 2026-11-11 codekiln chose to replace each space in an asset page name with a hyphen in its file name, so new links need no %20. Logseq/Entity/Asset states the rule.
    • An agent working on #347 Link B2 assets by relative path and publish them as public URLs will copy each object with a space in its key to a hyphenated key and point the page's link at the copy. That covers about 730 of the linked files, nearly all MicroFreak and Launchpad screenshots and preset .bin files. No podcast enclosure has a space in its name, so the feed's URLs stay the same. The old keys stay in the bucket until codekiln approves deleting them after the migration.
    • Two tasks build file names from page names and need to write hyphens: asset_name in b2_upload.py behind gitpa:media:upload, and the preset .bin name in preset_page.py.
