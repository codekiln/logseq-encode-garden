    • The 1Password names now reflect the two roles. Backblaze administration retains the existing account-wide key and its local .env mount. logseq-encode-publishing exists but has no variables or mount yet. The current rclone wrapper still reads the old mount path, so the two roles are not operationally separated until a bucket-scoped key is created and the wrapper is switched.
    • The concern about a read-only mount is fair. The real requirement is that an agent can author a public page from another checkout without this Mac's mount. A stable URL on a media domain you control lets Logseq, GitHub, CI, and remote agents read an existing public asset directly. A local mount or downloaded copy can remain an optional editing convenience. For newly created remote assets, an agent needs a scoped upload path; otherwise the page should use an existing URL or an asset committed to Git until upload is available. This is a design proposal, pending the choice between source URLs and relative links above.
    • rclone mount presents B2 as a filesystem, but a remote file read may fetch data on a cache miss, and directory access may require remote listing. The number of B2 requests depends on rclone's VFS and directory caches; a filesystem read is not always one B2 request. At current Backblaze pay-as-you-go pricing, Class A/B/C API calls are free, while direct downloads count against the included egress of 3× average monthly storage before overage charges. The larger practical costs for this workflow may be latency, offline failure, and sandbox access to FUSE or credentials.
