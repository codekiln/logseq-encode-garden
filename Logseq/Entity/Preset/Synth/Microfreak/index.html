logseq-entity
Logseq/Entity/Definition

  • MicroFreak Synth Preset

    • In this garden, MicroFreak Synth Preset pages model individual saved sounds on the Microfreak, following Logseq/Entity/Preset/Synth.

    • Placement and identity

      • Pages use Microfreak/Preset/<slot> <name>, with a three-digit slot and the name observed at creation. The namespace models the presets currently on codekiln's MicroFreak, so each slot has at most one page. Saving a new sound into a slot replaces its page: the new sound gets a new page, and the old page is deleted. Git history keeps the deleted pages.
      • Microfreak/Preset/396 Anit and Microfreak/Preset/397 Imit illustrate the frontmatter and notes format. Repeated names or slot numbers alone cannot establish that two observations are the same saved sound.

    • What the sources can capture

      • The saved-header inventory reads slot, name, category and initialization status. It cannot detect a same-name edit to oscillator, filter, envelope, modulation or sequence settings. The Elektroid header decoder supplies the protocol evidence.
      • Elektroid’s preset download and serialization retain the preset payload for export: up to 146 blocks of 32 bytes. Supported payloads contain labeled raw parameter records for oscillator, filter, envelopes, LFO, modulation routes and preset settings. Repeated live reads matched the corresponding MIDI Control Center export byte for byte; the parameter inspection documentation records the framing and remaining interpretation limits.
      • The parameter inspection task reads a saved export with mise run microfreak:inspect /private/path/preset.bin or a computer project with mise run microfreak:inspect /private/path/project.mfprojz --slot 1. It reports exact stored bytes and named raw fields, identifies unsupported layouts, and leaves the input unchanged. Its local implementation preserves the distinction between raw values and unverified display conversions.
      • --interpret-fw5 adds the existing firmware 5 interpretations beside the raw fields: supported oscillator model and control names, normalized or metadata-scaled value domains, and source evidence for each interpretation. The report states the firmware assumption; an export does not establish its firmware version. Unknown models retain generic field names, and unsupported values retain their raw readings. The option leaves the raw report and preset notes intact.
      • Raw values describe saved base settings; modulation, performance gestures and unsaved edits affect the audible sound. Instrument display units, sequence contents, matrix destination meanings and referenced sample or wavetable identities require further verification. Firmware 5 oscillator indices follow the research cited in the optional interpretation report. A computer project can differ from the current device inventory.
      • Microfreak/UG/17 Ext Gear/09 MIDI CC Control and Microfreak/UG/21 Appendix D - CC Values describe MIDI control changes. A stream of knob movements is incomplete evidence of a saved sound: parameters that never change remain unobserved. Microfreak/UG/04 Presets/05 Digital Control explains why panel positions may differ from recalled values.
      • Microfreak/UG/06 Dig Osc/03 Types defines oscillator models. Microfreak/UG/04 Presets/03 Preset Config defines per-preset settings, including voice behavior, scale and sequencer options. These guides describe meanings and ranges; values for a particular saved sound need a read or observation of that sound.
      • Samples and user wavetables have separate export workflows in Microfreak/UG/14 Config/02 MIDI Control Center/03 Samples Tab/01 Management and Microfreak/UG/14 Config/02 MIDI Control Center/02 Wavetables Tab/01 Management. A preset export alone does not establish that those resources are preserved. Global settings such as tuning and tempo behavior also affect playback; see Microfreak/UG/14 Config/02 MIDI Control Center/01 Device Tab.

    • Session-linked research

      • A saved preset referenced by a published session has notes covering Saved export and provenance, Oscillator, Filter, Envelopes, LFO, Modulation matrix, and Performance and session context. These sections explain supported settings and their control meanings, with cited sources and explicit uncertainty.
      • Provenance identifies the export, capture date, bank or slot when relevant, and file digest. A verified match to an archived factory payload establishes that saved baseline; it does not establish a session-time capture or the instrument's unsaved state.
      • Values carry verified units or a clearly named normalized or raw domain. Unknown display conversions, matrix destinations, firmware assumptions and resource identities remain qualified. Large raw inventories stay outside the notes unless their numbers help explain the sound.
      • Performance notes distinguish what the saved patch supports from changes heard or recorded during a session. An unidentified initialized sound is described plainly rather than assigned an invented numbered preset or presumed settings.

    • Sync

      • The MicroFreak sync task previews the connected device with mise run microfreak:sync; --apply updates its saved metadata. The sync implementation on GitHub is also available as a local file.
      • --save-inventory /tmp/microfreak-inventory.json stores a full inventory; --inventory /tmp/microfreak-inventory.json previews that capture. --garden /absolute/path/to/worktree selects the destination and --port 'Arturia MicroFreak' selects an exact endpoint.
      • A complete successful inventory updates reported fields, omits initialized slots and marks missing sounds absent; pages marked absent are then deleted. Partial reads write nothing. Handwritten notes, established origin, verified oscillator type and export references survive metadata refreshes. A saved inventory describes its capture time; a new device read is needed to establish current state.
      • Header sync performs no binary export. File and digest properties are populated only after an export and its destination have been verified.
