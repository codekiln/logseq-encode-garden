My/AI/Agent/Chief of Staff/Log/26/08/24 Mon

  • 2026-08-24 Mon
    • First day with the seat in a tmux session rather than a herdr workspace, and the first run as several context windows instead of one — My/AI/Agent/Fleet/Bed Down. No scribe ran, so the journal and the commits sat with the seat.

    • A test can pass on every input that could not have failed

      • A claim about tmux session names went out having been tested only against targets that named a window explicitly, session:0. That is the single target shape a stray dot in the name leaves alone, so the test passed on everything it was given and confirmed the opposite of the truth. Bare targets — has-session among them — fail on such a name: tmux/Q/Why does a session name containing a dot break every bare -t target?.
      • The falsifier was already written down beside the claim. It cost one command and was not run, which is the same omission as reading an ahead-behind count without fetching first (git/Q/Does an ahead-behind count against origin reflect the remote's current state?) and as calling a capability absent after four refusals. None of the three lacked evidence; all three had it one command away.
      • So a rule that holds on every sample tried is not yet a finding. Look for the sample that would break it, and if none can be constructed, say which inputs were tried.

    • An absence is a dated claim, not a property

      • A seat met four refusals on claude --chrome, recorded the capability as unavailable, and after bedding down ran the identical command successfully first try. Meanwhile the fleet had a source written down as blocked when only one route to it was — the constraint belonged to the fallback tool, not to the thing being reached. My/AI/Agent/Fleet/Browser now leads with the route that works.
      • Bedding down is therefore a retry, and the useful shape for an absence is the shape of a count: what was tried, when, and what the failure looked like. Written as a property, an absence never gets retested, because nothing about it says it might have expired.

    • A governing page can be out of date and still governs

      • Logseq/Journal and Logseq/Journal/Editorial headings instruct topic-led narrative blocks above the change log. Person/codekiln deleted three such blocks from their own journal on 2026-08-18 Tue and has written none since; 08-16, 08-18 and 08-19 are change log only. Following the pages put five of them into today's journal before the record of that deletion was read.
      • Neither source is wrong about what it says. The page says what the practice was, the journals say what it is, and the page carries no date, so nothing on its face marks it as the older one. What settled it was reading the last four journals rather than reasoning about which kind of source ought to win.
      • Where a page and an observed human action disagree, the action decides the immediate question and the disagreement is worth filing rather than quietly obeying one side. Changing a convention page is not the reading agent's call; noticing that it teaches something nobody does any longer is.

    • A convention claim stops being true when it crosses a repository

      • The fleet's conventions held that tmp/ is gitignored, and reasoned from it: that working notes there are private, and that git add -f on such a file bypasses a secret scan. In this garden .gitignore carries no tmp rule at all, three notes under tmp/ are tracked, and anything written there is published. The warned-of bypass does not exist here, and neither does the privacy it assumed.
      • A claim of that shape reads as being about the harness when it is really about one checkout, so it travels intact and arrives false. git check-ignore answers it per repository in one call. My/AI/Agent/Fleet now asks the question rather than carrying the answer.

    • A name that has changed four times should not be written as a literal

      • The seat's session was ls-encode-garden, then hayward-ls-encode-garden, then hayward-2026-08-24, then hayward-2026-08-24-LEG — two of those changes on one day. Every page naming the current one as a literal was wrong within days of being written, and a successor reading it has no way to tell a stale literal from a live one.
      • The repair is to name the scheme where the scheme is decided and to name the command that reads the live value, tmux display-message -p '#{session_name}'. A page describing a pattern survives the next rename; a page quoting a value has to be found and edited.

    • The rule that held was the one nobody was awake to enforce

      • A peer seat committed into this shared checkout mid-task, and the seat's own next commit landed on top of theirs without either noticing. Nothing collided, because both stage named paths; git add -A at that moment would have swept up work in flight. The 2026-08-18 Tue entry on My/AI/Agent/Chief of Staff/Scribe reached this conclusion with a scribe present to enforce it — today it held with no scribe at all, which is the stronger form of the same evidence.
      • It follows that default-branch, in-sync and tree-clean are readings of a moment in any shared checkout, and a report saying so should say when it was read.

    • The morning, and what it produced

      • Three context windows, the third taking the seat at 11:55 and closing the morning at codekiln's wrap. CursorAI/Explanation/Grok Bot on a Teams seat filed from a worker that ran 8m 4s; archive.ph updated with a result Person/codekiln tested themselves; the fleet's browser rule filed on My/AI/Agent/Fleet/Browser; the display swept twice. Every commit pushed, no worker left running, and no window left open past its commit.
      • The seat also answered a peer's search of this graph — whether it already held a note on getting past Medium's login wall. It did: one page, ten months old, never revisited since the day it was written.

    • A brief's hedge can be wrong in the direction of caution

      • The Grok Bot brief expected the product name to be a voice-input mis-transcription of Cursor's Bugbot, and told the worker to stop and ask rather than choose between that and xAI's Grok. Neither guess was needed. The product is real under the name as heard, with its own Cursor documentation, and the worker settled it from a primary source before writing a line.
      • The instruction was still right, and the reason is worth separating from the outcome. "Stop rather than guess" is what prevented a coin-flip between two real products, and it cost nothing when the question turned out to have a documented answer. What a brief cannot know is which of its own uncertainties are already settled somewhere in public.
      • So read a stop-and-ask instruction as do not guess rather than as do not resolve. Looking for the source that decides the question is not guessing, and it is cheaper than an escalation — this one cost one fetch and saved a round trip through a human.

    • A stranded input box does not say who typed it

      • Text sat unsent in the worker's input box — add it to today's journal, never processed as a turn. It resembled the send-keys stranding failure this seat has recorded twice, which would have made a third occurrence and would have answered the open question of whether that failure earns a rule of its own.
      • It was filed as an observation and explicitly not as that evidence, because a stranded box cannot distinguish a script's send from a person typing and walking away, and those two have different fixes. Asking settled it: the peer seat had used no send-keys all day, having sent every message through the cross-session channel, so a person typed it.
      • One candidate cannot be ruled out by anything still readable — the predecessor context, now dead. It is unlikely rather than excluded: its own brief made the seat responsible for the journal, so instructing the worker to write one would have contradicted the instruction it had just issued.
      • The general form is that when a data point's provenance decides which claim it supports, the provenance is the finding. Asking cost one message. Filing it as a third occurrence would have put an unattributed claim into a decision about a standing rule, which is the same error this day already recorded twice under carrying a claim forward without its source.

    • A guard can be committed, correctly aimed, and never have run

      • This graph declares a pre-commit identity guard in a tracked lefthook.yml, whose own opening comment says it exists to keep personal and employer identifiers out of a public graph. It had never executed. lefthook install writes dispatchers into .git/hooks, that directory held nothing but the stock samples, and its mtime predated the commit that added the guard by twelve days — so the guard was declared, tracked, and inert for seventy-five days while the thing it was written to prevent happened.
      • .git/hooks is not tracked, which makes this the default state of every fresh clone rather than a slip in one checkout. A repository can only ship the declaration; whether it runs is per-clone and invisible from the repository.
      • The reason it is worse than having no hook at all is that it inspects clean. A missing hook is visible to anyone who looks; a tracked config naming the exact failure mode reads as protection from every place a person would check, including the commit that introduced it. The reading is ls .git/hooks, not the config file.

    • A privacy judgement can be made at the right moment and scoped to the wrong unit

      • The leak that prompted this had already been considered. The seat writing the page deliberately withheld the account addresses from a public repository and recorded that decision — and published the domain, which was the employer. The unit it chose was addresses; the unit that mattered was identity.
      • No word list would have taught it the difference, and the guard's own list did not carry the institution's name either. Both the human judgement and the mechanical check were narrower than the question, independently, in the same direction.
      • So a redaction is worth re-reading against what it was protecting rather than against what it removed. "The addresses are off the page" is a true sentence that answers a smaller question than the one being asked.

    • Staging named paths protects against other files, not against a second writer in the same file

      • The entry above on this page concluded that the rule held with nobody awake to enforce it, on the strength of two agents committing into one checkout without colliding. That is true for disjoint files and it is the whole of what named-path staging buys.
      • It does not survive two writers in one file. A commit here staged a single named journal path and carried away two edits the human had made to that same file in the interval — a sentence in their own voice and a formatting fix — under an agent's commit message and co-author trailer, which then claimed authorship of a human's prose.
      • The missing check is cheap and it is not the one that was run. git status before editing describes the tree at that moment; git diff --cached before committing describes what is actually about to be recorded. In a shared checkout only the second one answers the question.

    • An exemption can read as applied and do nothing

      • Suppressing a check on one line has two silent failure modes here. An in-file directive written with a colon before its reason is ignored entirely. A directive on a file's final line is ignored when the file has no trailing newline, which is the state of 491 of 800 pages sampled in this graph.
      • Both produce the same artefact: an annotation that is present, correctly spelled, carrying a good reason, on the right line, and dead. It survives review because reviewing it means reading it, and reading it is exactly what makes it look right.
      • This is the same defect as a redaction tool that reports clean after removing one of five identifiers — a mechanism certifying an outcome it did not produce. Having met it twice from opposite directions, the rule is to re-run the check after suppressing it, never to annotate and move on.

    • A finding count can argue for the wrong fix

      • Installing the guard turned up sixty findings across eighteen files. Ten were the thing it was built for. Seven were the employer named as a public fact about other people — conference speakers, a faculty profile, verbatim public transcripts. Forty-three were a home-directory path in pages whose value is the copied machine output.
      • Acting on the count would have installed a gate whose first act was to block the seat's own handoff commit over a path in a note whose entire purpose is to be committed on a deadline. That is how a guard earns a permanent bypass, and the switched-off guard is the cost — not the wasted trip.
      • The count needed classifying before it could be acted on, and the classification changed the recommendation twice. A number that measures what a tool noticed is not a measure of what is wrong.
