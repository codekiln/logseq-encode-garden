Task/Management/Git-Friendly/26/05/Comparison

  • Git-friendly task manager comparison

    • Evaluation criteria

      • A good replacement for this repo should store task state in Git-friendly text files or Git-native objects, avoid SQLite as the committed source of truth, and work from a CLI without requiring a hosted service.
      • It should be legible to AI coding agents without dumping huge JSONL blobs into context, support basic issue states and dependencies, and have a clear ready/blocked view for resuming work.

      • beadwork

        • jallum/beadwork

          • CLI/Tool that implements a git-backed issue tracker for AI agents.

          • Data/Model

            • plans, progress, and decisions live as files on an orphan branch instead of mixing into the main worktree.

          • My Notes

            • design.md looks like what I've thought about building

              • All data lives on a git orphan branch, manipulated directly in the object database via go-git. Every operation is an atomic commit. Sync uses fetch-rebase-push with intent replay on conflict.

              • For storage layout and sync mechanics, see docs/design.md.

            • ~44 GitHub/Stars as of 2026-05-26 Tue
            • includes Self/Update - To update an existing install: bw upgrade.

          • CLI commands

            • bw init                                           # initialize in any git repo
bw onboard                                        # print bootstrap snippet for CLAUDE.md / GEMINI.md
bw create "Fix auth bug" --type bug -p 1          # create an issue
bw ready                                          # list unblocked work
bw comment bw-a1b2 "Fixed in latest deploy"       # add a comment
bw close bw-a1b2                                  # close it
bw sync                                           # push to remote

            • Dependencies - see bw dep

            • written in Go; see source for bw executable here

          • Data/Model

            • Where stored:
              • Personal mode: configured via ff config dataDir; config is in XDG config at ff/config.yaml unless project mode applies.
              • Project mode: if run inside a Git repo, it creates/uses .ff in that repo. README example shows after ff add, the repo contains .ff .git, and you commit .ff.
            • On disk it appears collection-oriented, like:

              • Note
                • status: Active, Archived, or Wiki

                • track: external issue-tracking metadata
                • links: set of Link refs
                • recurring: bool

      • tk

        • wedow/ticket: Fast, powerful, git-native ticket tracking in a single bash script. Dependency graphs, priority levels, zero setup.

          • CLI/Tool that implements a git-backed issue tracker for AI agents.

          • Data Model

            • Markdown Yaml Frontmatter files in .tickets/.

          • My Notes

            • there's a "migrating from beads" section of the README with a Beads uninstall script migrate-beads
            • Rooted in the Unix/Philosophy
              • inspired by Person/Joe Armstrong/Blog/14/06/25/Minimal Viable Program
            • as of 2026-05-26 Tue, hasn't been updated in two months, probably because it's got a small surface area
            • uses Behavior/Driven/Development with the behave python library; see the features directory for files such as ticket_notes.feature.

          • Features

    • Excluded

      • OpenSpec - it's not really a task manager. It's only oriented at "what's the next change"
      • td and td/sidecar remain useful references, but this garden's definition of Task/Management/Git-Friendly rejects SQLite-backed task state as not truly Git-friendly for this purpose.
      • HamsterBase Tasks and Will Be Done are interesting local-first task apps, but they are GUI or app-sync oriented rather than CLI repo-local Beads replacements.
