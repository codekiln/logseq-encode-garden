Obsidian/Q/Can a keyboard shortcut add a block id to a todo?

  • Can a Keyshort add a block id to a todo in Obsidian, compatible with a Logseq/Block/Reference?

    • AI Answer

      • Short answer: yes for the block id — a todo is a list item, and two plugins already tracked here mint an id and copy a link to it from one bindable command. No for the Logseq half: nothing produces a ((uuid)) that Logseq resolves.

      • Native block ids reach a todo, but no command mints them

        • Answer/Official from Link to a block in a note.
        • A block is "a unit of text in your note, such as a paragraph, block quote, or list item," so a - [ ] task line qualifies. For a list item the identifier sits directly on the bullet: - [ ] call the bank ^37006f.
        • Typing ^ inside a link opens a picker of existing blocks, and [[^^text]] searches blocks across the vault.
        • Obsidian ships no command that creates an identifier, so out of the box there is nothing in Settings → Hotkeys to bind.

      • Plugins that mint the id on a keystroke

        • Obsidian/Plugin/Easy Copy — Contextual Copy with Auto block ID enabled generates an identifier for the block under the cursor and copies [[Note#^blockid|summary]]. Already bound here to ⌥ ⇧ C, per No default hotkey — assign one in Settings → Hotkeys. The README suggests Ctrl+Alt+C (⌘⌥C on macOS) but that combo may not be registerable in the Obsidian hotkeys UI; ⌥⇧C is a working alternative..
        • Obsidian/Plugin/Copy Link — Copy block link auto-creates or reuses an identifier and yields [[Note#^blockid]], one link per line across a multi-block selection. It also offers Copy anchor link ([[#^blockid]]) and Copy block URL (an obsidian://open deep link). Installed through BRAT rather than the directory.
        • Both are ordinary commands, so either can carry a hotkey. Neither treats a task line specially, which is what makes them work on todos.

      • Where compatibility stops

        • Obsidian writes ^blockid trailing the line and references it as [[Note#^blockid]], embedding as ![[Note#^blockid]].
        • Logseq writes id:: <uuid> as a block property on its own line and references it as ((uuid)).
        • The identifier format and the reference syntax both differ, so a link either tool makes is inert in the other. A bridge would need a plugin that writes id:: <uuid> beneath the task and copies ((uuid)) to the clipboard.
        • Obsidian/Plugin/Obsidian Todoseq is the closest thing that exists: it reads Logseq's TODO / DOING / DONE / LATER / NOW / WAIT keywords and SCHEDULED: / DEADLINE: metadata. It carries the task vocabulary across, not the reference syntax.

      • Scope of this answer

        • Drawn from the official Obsidian help and from the plugins recorded in this garden. The full community directory was not swept, so a ((uuid))-emitting plugin may exist unrecorded.
Obsidian/Q/Does Obsidian have a Collapse All feature, and can the collapse state live in the markdown?

Page reference

  • Does Obsidian have a Collapse All feature, and can the collapse state live in the markdown like Logseq/Block/Attribute/collapsed?

    • AI Answer

      • yes to Collapse All — it ships as Obsidian/Command/Fold all headings and lists, which could
        • that could be bound to a Keyshort.collapsed:: true.
      • No to the collapse state living in markdown; Obsidian keeps fold state in localStorage. See How Obsidian stores data
      • Two community plugins fix that by writing a %% fold %% comment onto the folded line, which is the closest thing Obsidian has to logseq's functionality.

      • The native Collapse All

        • Answer/Official from Folding - Obsidian Help.
          • Fold all headings and lists collapses the whole note; Unfold all headings and lists reverses it. Both are ordinary commands, so either can take a hotkey in Settings → Hotkeys.
          • Fold heading and Fold indent must be on under Settings → Editor for folding to work at all.
          • Fold more and Fold less act on the section under the cursor rather than the note, for finer control.
          • The file explorer and the outline pane carry their own collapse-all buttons; those fold the tree, not the document.

      • Plugins that put the fold in the document

        • Both write %% fold %% onto the folded line. It is Obsidian's native comment syntax, so it is invisible in Reading view and inert to any other tool reading the file — closer to a hidden marker than to Logseq's declared property.
        • Creases by Liam Cain — in the community directory, ~45k downloads. Works on headings and lists. Adds Toggle crease, Fold along creases, Iron out the creases, Crease the current folds, and vim-style fold-level commands. The model is deliberate: a crease is a fold you declared, not a record of how you last left the note.
        • Foldstate — manual install only, not in the directory. Headings only, and only in Live Preview or Source mode. The model is automatic: every fold and unfold rewrites the marker, so the file records the note's current state.
        • Sync Folds takes the third path — fold state goes into the plugin's own data.json rather than the note. It syncs across devices but leaves the markdown untouched, so it does not answer the question as asked.

      • Which one matches the preference

        • For a fold that lives in the document and is set on purpose, Creases is the closer fit: it is maintained, in the directory, and covers lists as well as headings.
        • For a fold that mirrors how the note was last left, without any deliberate act, Foldstate is the only one that does it — at the cost of a manual install and heading-only coverage.

      • Scope of this answer

        • Drawn from the official Obsidian help and the plugins' own repositories. Download counts and update dates were read in September 2026.

  • The challenge in achieving metanarrative fluency in linked, proxied logseq pages is making a shortcut to creating and copying a block reference in the upstream page. In a single garden, I can press Cmd+C to generate and copy a UUID block reference that gets expanded elsewhere. But if I'm in the "downstream" representation of a page and I click Cmd+C in Logseq, it creates a Logseq/Block/Reference that doesn't propagate to the "upstream" representation easily. So, I'd like to make a way that if a page is a Logseq/Entity/Proxy/Page and it points to a remote garden, then the Cmd+C keyboard shortcut or another affordance would create a block reference that would originate in the upstream page, so subsequent syncs of the page would bring it down, creating a stable reference.

  • This is all very related to an idea from earlier this year, using two fuzzy hashes to represent a range for discussion. In general, markdown documents don't generally provide the best method of providing rich commentary on discussion. That's actually one of the core motivating features for Logseq: if markdown consists of Logseq/Blocks that are unordered lists in Markdown, then one can nest as deep as you practically could need in order to satisfy the ability to go deeper into the topic and provide metanarrative. But with logseq proxies, one can't comment on the upstream page easily ... but one could get around this with the hack mentioned above.
