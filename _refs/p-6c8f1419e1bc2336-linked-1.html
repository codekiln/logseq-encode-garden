  • TIL
    • MCP (Model Context Protocol) is a pun on MCP — the Master Control Program — from the 1982 Tron movie, where MCP was the villainous AI that sought to dominate all computer programs
    • Skills can be bundled into an MCP/Server, making them available to any MCP client (not just Claude Code)
    • MCP/Server deployments that scale to zero need a token cache layer — e.g. Redis, KV, DynamoDB, or Cloudflare/DurableObjects — since in-process token state is lost on each cold start
    • Async server-side agents calling protected APIs need Auth/M2M (client credentials / short-lived JWT) rather than user-delegated flows, since there is no human present to authorize

  • TIL
    • Claude/Code permission prompts: when Claude asks for permission, option 2 is often a very specific command — you can select it and then use the delete key to broaden it. For example, bd --no-daemon --specific-flags ... becomes bd --no-daemon *, and the entry saved to .claude/settings.local.json is "Bash(bd --no-daemon *)". See Claude/Code/How To/Answer Permission Dialog To Record Wildcard Permissions in Local Settings.
    • text (double-equals) highlighting in Logseq is not standard Markdown — it's a Pandoc extension that renders as HTML <mark>. Obsidian also supports it, but CommonMark does not.
    • in tmux (or oh-my-tmux — not sure which), you can drag the divider between two panes with the mouse to resize them live. Mouse mode must be enabled; the feature likely comes from set -g mouse on in .tmux.conf, which hands pointer events to the terminal multiplexer so it can interpret drag gestures on pane borders.
    • github.com/codespaces lists all your GitHub Codespaces and lets you request a usage report for each one.
    • github.com/codespaces also lets you export unpushed changes to a new branch before deleting a Codespace — so you don't lose work when cleaning up.
    • github.com/settings/billing/budgets lets you set a spending budget per product — e.g. $5 for GitHub Codespaces — to cap usage costs. Trying this out; will update once confirmed.

Person/Jan-Erik Rediger/TIL/Nix/minimal flake for a shell

  • A minimal flake for a shell — TIL

    • Author: Person/Jan-Erik Rediger
    • Source: fnordig.de TIL

    • Flake (minimal dev shell)

      • 		{
		  description = "A very basic flake";
		  outputs = { self, nixpkgs, ... }:
		    let
		      supportedSystems = [ "aarch64-linux" "aarch64-darwin" "x86_64-darwin" "x86_64-linux" ];
		      forAllSystems = nixpkgs.lib.genAttrs supportedSystems;
		    in
		    {
		      devShells = forAllSystems (system:
		        let
		          pkgs = nixpkgs.legacyPackages.${system};
		        in
		        {
		          default = pkgs.mkShell {
		            buildInputs = with pkgs;
		              [
		                ripgrep
		              ];
		          };
		        });
		    };
		}
      • Run with: nix develop

    • Old way (shell.nix)

      • 		with import <nixpkgs> {};
		pkgs.mkShell {
		  nativeBuildInputs = with pkgs; [
		    ripgrep
		  ];
		}
      • Run with: nix-shell
