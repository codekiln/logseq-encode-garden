Logseq/Date
Logseq DateFormat by precision
  • Older Dates Grouped by Century and Decade - 17/4/9 for 1749 or 18/3/2 for 1832. Useful for older dates so as to cluster them together by decade. Maybe eventually decades or centuries will be named or have themes for mnemonic purposes. See Logseq/Entity/Time/Year for the full entity that models this grouping.
Logseq DateRulesMost of the time, more precision is preferred if factually confirmed, but not always.
  • For the dates that correspond to when a durable work like a Logseq/Entity/Book was published, it's probably better use use a longer time horizon representation like [[YYYY]]. There's a reason copyright pages don't list "Jan 29, 1946, 3:36 PM Trieste"

AbbreviationWhen we treat something as an abbreviation entity

Logseq/Entity/AI/Leaderboard

Page reference

AI Leaderboard
  • In this garden, AI Leaderboard pages model a current ranked list of Logseq/Entity/AI/Model pages along one dimension — Intelligence, Speed, Cost per Task — taken from a named public board such as ArtificialAnalysis.
AI LeaderboardWhat counts as an instance
  • Not an instance: a single model's metrics page, which is a Logseq/Entity/AI/Model/Doc/Analysis; official vendor docs, which are a Logseq/Entity/AI/Model/Doc/API.
AI LeaderboardHow a refresh works
  • Every row is a garden model page plus its score. A model already in the garden is linked at its canonical path. A top-row model that is missing is created as a Logseq/Entity/AI/Model (stub is enough) with its Logseq/Entity/AI/Model/Doc/API when the official URL is known.
AI LeaderboardRelationship to other types
  • Logseq/Entity/AI/Model — each row.
AI LeaderboardRelationship to other types
  • Logseq/Entity/AI/Model/Doc/Analysis — the per-model source card behind a score.
Logseq/Entity/AI/Model

Page reference

AI ModelWhat counts as an instance
  • Not an instance: a kind of model. AI/Model/Reasoning, AI/Model/World, AI/Model/Open Weight and their siblings under AI/Model/ classify models; they are Logseq/Entity/Term or Logseq/Entity/Concept pages that instances link to.
AI ModelWhat counts as an instance
  • Not an instance: the official docs page or a third-party metrics card. Those are Logseq/Entity/AI/Model/Doc/API and Logseq/Entity/AI/Model/Doc/Analysis, nested under the model.
AI ModelNaming and links
  • Pages live under the provider's namespace. The provider should be an instance of Logseq/Entity/Company or Logseq/Entity/Organization. Version numbers that contain a decimal split the same way Logseq/Entity/Time/Year splits a year: most significant digit group first, then the next. Claude Opus 5.5 is Anthropic/Model/Claude/5/5/Opus, not Claude/Opus/5.5 and not Claude/5.5/Opus. Claude Fable 5.1 is Anthropic/Model/Claude/5/1/Fable. GPT-4.1 is OpenAI/Model/GPT/4/1.
AI ModelFrontmatter
  • It should have standard entity attribution in Logseq/Entity/Frontmatter.
AI ModelPage shape
  • After the H1, embed the model's docs namespace — at minimum the Logseq/Entity/AI/Model/Doc/API page, and any Logseq/Entity/AI/Model/Doc/Analysis pages worth seeing on the model itself. That is a Logseq/Page/Embed:
    • {{embed [[Provider/Model/…/Doc/API]]}}
    • {{embed [[Provider/Model/…/Doc/Artificial Analysis/Intelligence]]}}
AI ModelWriting an instance
  • Deduplicate first: model code, official docs URL, provider path, and any Logseq/Entity/AI/Leaderboard row that already names it.
AI ModelWriting an instance
  • When a Logseq/Entity/AI/Leaderboard is being refreshed and this model is missing from the garden, a thin page plus Doc/API is enough. A later pass can fill house sections.
AI ModelRelationship to other types
  • Logseq/Entity/AI/Model/Doc/API — official documentation, nested at <model>/Doc/API and embedded at the top of the model page.
AI ModelRelationship to other types
  • Logseq/Entity/AI/Model/Doc/Analysis — third-party metrics for the same release.
AI ModelRelationship to other types
  • Logseq/Entity/AI/Leaderboard — ranked lists that point at model pages.
AI ModelRelationship to other types
  • Logseq/Entity/Term / Logseq/Entity/Concept — the AI/Model/<Kind> pages that classify models, and the concepts a model page cites.
AI ModelRelationship to other types
  • Logseq/Entity/Person — researchers and founders link to the models they shipped, not the reverse.

Logseq/Entity/Axiom

Page reference

Axiom
  • In this garden, Axiom pages model statements that hold by proof or by physical law—provable with internal consistency within a formal system (mathematical or logical axioms), or established laws of nature with predictive force. This is the contrast class to Logseq/Entity/Named Law: not a shortcut, and not defeasible by gaming or fashion.
AxiomRelationship to other types
  • Logseq/Entity/Named Law — the "masquerading as laws" category: eponymous laws, effects, and fallacies that are useful but defeasible. When something is called a law but can be gamed, can expire, or admits exceptions, it is a named law, not an axiom.
AxiomRelationship to other types
  • Logseq/Entity/Concept — use when the goal is an understanding-oriented essay rather than anchoring a single provable statement. The distinction itself is explained at Epistemics/Concept/Heuristic vs Axiom.
AxiomRelationship to other types
  • Logseq/Entity/Term — glossary stubs only.

Book

Logseq/Entity/CLI/Command

Page reference

CLI CommandWhen we treat something as a CLI command entity
  • Not Logseq/Entity/Software/Project: that type models the product; command entities model individual subcommands under the product namespace.
CLI CommandNaming and links
  • File shape: pages/{tool}___{command}___{path}.md with triple underscores between segments; preserve --flag-style segments when they are command-level (rare); flag options use Logseq/Entity/CLI/Flag instead.
CLI CommandRelationship to other types
  • Flags: options for a command are Logseq/Entity/CLI/Flag pages nested under the command path (e.g. mise/unuse/--global).
Logseq/Entity/CLI/Flag

Page reference

CLI FlagWhen we treat something as a CLI flag entity
  • Not this type: standalone subcommands (use Logseq/Entity/CLI/Command), global config keys, environment variables, or Agent/Command.
CLI FlagRelationship to other types
  • Parent: always a Logseq/Entity/CLI/Command instance (or command stub) for the owning subcommand.
