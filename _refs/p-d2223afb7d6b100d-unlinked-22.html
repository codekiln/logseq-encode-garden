  • Why it fits: a detuned Microfreak/UG/06 Dig Osc/03 Types/02 SuperWave one octave down, with a slow attack and a filter that a held envelope sweeps open. It swells in like strings in a horror score. Paraphonic mode lets you hold dark chords.
  • Why it fits: a Microfreak/UG/06 Dig Osc/03 Types/03 Wavetable through a high-pass filter with high resonance, a slow attack and a release that runs nearly as long as the instrument allows. A slow triangle LFO moves the timbre. Notes ring on after you let go, like an echo in an empty house.
  • Why it fits: a Microfreak/UG/06 Dig Osc/03 Types/13 Noise oscillator through a nearly closed band-pass filter, with a slow attack and a slow random LFO adjusting the cycling envelope. Filtered noise that rises and falls sounds like wind through a broken window.
  • Why it fits: Microfreak/UG/06 Dig Osc/03 Types/08 Two Op.FM through a band-pass filter, with a slow attack and a filtered random LFO on the cutoff. The band-pass thins the sound like a small speaker, and the random movement wobbles it like warped tape. An old song on a broken machine is a staple of ghost stories.
  • Why it fits: the Microfreak/UG/06 Dig Osc/03 Types/10 Chords oscillator plays a full chord from each key, with paraphonic mode on and a sine LFO adding a slight vibrato. A pipe organ in a minor key is the haunted-house sound most people know, from Bach's Toccata and Fugue in D minor.
  • Why it fits: the Microfreak/UG/06 Dig Osc/03 Types/12 Modal oscillator models a struck resonating body, and this patch is tuned as tubular bells with a medium decay. The opening of Mike Oldfield's "Tubular Bells" became the theme of The Exorcist. Twelve strokes on one bell is also the midnight chime.
  • Why it fits: a Microfreak/UG/06 Dig Osc/03 Types/16 HARM lead with a resonant low-pass filter, a short decay with no sustain, and paraphonic voices. Pressure adds noise to the oscillator. The name points at 1970s horror-film scores, and plucked resonant chords with breath-like noise fit that era.
  • Why it fits: a Microfreak/UG/06 Dig Osc/03 Types/15 SAWX through a band-pass filter, with the cycling envelope pushing both wave and timbre fully. Each note opens with a sweep that sounds like a growl.
  • Why it fits: a Microfreak/UG/06 Dig Osc/03 Types/07 Waveshaper whose timbre is driven by both the cycling envelope and a clock-synced Sample-and-Hold LFO. Obsidian/Q/Are there any Obsidian plugins which provide better support for Markdown front matter YAML?
  • Short answer: Yes. Nested Properties is the closest fit for a vault that stores nested YAML in frontmatter. It renders nested objects and arrays as a collapsible tree in Obsidian's Properties editor, supports adding and editing fields at any level, and records property types by dotted path. Its documentation includes an array-of-objects example, where fields such as versions.version and versions.released retain their types across every list item.
  • Use Metadata Menu when repeated objects need a form and a field schema. Its Object and Object List field types represent a collection and a list of collections, and field settings can be defined globally or through a FileClass. That gives a more structured editing workflow than raw YAML. The maintainer says they have limited time for the project, so try it with a small representative vault before making it central to a workflow. Answer/Official from Metadata Menu.
Obsidian/Q/Can Obsidian be configured to show markdown files in folders that begin with a dot (dot-folders), e.g. to edit .claude/skills/<skill-name>/SKILL.md?
  • Short answer: Not natively — Obsidian hides any file or folder whose name starts with a dot from the file explorer, search, and graph, and there is no core setting to reveal them (the "Detect all file extensions" setting only affects unsupported file types, not dot-prefixed names). Community plugins close the gap.
  • Show Hidden Files — broader, all-or-nothing. Exposes every dotfile/dot-folder plus unsupported file types at once by intercepting the vault adapter's deletion-reconciliation step (which is what Obsidian normally uses to hide dotfiles) and re-registering them. Simpler to install, but it also surfaces sensitive files like .env or .git-credentials, so it's less scoped than opting in folder-by-folder.
  • Hidden folders (dotfiles) not showing in File Explorer despite "Detect all file types" — Obsidian Forum

Obsidian/Q/Does obsidian allow a list of links to other obsidian pages in the YAML markdown frontmatter?
  • In Obsidian 1.4+, frontmatter is surfaced as Properties. Each property has a type; the relevant types for page links are:
    • Link — a single wikilink to one note (type: link in the Properties view)
    • Link list — an array of wikilinks (type: multitext / shown as "List" with link items)
  • You can also declare the type explicitly in Settings → Properties so Obsidian uses the link-picker UI when editing.

Obsidian/Q/In obsidian, is there a way to insert a reference to a future date, something like a command to look up a date and be able to create the standard reference?
  • Short answer: Obsidian's built-in tools only insert today's date. For future-date wikilinks (e.g. [[2026-06-25]]), the community Natural Language Dates plugin is the most direct fit — type @next friday or @in 2 weeks anywhere in a note and it resolves to the correctly formatted daily-note link. The Templater plugin handles scripted offset dates.
  • Install from community plugins. After enabling, type @ followed by a natural-language expression:
    • @tomorrow → [[2026-06-18]]
    • @next monday → next Monday's ISO date as a daily-note wikilink
    • @in 2 weeks → two weeks from today
    • @June 25 → [[2026-06-25]]
