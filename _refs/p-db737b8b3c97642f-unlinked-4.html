rulesync/Explanation/Rulesync authenticates to GitHub with GITHUB_TOKEN
  • A gh auth login on macOS keeps the token in the Keychain. Rulesync never asks gh for it, so a shell that is signed in to gh still runs rulesync anonymously.

  • Why gh auth status succeeds while rulesync fails

    • gh auth status reads the keyring. The environment variables are a separate channel, and nothing copies the keyring token into them.
    • gh auth token prints the keyring token, so GITHUB_TOKEN=$(gh auth token) rulesync install bridges the two.
  • mise has its own token lookup for its own GitHub calls. It reads GITHUB_TOKEN, token files, the gh hosts.yml file, and a credential_command. On macOS the gh token sits in the Keychain, so mise needs credential_command = 'gh auth token --hostname "$MISE_CREDENTIAL_HOST"' to see it. See mise/Config/Setting/github.credential_command.
  • 1. A mise/Task/File that exports GITHUB_TOKEN from gh auth token and then runs rulesync install and rulesync generate. The hook calls mise run <task>. One repository changes, and no token touches disk. This is the fix codekiln/logseq-garden uses, as rulesync:sync.
  • 2. GH_TOKEN exported from the shell profile, as export GH_TOKEN=$(gh auth token). Every program started from that shell sees it, at the cost of one gh call per shell.
  • bash
    			  #!/usr/bin/env bash
			  #MISE description="Install rulesync sources and regenerate tool config, authenticated with the gh login"
			  set -euo pipefail
			  if [[ -z "${GITHUB_TOKEN:-}${GH_TOKEN:-}" ]] && command -v gh >/dev/null; then
			    GITHUB_TOKEN="$(gh auth token 2>/dev/null || true)"
			    export GITHUB_TOKEN
			  fi
			  rulesync install
			  rulesync generate
rulesync/Skill/Declarative Source
  • bash
    			  export GITHUB_TOKEN=$(gh auth token)

  • Using local git auth (e.g. Git Credential Manager) instead of GITHUB_TOKEN

    • The plain owner/repo shorthand always uses the default "github" transport, which reads only GITHUB_TOKEN/GH_TOKEN — it never consults local git credentials.
    • To fetch a private repo's skills via local git auth (SSH keys or an HTTPS credential helper like Git Credential Manager) instead, set the transport to git and give a full URL rather than the owner/repo shorthand:
      • jsonc
        			  { "source": "https://github.com/owner/private-repo", "transport": "git", "ref": "main", "path": "rulesync/skills" }
    • No rulesync.jsonc hand-editing is required — rulesync add exposes this as flags directly:
      • bash
        			  rulesync add https://github.com/owner/private-repo --transport git --ref main --path rulesync/skills --skills skill-creator
Security/ABAC
  • Authorization decides whether a subject may perform an action on a resource. Role-Based Access Control (RBAC) assigns permissions to named roles, then assigns users or services to those roles. Attribute-Based Access Control (ABAC) evaluates policy conditions over attributes of the subject, resource, action, and sometimes the surrounding environment.
Security/Application/DAST
  • “DAST duplicates SAST” — Incomplete; many bugs (routing, auth state, infra headers) appear only at runtime.
Security/Application/SAST
  • SAST analyzes first-party source code (and sometimes bytecode/IR) without executing the full app: dataflow, control flow, pattern rules, taint tracking, and policy checks to flag classes like injection, unsafe crypto, or auth mistakes.
Security/RBAC
  • RBAC is an authorization model that grants permissions based on predefined roles assigned to users
Security/Vulnerability
  • Running behavior — Security/Application/DAST (and adjacent IAST / observability) finds issues that appear only when the system executes with real routing, auth state, and infrastructure.
