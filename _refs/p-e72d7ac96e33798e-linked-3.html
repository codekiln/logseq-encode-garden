Logseq/Entity
Logseq EntityNaming entity definition pages
  • All entity definition pages under Logseq/Entity/ use Title Case nouns. Multi-word names use nested namespace segments, for example Logseq/Entity/Software/Project.
Logseq/Entity/CLI/Command
CLI CommandWhen we treat something as a CLI command entity
  • Not Logseq/Entity/Software/Project: that type models the product; command entities model individual subcommands under the product namespace.
Logseq/Entity/Collection
Collection
  • In this garden, the Collection pattern models a curated collection whose members are all instances of some other entity type. It is not instantiated directly — it is specialized per member type as <EntityType>/Collection (e.g. Logseq/Entity/Software/Plugin/Collection), and each specialization points back here for the shared rules.
CollectionSpecializations in this garden
  • Logseq/Entity/Software/Plugin/Collection — curated collections of plugins for a host (LazyVim extras, VS Code Extension Packs, …).
Logseq/Entity/Color/Theme
Color Theme
  • In this garden, Color Theme pages model coordinated palette families (foreground, background, accent colors) reused across terminals, editors, multiplexers, file managers, and other UI tools. A color-theme instance is the aesthetic system (e.g. Catppuccin with subpages Catppuccin/Latte, Catppuccin/Frappe, Catppuccin/Macchiato, Catppuccin/Mocha); individual ports often stay Logseq/Entity/Software/Project instance pages that link back to the theme hub.
Color ThemeRelationship to Software/Project
  • Official or community ports (Neovim plugin repo, tmux plugin, etc.) can be software project entities with logseq-entity:: Logseq/Entity/Software/Project; they should link to the color-theme hub for palette and flavor semantics. The theme hub lists app wiring without duplicating full plugin documentation.
Logseq/Entity/Company
Company
  • In this garden, Company pages model commercial vendors, businesses, product firms, devtool vendors, consulting companies, and brands tracked as first-class pages—often because they ship multiple Logseq/Entity/Software/Project pages linked with created-by::.
Logseq/Entity/Definition
Entity DefinitionExamples in this garden
  • Logseq/Entity/Person, Logseq/Entity/Software/Project, Logseq/Entity/Book, and the other pages under the Logseq/Entity/ namespace.
Logseq/Entity/Dotfiles/Dep
Dotfiles DependencyWhat counts as an instance
  • Not an instance: a software project with no bearing on the dotfiles (model it as Logseq/Entity/Software/Project alone); a My/Pref or My/Principle page.
Dotfiles DependencyRelationships to other types
  • Logseq/Entity/Software/Project — a dependency that is also a shipping project may declare both, primary entity first.
Logseq/Entity/Dotfiles/Dep/Idea
Dotfiles Dependency IdeaWhat counts as an instance
  • Not an instance: the tool itself (that is a Logseq/Entity/Dotfiles/Dep, and usually also a Logseq/Entity/Software/Project); a My/Pref or My/Principle page.
Dotfiles Dependency IdeaRelationships to other types
  • Logseq/Entity/Software/Project — the candidate tools weighed for an idea are software projects.
Logseq/Entity/File/Format
File FormatWhen we treat something as a file format entity
  • Not this type: a specific document saved in the format; the application that reads or writes it (model that as Logseq/Entity/Software/Project).
File FormatRelationship to other entity types
  • Logseq/Entity/Software/Project — applications and libraries that implement the format stay separate entities, linked from the format page.
Logseq/Entity/Font
FontWhen we treat something as a font
  • Not this type: font patchers, aggregators, or patcher projects (e.g. Font/nerdfonts, Font/Nerd Font) — model those as Logseq/Entity/Software/Project.
