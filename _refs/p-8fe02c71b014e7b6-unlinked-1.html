Claude/Desktop/Code/Q/How can I get Claude Desktop to render a Mermaid diagram in Claude Code's markdown output?

Page reference

  • Short answer: Not in the transcript. The Code tab prints a `mermaid fence as raw source text — same as the CLI — and there is no Code/Preview toggle for it. To see a rendered diagram you have to route the fence out of the chat into a surface that does render Mermaid: an artifact, the Browser pane, or a pre-rendered image.
  • Native rendering in the desktop Code tab is an open enhancement, not a shipped feature: #52517 — Mermaid code blocks not rendered in Claude Code tab (opened April 2026, area:desktop, no maintainer response). It asks for exactly the Code/Preview toggle claude.ai artifacts have, defaulting to Preview. The sibling request for the terminal TUI, #14375, proposes mermaid-ascii instead and is also open.
  • Answer/Official from Share session output as artifacts. Ask Claude to publish the document as an artifact. Artifacts render Mermaid natively — a `mermaid fence in a published .md, or a <pre class="mermaid"> block in a published .html — with no external library, so the strict artifact CSP is not a problem.
  • Write the diagram into a single .html file — either the mmdc SVG inlined, or a <pre class="mermaid"> block with mermaid.js bundled locally rather than pulled from a CDN — and click its path. Useful when the diagram belongs alongside other prose or several diagrams on one page and you don't want it published to claude.ai.
  • veelenga/claude-mermaid is an MCP server that renders Mermaid in a browser and hot-reloads as Claude edits the source. Good for iterating on a diagram's layout; adds a server to maintain.

QuartzMD/Q/Is there a way to render Mermaid diagrams in a QuartzMD site?

Page reference

  • Short answer: Yes. Quartz has built-in Mermaid support enabled through the ObsidianFlavoredMarkdown plugin. Diagrams render automatically and adapt to the site's light/dark theme.
  • Syntax: Use a standard mermaid fenced code block in your Markdown:

    • sequenceDiagram
      Alice->>Bob: Hello
      Bob-->>Alice: Hi!

  • Mermaid rendering is part of the ObsidianFlavoredMarkdown plugin in quartz.config.ts. It is enabled by default in a standard Quartz install.
  • Mermaid is rendered client-side via JavaScript. An open GitHub issue (#1699) tracks a request to render diagrams to static SVG at build time instead.
  • Quartz — Mermaid Diagrams
  • Issue #1699: feat(mermaid): options to render to static SVG

Structurizr

Page reference

  • Intentionally not UML; constrained box-centric notation with styles, themes, groups, and element-level icons—suited to rigorous software architecture modeling rather than a rich vendor-icon “architecture board” look (compare diagrams, D2, Diagram/Mermaid).
  • DSL parser, validation, diagram generation, export (PlantUML, Mermaid, PNG/SVG, static site).
  • Typical: parse DSL → JSON, validate, export diagrams (PlantUML, Mermaid), inspect models.
  • Trade-offs: less visually free-form than general diagram languages; weaker fit than some tools for dense vendor/service icon boards (again vs diagrams, D2, Diagram/Mermaid).
