Claude/Code/Settings
  • Managed — deployed by IT as a file in a system location, through MDM or OS policy, or delivered from the server at sign-in. Applies to everyone in the organization or on the machine, and cannot be overridden from below.
  • model and outputStyle are read once at startup. Use /model to switch model mid-session; outputStyle is part of the system prompt and is rebuilt on /clear or on restart.
  • agent — run the main thread as a named agent, applying that agent's system prompt, tool restrictions, and model. Example: "code-reviewer".
  • includeGitInstructions — set false to leave the built-in commit and pull-request workflow instructions out of the system prompt. Default true.
  • outputStyle — output style adjusting the system prompt. Read at startup and rebuilt on /clear. Example: "Explanatory". See the output styles documentation.
  • USE_BUILTIN_RIPGREP — set 0 to use the system rg instead of the bundled one.
  • Identity and access management — the permission system and tool-specific rule syntax.

Claude/Desktop/Q/How can I disable notifications for Claude Desktop?
  • Short answer: Claude/Desktop has no documented in-app toggle for its OS notifications — turn them off the same way you'd turn off any desktop app's notifications, through the operating system.
  • macOS: System Settings → Notifications → Claude → toggle off Allow Notifications (or set the alert style to None).
  • Windows: Settings → System → Notifications → Claude → toggle off.

CursorAI/How To/Share Cursor Project Rules Across Repositories and Users
  • Cursor project rules are a unique set of Metaprogramming tools. A set of related cursor project rules define the CursorAI Agent Mode's Agentic System, each encapsulating a particular aspect of the overall capabilities of that system.

  • Use OS/File/System/Link/Soft

    • While I have not yet documented it under CursorAI Project Rule Tests, I have found that Cursor does follow rules that are symlinked under .cursor/rules. To achieve similar behavior to git submodules, one can clone a repository of project rules and then symlink in the rules.

    • Downsides

      • Extra Tooling
        • This approach opens up the need for a set of tools that can "deploy" a set of symlinks from another repository into the cursor rules.
        • To use cursor project rules in a systematic way, one would want a tool to deploy them systematically.
      • Issues with cross-platform compatibility
        • Symlinks work differently in Linux than in Windows.
        • Symlinks are only stable in git if they are relative paths. If relative paths are made from projects/my-project/.cursor/rules/link-*.mdc to projects/my-centralized-project-rules/link-*.mdc, then all users who edit my-project who wish to use the rules in my-centralized-project-rules will need to place it as a sibling directory to my-project. This is a hard requirement that may or may not make sense for all users.
          • On may work around this by using two symlinks - the first would go from projects/my-project/.cursor/rules/link-*.mdc to projects/my-project/user-rules/link-*.mdc, where my-project/user-rules is added to .gitignore and not in version control, treating it as a directory similar to .vscode or .idea for IDEA, which is allowed to vary between users. It would be a user's responsibility to create symlinks to the rules in this directory on their machine. However, again, there's a need for standardized tooling.

CursorAI/Q/Why does Cursor have token limits that are lower than the model's advertised context limits?
  • Short answer: Cursor caps the default window below the model's advertised max for cost and product defaults — not because the model lacks capacity. Staff have also said Cursor may lower a model's usable limit based on how it performs at that size. The UI meter can look even smaller because system prompts, tools, reasoning, and output reserve share the same window.
  • Why the usage bar can still look short of even Cursor's limit. Reserved space for system/agent instructions, tool definitions, reasoning tokens, and the reply means the "available" user context is less than the configured window. That is separate from the default-vs-max policy above. (Forum thread on truncated available context)
CursorAI/Terminal/Q/Why does the Cursor integrated terminal lack a Nerd Font while Ghostty renders one correctly?
  • CursorAI is a VS Code fork, and VS Code-based terminals read a dedicated terminal.integrated.fontFamily setting (separate from editor.fontFamily) to pick the font for the integrated shell panel. When that key is absent, the terminal uses the platform default monospace font rather than any Nerd Font installed system-wide.

cybernetics
  • Ross Ashby's An Introduction to Cybernetics (1956) gave the field its textbook and its Law of Requisite Variety: a regulator can hold a system steady only if it has at least as many responses as the disturbances it faces. Qian Xuesen's Engineering Cybernetics (1954) made the field a foundation for automation.
  • What kept the name turned toward biology, society and the observer. Heinz von Foerster's Biological Computer Laboratory at the University of Illinois (1958 to the mid-1970s) incubated second-order cybernetics, the cybernetics of observing systems, which puts the scientist inside the loop being described. Maturana and Varela's autopoiesis, Bateson's double bind and its use in family therapy, Stafford Beer's management cybernetics and Viable System Model, and Gordon Pask's conversation theory belong to this wave. Beer's Project Cybersyn in Chile (1971 to 1973) tried to steer a national economy on these principles.
  • Feedback — a system's output returns as its input. Negative feedback pulls toward a goal, as in a thermostat; positive feedback runs away, as with a microphone held to its own speaker.
  • The observer in the loop — second-order cybernetics: a description of a system is made by someone who belongs to a larger system that includes the describing.

DevContainer/Report/25/12/Multi-Env DevContainer Setup
  • JetBrains Gateway Behavior: JetBrains' implementation of devcontainers (as of 2024+) is still maturing and follows the devcontainer spec but with some differences in source handling. JetBrains IDEs (Gateway or IntelliJ with the Dev Containers plugin) typically clone the repository into a Docker volume by default for remote dev containers [5]. Their system creates a volume (e.g. jb_devcontainer_sources_xxx) and populates it with the source, rather than bind-mounting your local workspace [5]. This approach avoids the gRPC FUSE file-sharing layer and its issues. In practice, JetBrains prefers using a named volume for the project code when creating a container from a VCS URL, precisely to dodge the performance and file-sync problems that can occur with bind mounts over remote connections (the "gRPC FUSE memory issues" the user noted). For local projects opened via Gateway, JetBrains can also work with a bind mount, but the remote usage is their primary focus.
