  • Assumption - every clip has a four digit number that identifies MMSS of the clip
    • The first M determines the octave of the drum rack mapping
    • The second M determines the "quadrant" of the octave mapping, given 12 semitones, if M is 3, that would be first quadrant, if second M is 4, that would be 2nd quadrant, etc
    • if there's not room, squeeze into octave, trying to honor halfs instead of quarters, or just trying to squeeze all into octave

  • Unfortunately, AbletonOSC has the clearest network-security defect I found in a mature project. The actual server constructor defaults to local_addr = ('0.0.0.0', OSC_LISTEN_PORT), and its own source explains that this listens on every available local IPv4 interface. The UDP socket is then bound directly to that address. [33] There is no authentication layer in the OSC protocol shown here. Because AbletonOSC provides mutating operations—track creation, parameter changes, playback, clip manipulation, and more—that means another machine able to reach UDP 11000 can potentially control the running Live instance. The README's statement that it “listens on port 11000” understates this important distinction. [7]

Its architecture includes TCP 9877, UDP 9882, optional OSC/UDP 9878/9879, and a web dashboard; the README explicitly shows the dashboard on 127.0.0.1, but in the material I inspected I did not find an equivalent security statement establishing authentication or loopback-only defaults for every Remote Script transport.
