Proxy PageLocating the source
  • With a code forge URL: the host, owner and repository in Logseq/Entity/Proxy/Page/Frontmatter/logseq-proxy-codeforge-url form a ghq address, and ghq list --full-path --exact <address> gives the local clone. One path is the clone; no path means the repository is not cloned here, and cloning waits for the human; several paths wait for the human to pick one. The part of the URL between the branch and pages/ is the graph's folder inside the clone, empty when the graph sits at the repository root.
Proxy PageLocating the source
  • Without one: the graph name in Logseq/Entity/Proxy/Page/Frontmatter/logseq-proxy-url resolves through Logseq desktop's own graph list, ~/.logseq/graphs/, which holds one file per graph with the graph's path in the file name. The graph is the one whose folder carries that name. This resolves only on a machine where Logseq has the graph.

Page reference

Sync a Proxy Page and Its Companion TasksInputs and outputs
  • Copies pages under their source logical names, adds Logseq/Entity/Proxy/Page membership, and sets source URL, available code forge URL, and sync date. Source bodies replace destination bodies.
Sync a Proxy Page and Its Companion TasksInputs and outputs
  • On re-sync, page properties follow the source: new ones are added, changed ones updated, and ones the source dropped are removed. Properties explicitly listed in an entity definition’s entity-proxy-source-properties:: follow the source even when another definition assigns them to the destination. Other destination-owned properties retain their values; tags:: and the proxy keys remain protected. Logseq/Entity/Proxy/Page states the rule; the preview lists each property added, updated or removed.
Sync a Proxy Page and Its Companion TasksDependencies and access
  • Source discovery follows Logseq/Entity/Proxy/Page: a code forge URL resolves through locally registered ghq repositories, and a Logseq graph URL can resolve through the desktop graph list. An explicit --source selects a graph directly.
