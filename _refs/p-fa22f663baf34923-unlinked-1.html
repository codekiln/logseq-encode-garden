Artifact/Management

  • Artifact/Management

    • The practice of controlling, cataloging, and tracking the software artifacts — container images, packages, libraries, binaries — that are deployed across an environment

    • Relationship to zero-day defense

      • When a zero-day hits a library or base image, artifact management lets you answer "who is running this?" immediately
      • Without it, the patch window is consumed hunting for affected systems; with it, you can go straight to remediation
      • Complements Zero/Day/Near response by collapsing the time between "patch available" and "all instances identified"
      • Core idea: shrink the exposure window by knowing your inventory, not by patching faster

    • Key practices

      • SBOM (Software Bill of Materials) — machine-readable manifest of all components in an artifact
      • Version pinning — pin dependencies to known-good digests, not floating tags
      • Private artifact mirrors — proxy public registries so you control what enters the environment
      • Artifact scanning — scan on push and on schedule; integrate with CVE feeds
      • Artifact promotion — move artifacts through dev → staging → prod registries only after passing gates

    • Common tools

      • JFrog Artifactory, Sonatype Nexus, AWS CodeArtifact, GitHub Packages, Cloudsmith

ChatGPT/Sites/Q/To what extent is it possible, either using Claude artifacts or using ChatGPT sites, to have a database that backs the site?
  • Answer/Official from Anthropic: Store data in an artifact.
  • Shared storage exposes the same saved data to everyone using the artifact. Personal storage keeps each person's data private. A shared comment feed uses shared storage.
  • Storage is available on Pro, Max, Team, and Enterprise on web and desktop, with a text-only limit of 20 MB per artifact. JSON can represent comment records within text storage.
  • New artifacts can save before publication. Legacy artifacts require publication, and unpublishing a legacy artifact deletes its stored data.
  • Editors can also upload images, PDFs, and CSVs to an artifact; no storage quota for uploads is published. See Claude/Artifact/Q/How much storage comes with Claude artifacts?.
  • Sites is the stronger fit for a public comment site with accounts and structured records. Claude shared storage can support a small collaborative comment feed within the artifact experience.
Claude/Artifact/Concept/Install as Desktop App

  • Claude/Artifact/Concept/Install as Desktop App

    • A published Claude artifact can be installed as its own app on your computer. It gets a dedicated window, an icon in your app launcher, and no browser tab or address bar.
    • The artifact is a web page at a claude.ai URL, so the feature comes from the browser's PWA install, not from a Claude-specific installer.

    • What you see

      • On the artifact page, the title menu (the name with a chevron, top left) lists Export, Copy as Markdown, Install artifact, and Rename.
      • Install artifact opens Chrome's "Install app" dialog: "Access this site in a dedicated window on your computer". It shows the artifact name followed by "Claude artifact" and the domain claude.ai.
      • Next goes to a second dialog showing the icon moving into a Chrome Apps folder. Install finishes it.
      • A confirmation offers Show in Finder and Open tab in app.

    • What you get

      • A standalone window for one artifact, separate from your browser tabs and from the Claude app.
      • A launcher icon: Start menu on Windows, Launchpad and Spotlight on macOS, as listed by web.dev.
      • Entries in the OS app switcher and app search, with the option to pin to the taskbar on Windows.

    • Windows

      • Windows works. Chrome and Edge both install PWAs on Windows, macOS, Linux, and Chromebooks, per web.dev.
      • In Chrome: More (three dots) → Cast, save, and share → Install page as app, or the install icon at the right end of the address bar. See Google's Chrome Help.
      • In Edge: the App available icon in the address bar, then Install. The app lands in the Start menu and taskbar, and appears under Windows Apps & features. See Microsoft's Edge PWA guide.
      • Edge on Windows can also start the app when you sign in (edge://apps → More options → Auto-start on device login).
      • The browser-level install is documented for Edge. Whether claude.ai shows the Install artifact menu item in Edge is undocumented.
      • Edge has one documented gap: PWAs do not survive logoff in FSLogix virtual-desktop profiles.

    • Browser limits

      • Safari on macOS does not support installability (web.dev). Use Chrome or Edge.
      • Firefox on desktop is not covered by those sources.
      • An app cannot be installed twice in the same browser.

    • Managing the app

      • Chrome: open chrome://apps to see installed apps, create shortcuts, or set launch at sign-in. To remove one, open it and choose More → Uninstall.
      • Edge: edge://apps, or Windows Add or remove programs.

    • Official documentation status

      • Answer/Official for the browser mechanism: the Chrome, Edge, and web.dev pages linked above.
      • No Anthropic Help Center article describes Install artifact. The article What are artifacts and how do I use them? covers viewing, editing, sharing, and exporting, and says nothing on installing.
      • The dialogs in the screenshots are Chrome's own PWA install flow with Claude's name and icon filled in.

  • writes local artifacts (yaml/json) so prompts+schemas are kept in your repo for version control.

		  from typing import Any, Dict, List, Optional, Type
		  import json
		  import os
		  from pathlib import Path
		  
		  from langsmith import Client
		  from langchain_core.prompts import ChatPromptTemplate
		  # example model class provider import; optional:
		  # from langchain_openai import ChatOpenAI
		  
		  # if you use pydantic v1/v2 choose the right method to export schema:
		  try:
		    # pydantic v2
		    from pydantic import BaseModel as PydanticBase
		    def pydantic_to_json_schema(m: Type[PydanticBase]) -> Dict[str, Any]:
		        return m.model_json_schema()
		  except Exception:
		    # fallback for pydantic v1
		    from pydantic import BaseModel as PydanticBase
		    def pydantic_to_json_schema(m: Type[PydanticBase]) -> Dict[str, Any]:
		        return m.schema()
		  
		  class PromptHubSync:
		    def __init__(self, client: Optional[Client] = None, out_dir: str = "prompts"):
		        self.client = client or Client()
		        self.out_dir = Path(out_dir)
		        self.out_dir.mkdir(exist_ok=True, parents=True)
		  
		    def write_local_artifact(self, prompt_id: str, prompt_obj: Any, schema: Optional[Dict]=None):
		        # save prompt text and schema to repo for git/version control
		        base = self.out_dir / prompt_id
		        base.mkdir(exist_ok=True, parents=True)
		        if isinstance(prompt_obj, ChatPromptTemplate):
		            # get something serializable
		            with open(base / "prompt.txt", "w", encoding="utf8") as f:
		                try:
		                    # ChatPromptTemplate has from_messages/from_template; try to format sensibly
		                    f.write(str(prompt_obj))
		                except Exception:
		                    f.write(repr(prompt_obj))
		        else:
		            with open(base / "prompt.obj.json", "w", encoding="utf8") as f:
		                json.dump({"repr": repr(prompt_obj)}, f, indent=2)
		        if schema is not None:
		            with open(base / "schema.json", "w", encoding="utf8") as f:
		                json.dump(schema, f, indent=2)
		  
		    def push_prompt_with_models(
		        self,
		        prompt_id: str,
		        prompt_obj: ChatPromptTemplate,
		        pydantic_schema: Optional[Type[PydanticBase]] = None,
		        models: Optional[List[Dict[str, Any]]] = None,
		        tags: Optional[List[str]] = None,
		        description: Optional[str] = None,
		    ) -> Dict[str,str]:
		        """
		        - prompt_obj: ChatPromptTemplate (or other LangChain prompt object)
		        - pydantic_schema: Optional Pydantic BaseModel class (we attach its JSON Schema as readme)
		        - models: list of dicts each describing a model variant. Each dict can be:
		           {"name": "gpt-4o-mini", "model_obj": <langchain model instance>, "tags": ["g:gpt4o-mini"]}
		          OR: {"name": "gpt-4o-mini", "tags": ["g:gpt4o-mini"]} to only push prompt metadata for that model.
		        Returns mapping model_name -> url of pushed prompt commit.
		        """
		        # 1) save locally (git-managed)
		        schema_json = None
		        if pydantic_schema:
		            schema_json = pydantic_to_json_schema(pydantic_schema)
		        self.write_local_artifact(prompt_id, prompt_obj, schema_json)
		  
		        # 2) push a baseline prompt (content only). We'll put schema JSON in `readme` as a practical workaround.
		        readme_text = None
		        if schema_json:
		            readme_text = json.dumps({"schema": schema_json}, indent=2)
		        baseline_url = self.client.push_prompt(
		            prompt_id,
		            object=prompt_obj,
		            description=description or "",
		            readme=readme_text,
		            tags=tags or [],
		        )
		  
		        results = {"baseline": baseline_url}
		  
		        # 3) push model-specific commits (if model objects supplied, push prompt|model runnables)
		        if models:
		            for m in models:
		                name = m.get("name") or m.get("model") or "model"
		                model_obj = m.get("model_obj")
		                model_tags = (tags or []) + m.get("tags", [])
		                try:
		                    if model_obj is not None:
		                        # push prompt|model so the commit stores the model config LangSmith supports
		                        runnable = prompt_obj | model_obj
		                        url = self.client.push_prompt(f"{prompt_id}-{name}", object=runnable, tags=model_tags, description=(m.get("description") or ""))
		                    else:
		                        # fallback: just push the prompt but tag with the model name
		                        url = self.client.push_prompt(f"{prompt_id}-{name}", object=prompt_obj, tags=model_tags)
		                    results[name] = url
		                except Exception as e:
		                    results[name] = f"ERROR: {e}"
		        return results

		        score: int = Field(..., title="Score")

Logseq/Publish/Explanation/Options for Hosting Larger Files
  • GitHub Pages limitations: GitHub Pages does not directly serve LFS content – if an LFS pointer is pushed, the published site won't retrieve the file. In fact, Pages has no built-in support for LFS GitHub Community Discussion. The workaround is to use GitHub Actions to fetch LFS files at build time and include them in the published site. GitHub now supports deploying Pages via Actions, so by enabling lfs: true in the checkout step, the action downloads the real files (GitHub Community Discussion, Standard deployment). This allows large files to be present in the static site output (bypassing the LFS pointer issue). However, be mindful: if a file exceeds 100 MB, even the Pages artifact may violate GitHub's limits if it were to be stored in a branch. Using the Actions deploy mechanism (which uploads the site via an API rather than a git push) might bypass the 100 MB git limit, but extremely large files could still pose problems or slow deployments.

My/AI/Rule/No Recipe in the Cake
  • AI does this constantly — embedding the meta-instruction into the artifact being produced.
    • Examples (to avoid)
      • Asked to build a page listing blog posts, it creates a page that reads: "This page is the canonical listing of all blog posts" instead of a page that just titled "Blog Posts"

      • Asked to not use a status:: key in a proposal and to pick a different name, AI creates a plan that says "Movement through the pipeline is tracked by a page property scoped to this process, not a generic status:: key — a generic key invites unrelated pages to reuse it loosely."
