Software ProjectHow to name the main page for a software project
  • Give a software entity a root-level one-word or short main page when its primary name is not confusing and it is either reputable or nascent but likely to grow sub-namespaces for shortcuts, config, docs, or related notes. A short main name leaves room; long names (owner/repo or person/project) make every child path longer and harder to work with. Example: Lazygit rather than Person/Jesse Duffield/GitHub/Lazygit. Aliases can point from other namespaces, such as Programming/Language/Rust or Person/Name/GitHub/Project, to that main page when useful.

Logseq/Pref/Page/Name
Page name preferences
  • Creator namespace with type segment: when a work's creator already has a namespace in the garden, place the entity under Creator/Type/Short Name — interpose a type segment (e.g. Font, Book) between the creator and the leaf, matching the pattern of Person/Douglas Hofstadter/Book/85/Metamagical Themas. Drop redundant creator and type words from the leaf: JetBrains/Font/Mono Nerd, not JetBrains/JetBrains Mono Nerd Font. Reserve type-only top-level namespaces (e.g. Font/<Name>) as a fallback when no creator namespace exists. Exception: entities well-known enough to warrant a top-level page (e.g. Lazygit, tmux) may stay at the top level regardless of creator.
