Pi Extension ArchitectureOverview

PiAI/Extension/Pi Review

Page reference

pi-review
  • A single review.ts of roughly 1600 lines. Interesting less for its hook usage than for what it shows about distribution and workflow ownership; the complement to PiAI/Extension/Plan Mode, which is bundled and hook-heavy.
pi-reviewIt ships source, not a build
  • The security consequence matters more than the convenience one: since the source is the distribution, "review before you install" is actually feasible, which is the mitigation the trust model on PiAI/Extension/Philosophy depends on.
pi-reviewIt owns the session tree, not just the conversation
  • Three custom entry types carry all durable state, and both session_start and session_tree re-apply them — the same reducer pattern as PiAI/Extension/Plan Mode.
PiAI/Extension/Plan Mode

Page reference

Plan Mode
  • Architecturally the most revealing example in the repository, because a mode is exactly the kind of feature most agents hardcode. Its existence as an extension is the strongest evidence that the seams described on PiAI/Extension/Architecture are real.
Plan ModeState is four variables in a closure
  • This is the idiomatic shape, and it scales: PiAI/Extension/Pi Review uses the same pattern at four times the size.

PiAI/Subagent
Extensions – pi-mono
  • PiAI has no native AI/Agent/Subagent definition and no agents/*.md format. Subagent-like behavior is orchestrated from a PiAI/Extension in TypeScript or JavaScript, using the agent-flow events before_agent_start, agent_start, agent_end, and agent_settled.
