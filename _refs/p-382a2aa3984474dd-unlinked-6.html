Atlassian/Confluence/API/Concept/GraphQL vs REST
  • Result: Single mutation request to create and return the new page
  • GraphQL cannot create or modify content → False. GraphQL provides mutations like createPage, updatePage, and deletePage for content management operations. Both APIs support write operations, though REST may offer more specialized endpoints (like direct page copying)
  • GraphQL can do everything REST can do → Partially false. While GraphQL has mutations for CRUD operations, REST may have specialized endpoints that don't have direct GraphQL equivalents (e.g., dedicated copy endpoints). For duplicating pages, REST's copy endpoint is more straightforward than GraphQL's query-then-create approach

AWS/Okta Keyman/How To/Install and Configure for Bedrock
  • Use $> aws_okta_keyman config or directly create and edit ~/.config/aws_okta_keyman.yml
    • You should fill in the values you obtained from your DevOps team in the prerequisites:

        • Information you need from your DevOps Team

          • $OKTA_USERNAME - your username in okta
          • $OKTA_ORG - your Okta domain, for example, https://myorganization.okta.com
          • $AWS_REGION - your AWS/Region, for example, us-east-1
          • $AWS_ROLE_GATEWAY - name of the AWS/IAM/Role that developers should use when logging into AWS/Okta Keyman, for example, my-developer-gateway-role
          • $AWS_ROLE_ASSUMED_ARN - the AWS/IAM/Role ARN that should be assumed after using Okta to log into $AWS_ROLE_GATEWAY, which will give you the ability to use Bedrock, for example, arn:aws:iam::123456789010:role/my-bedrock-role
    • This will end up defining AWS/Okta Keyman/aws_okta_keyman.yml, which defaults to ~/.config/aws_okta_keyman.yml. Using the variables above, a sample yaml config file would be the following. AWS/Secrets Manager/Q/What terms does AWS Secrets Manager use for single-valued vs. multi-valued secrets, and what can each do that the other can't?
  • Answer/Official from Create an AWS Secrets Manager secret, CreateSecret API reference, and Pass Secrets Manager secrets through Amazon ECS environment variables:
  • Create an AWS Secrets Manager secret: "In Key/value pairs, either enter your secret in JSON Key/value pairs, or choose the Plaintext tab and enter the secret in any format." Its examples: an API key → key/value pairs (ClientID, ClientSecret); an OAuth token, certificate, or private key → plaintext.
  • AWS's ready-made rotation Lambda templates. Direct citations and the full picture — including a third, Lambda-less "managed rotation" path that's gated by how a secret was created, not by its shape: AWS/Secrets Manager/Secret/Rotation. Core citation: CreateSecret API reference: "you must make sure the JSON you store in the SecretString matches the JSON structure of a database secret" for those templates to work. AWS/Secrets Manager/Secret/SecretString (single-valued/plaintext) can still be rotated, but only with a fully custom Lambda — there's no ready-made template for it.
AWS/Secrets Manager/Secret
  • The console nudges toward the key/value shape even outside a recognized database type. CreateSecret API reference: "If you create a secret by using the Secrets Manager console then Secrets Manager puts the protected secret text in only the SecretString parameter. The Secrets Manager console stores the information as a JSON structure of key/value pairs that a Lambda rotation function can parse."
AWS/Secrets Manager/Secret/KeyValue
  • The same AWS/Secrets Manager/Secret field (SecretString) holding a JSON object instead of a bare string, e.g. {"username":"admin","password":"secret"}. AWS's console calls this the Key/value pairs tab. Answer/Official from Create an AWS Secrets Manager secret: "In Key/value pairs, either enter your secret in JSON Key/value pairs..." — its example: an API key entered as ClientID / ClientSecret pairs.
  • Setting it: console → Store a new secret → Other type of secret → Key/value pairs tab. CLI → aws secretsmanager create-secret --name <name> --secret-string '{"key":"value", ...}' — any valid JSON object string. (Create an AWS Secrets Manager secret)
AWS/Secrets Manager/Secret/Rotation

  • Path 1: managed rotation, no Lambda at all — gated by how the secret was created, not by its shape

    • Only for secrets created through the owning service's own integration: Amazon RDS, Aurora, and DocumentDB master credentials, Amazon Redshift admin passwords, ECS Service Connect TLS certificates, and Secrets Manager managed external secrets (held by Secrets Manager partners — not a database at all). Managed rotation for AWS Secrets Manager secrets — this is the definitive list of what qualifies: "Some services offer managed rotation, where the service configures and manages rotation for you. With managed rotation, you don't use an AWS Lambda function..."
    • You cannot get this by hand-crafting your own CreateSecret call, whatever shape you give it — it depends on which service's UI/API created the secret, not on JSON vs. plaintext. CreateSecret API reference, same page cited below for the schema requirement: "For secrets that use managed rotation, you need to create the secret through the managing service."
  • fnox set overwrites a secret's entire SecretString with only the one value given on the command line — it has no read-merge-write for json_path. Verified directly in the fnox source at the commit this page cites: put_secret in aws_sm.rs does a bare put_secret_value/create_secret with whatever string it's handed, and the set command's call site passes it the one value the person typed, with no read-first step.
AWS/Secrets Manager/Secret/SecretString
  • The AWS/Secrets Manager/Secret field holding one raw string, no internal structure — an API key, OAuth token, certificate, private key. AWS's console calls this the Plaintext tab. Answer/Official from Create an AWS Secrets Manager secret: "choose Other type of secret. In Key/value pairs, either enter your secret in JSON Key/value pairs, or choose the Plaintext tab and enter the secret in any format."
  • Setting it: console → Store a new secret → Other type of secret → Plaintext tab. CLI → aws secretsmanager create-secret --name <name> --secret-string '<raw value>' with any non-JSON string. (Create an AWS Secrets Manager secret)
