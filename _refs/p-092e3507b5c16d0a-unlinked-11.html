Obsidian/Q/Can custom Obsidian plugins run on iPhone?
  • The development workflow is usually desktop-based. Write and compile the TypeScript on a Mac or PC, then put the built main.js, manifest.json, and optional styles.css in VaultFolder/.obsidian/plugins/<plugin-id>/. Copy or sync that compiled plugin folder to the iPhone, restart Obsidian, and enable it under Settings → Community plugins.
  • Mobile compatibility is the important constraint. Node.js and Electron APIs are unavailable on iOS, so code or dependencies that use modules such as fs, path, or electron can crash. Obsidian/Q/Does Obsidian have a dedicated way of making slideshows?

  • Does Obsidian have a dedicated way of making Slideshows? Logseq has built-in reveal.js support; is there anything like it in Obsidian, or with plugins?

    • AI Answer

      • Answer/Official from Slides in the Obsidian help, plus the community plugin pages linked below:
        • Short answer: Yes. Obsidian ships a core plugin named Slides, and community plugins add reveal.js and Marp workflows on top of it.
        • Core Slides plugin (built in):
          • Run Start presentation from the command palette, or right-click a note's tab and choose Start presentation.
          • Any note works as a deck. Separate slides with --- on its own line, surrounded by blank lines.
          • Navigate with the arrow keys or Spacebar; Escape ends the presentation.
          • The help page documents nothing beyond this: no themes, transitions, speaker notes, fragments, or export.
        • Community plugins for reveal.js-style decks:
          • Advanced Slides — markdown-based reveal.js presentations inside Obsidian. The closest match to Logseq's reveal.js support.
          • Slides Extended — a fork of Advanced Slides that embeds notes into slides, previews edits live, applies themes, and exports to PDF or HTML.
        • Community plugins for Marp decks (a different Markdown slide framework, not reveal.js):
          • Marp Slides — preview and export to HTML, PDF, PPTX, or images through the Marp CLI.
          • Marp Extended — create, preview, present, and export Marp decks.
          • Marp
        • Choosing: use core Slides for a quick read-through of a note. Use Advanced Slides or Slides Extended when you want reveal.js features like themes and PDF export. Use Marp when you want PPTX output.

Obsidian/Q/How can an Obsidian vault declare the community plugins it depends on and install them by script?
  • Commit .obsidian/plugins/<id>/{manifest.json,main.js,styles.css} directly. Cloning the repo is the install; nothing is fetched and nothing is clicked.
  • bash
    				  #!/usr/bin/env bash
				  set -euo pipefail
				  VAULT="${1:-.}"
				  registry=$(curl -fsSL https://raw.githubusercontent.com/obsidianmd/obsidian-releases/master/community-plugins.json)
				  jq -r '.[]' "$VAULT/.obsidian/community-plugins.json" | while read -r id; do
				    repo=$(jq -r --arg id "$id" '.[] | select(.id==$id) | .repo' <<<"$registry")
				    [ -n "$repo" ] || { echo "not in registry: $id" >&2; continue; }
				    tag=$(gh api "repos/$repo/releases/latest" --jq .tag_name)
				    dir="$VAULT/.obsidian/plugins/$id"; mkdir -p "$dir"
				    for f in manifest.json main.js styles.css; do
				      curl -fsSL -o "$dir/$f" "https://github.com/$repo/releases/download/$tag/$f" || true
				    done
				  done

Obsidian/Q/Should a team vault in git commit its community plugins' code, or only the list of plugins?
  • Prompted by git status in a work team's knowledge garden on 2026-10-23: Obsidian had updated easy-copy, folder-notes and obsidian-git, so their tracked manifest.json files showed as modified and their main.js, styles.css and data.json showed as untracked.
  • The older gardens ignore plugins/*/main.js, plugins/*/styles.css and plugins/*/data.json and commit manifest.json. One of them records why in an OpenSpec spec for a multi-device .gitignore, from a 2026-05-27 change about plugin binaries.
  • Short answer: For a team vault that newcomers clone, commit each plugin's whole folder (manifest.json, main.js, styles.css) and decide data.json plugin by plugin. Committing only manifest.json records versions but installs nothing, so a fresh clone opens with plugins turned on that cannot load.
  • The older gardens' design says main.js and styles.css are files "that Obsidian re-downloads when plugins are installed". That holds only when someone installs the plugin by hand; nothing re-downloads them on clone.
  • Obsidian Git's Tips and Tricks gives three .gitignore choices: all of .obsidian/, only .obsidian/plugins (to keep plugin settings that may hold secrets out of git), or only workspace.json. It does not split main.js from manifest.json.
  • I found no source that recommends the manifest-only rule. It appears to come from treating main.js as build output, which it is for the plugin's author but not for the vault, where it is the installed program.
  • Committing plugin code means committing third-party JavaScript that runs with full access to each person's machine. The trust prompt is the same either way; committing it adds a pinned, reviewable version.
  • Unverified: I did not open a fresh clone of a manifest-only garden to confirm the exact message Obsidian shows for an enabled plugin with no main.js, and I did not test the !plugins/folder-notes/data.json exception against the template's other ignore rules.
