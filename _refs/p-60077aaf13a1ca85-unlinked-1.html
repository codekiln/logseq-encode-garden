Logseq/DB
  • The Database version (DB version) of Logseq introduces DB graphs. See this page to get an overview of the main features for DB graphs. If you are an existing user, see changes with the DB version. The DB version has its own new mobile app (on iOS, with Android coming soon)! To participate in the mobile app alpha, please complete this brief form. The DB version also has a new sync approach, RTC (Real Time Collaboration)! You can use it to sync graphs between multiple devices or collaborate with others. To participate in the RTC alpha, please fill out this form.
  • The DB version is in beta status while the new mobile app and RTC is in alpha. This means that data loss is possible so we recommend automated backups or regular SQLite DB backups. We recommend you create a dedicated test graph and choose one project that’s not crucial for you.

Logseq/Q/What data does srs-of-matrix.edn store in a Logseq graph?
  • Each graph has its own logseq/srs-of-matrix.edn. The file in logseq/docs (the official Logseq documentation graph, available at ghq/github.com/logseq/docs) is simply the SRS state for that graph — confirming the file is standard Logseq infrastructure, not custom to this garden.
Logseq/Q/Will Logseq render relative markdown links? What about if a page is renamed, will it refactor relative markdown links to that page?
  • Official page linking is wiki-style: [[page name]], or labeled [display text]([[page name]]). External URLs use ordinary [label](https://…) markdown. Answer/Official from Logseq docs — Markdown.

  • nbb-logseq is installed here through mise, the link-hygiene and flashcard skills already run ClojureScript scripts under it, and its README says the graph-parser's namespaces all load under it (nbb-logseq README). A short script can therefore run Logseq's own extract over the encode garden and write pages, aliases, tags, block parents, references, and explicit UUIDs to JSON. Check out logseq/logseq at the tag 0.10.15, the release codekiln's Brewfile pins the desktop app to, so the oracle and the app a person opens the garden in agree. That JSON file is the golden fixture the new tool's output is compared with, page by page, with the tag recorded beside it. Run the same dump over logseq/docs, the public Logseq graph cloned at ~/ghq/github.com/logseq/docs, so the comparison also covers a graph codekiln did not write, which the Brief asks for.
  • Parse every file in the encode garden and in logseq/docs, serialize each back, and require identical bytes. A parser that passes can support small edits. A parser that fails needs a separate layer that keeps original text and spans, which is what Codex describes. Tine's README says tine-core's tests include a parse/serialize round trip, that round-trip parsing is validated against a real Logseq graph, and that tine-check proves byte-faithful serialization without reading note content (Tine README, Testing). Running tine-check on the encode garden is the cheapest way to learn whether that claim holds for this corpus.
