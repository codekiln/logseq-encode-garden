Apple/IIe/Q/What was the BASIC prompt character on the Apple IIe?

  • What was the BASIC prompt character on the Apple IIe? card

    • AI Answer

      • AI/Response
        • Short answer: ] — the closing bracket, used by Applesoft BASIC, which shipped in ROM on the Apple IIe.
        • The > character was the prompt for Integer BASIC (also called "Integer" or "Apple Integer BASIC"), the original BASIC on the Apple I and Apple II. Integer BASIC was not included in the Apple IIe ROM; it required a Language Card with the Integer ROM.
        • So both characters appear in Apple II history, but on the IIe the default power-on BASIC prompt was ].
        • See Applesoft BASIC on Wikipedia and Integer BASIC on Wikipedia.
Apple/Q/Can I add something to the Apple Wallet for my iPhone from my MacBook if I'm logged in to the same Apple account on both?

  • Can I add something to the Apple Wallet for my iPhone from my MacBook if I'm logged in to the same Apple account on both?

    • My Notes

      • Distinguish passes/tickets (boarding passes, event tickets, coupons) from payment cards (debit/credit for Apple Pay); Apple documents them differently.

    • Answer

      • AI/Response
        • It depends what “something” is. Being signed in with the same Apple Account on both devices is necessary for several Wallet-related features, but it does not mean every Wallet item you add on the Mac automatically appears on the iPhone.
        • Passes and tickets (non–payment “Wallet passes”) — Often yes. Apple documents adding passes (for example boarding passes or movie tickets) from Safari on Mac to Wallet on iPhone, iPad, iPod touch, or Mac, and says iCloud must be set up for Safari on the iPhone (iOS 6 or later) or Mac. You open the pass in Safari on the Mac, use Add to Wallet (or Update if the pass changed). Mail on Mac can similarly surface passes you add toward Wallet on iPhone when iCloud is set up on both devices (see Apple’s Mail User Guide for your macOS version).
        • Debit/credit and other Apple Pay payment cards — Not by simple cross-device sync. To use Apple Pay on more than one device, Apple’s Set up Apple Pay guidance is to add the card in Wallet (or Wallet & Apple Pay settings) on each device you want to pay from, then complete any bank or card issuer verification for that device. The same Apple Account helps (and Cards Found For You / similar flows can reuse cards you already added elsewhere so you are not retyping everything), but the card is still enrolled per device for security, not copied automatically as a fully active card everywhere.
        • Practical takeaway — For tickets/passes from the web or email, adding on the Mac in Safari or Mail is a normal path and can land in Wallet on the iPhone when iCloud requirements are met. For paying in stores or with Apple Pay cards, plan to add (or re-verify) the card on the iPhone even if it is already on the Mac.

        • Sources

          • Set up Apple Pay — Apple Support

fnox/How To/Use Apple Secure Enclave Touch ID

  • How to use Apple Secure Enclave Touch ID with fnox

    • Overview

      • Keep the fnox sync cache's age key inside Apple's Secure Enclave, so decrypting secrets on your Mac can require Touch ID instead of reading a key file from disk.
      • Source: the Secure Enclave section of the fnox sync guide, read from a local clone of jdx/fnox at commit 03e9aee (2026-10-01). The commands below are copied from that guide.

    • Prerequisites

      • A Mac with a Secure Enclave running macOS 14 or later.
      • fnox installed.
      • Brew to install the plugin.
      • A project already set up for fnox sync, as in fnox/Golden Path.

    • Steps

      • 1. Install the plugin

        • age-plugin-se must be on your PATH.
        • bash
          			  brew install age-plugin-se

      • 2. Generate a hardware-bound identity

        • bash
          			  mkdir -p ~/.config/fnox
			  age-plugin-se keygen --access-control=any-biometry -o ~/.config/fnox/age-se.txt
        • The command prints a public key beginning age1se1.... Copy it.
        • --access-control sets when the Secure Enclave asks for a fingerprint. fnox's guide names any-biometry, any-biometry-or-passcode and none, and lists more. If you want Touch ID on every decryption, use any-biometry; none skips the prompt.

      • 3. Point the sync provider at the identity

        • Put the recipient in the global config so every project on the machine reuses the key.
        • toml
          			  # ~/.config/fnox/config.toml
			  [providers.sync-age]
			  type = "age"
			  recipients = ["age1se1..."]
			  key_file = "~/.config/fnox/age-se.txt"
        • age-se.txt holds a reference to the key in the Secure Enclave, not the private key. Treat it like an identity file anyway.

      • 4. Unset FNOX_AGE_KEY

        • If FNOX_AGE_KEY is exported, unset it. It takes precedence over the provider's key_file.

      • 5. Sync

        • bash
          			  fnox sync --provider sync-age --local-file
        • fnox get, fnox exec and shell integration now decrypt the cache through the Secure Enclave. Whether a Touch ID prompt appears depends on the access control you chose in step 2.

      • 6. Re-sync an existing cache

        • A cache written earlier with a file-based age key is encrypted to that old key. Run the sync command from the fnox/Golden Path with --force to rewrite it: fnox sync --provider sync-age --local-file --force.
        • Unverified: fnox's docs describe --force for refreshing a stale cache, not for switching keys. Confirm that it replaces entries encrypted to the old key.

    • Troubleshooting

      • The key only decrypts on the Mac that generated it, so a cache synced here cannot be read from another machine. Run the setup on each machine.
      • Unverified: how fnox behaves when the Touch ID prompt is cancelled, or when the Mac has no enrolled fingerprint. The upstream docs do not say.

          • Distribute .ipa file to install
