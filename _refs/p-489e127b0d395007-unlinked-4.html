Readwise/AI/Report/26/01/AI control of Readwise - Options Jan 2026
  • Official MCP Server: Readwise provides an official MCP server (@readwise/readwise-mcp on NPM) which is maintained by the Readwise team. This server allows AI clients (like Claude or Cursor) to search and retrieve highlights from your Readwise account [4]. It focuses on the main Readwise highlights (e.g. Kindle/book highlights) rather than full Reader documents, and is regularly updated (v0.0.7 as of late 2025).
  • Open-Source MCP Servers: Several community-driven MCP servers extend Readwise integration, enabling AI agents to read/write Reader documents and highlights. Notable examples include:
    • Readwise Reader MCP (edricgsh) – A popular open-source TypeScript MCP server that exposes the entire Readwise Reader API to AI agents [5]. It gives your AI full control over your Reader library, supporting full CRUD on documents (create/save new articles, list/filter documents, update metadata like tags/folder, and delete documents) as well as tag listing and powerful regex search across content [5]. This server is built with the official Claude SDK and is actively maintained; it had ~3.6k downloads by Oct 2025 [5], indicating healthy usage.
    • Readwise MCP Enhanced (arnaldo-delisio) – An open-source "unified" MCP server combining both Reader documents and Readwise highlights in one tool [7]. Written in TypeScript, it integrates the Reader API (v3) for document management and the original Readwise API (v2) for highlights [7]. This server provides comprehensive features (saving/searching documents, accessing all highlights, listing books and tags, etc.) with various optimizations (e.g. reduced token usage, content pagination) [7]. It is fairly active (40+ stars and ongoing development) and is compatible with any MCP-enabled AI client (Claude, Continue IDE, Raycast, etc.).
    • Readwise MCP HTTP Server – A Node.js MCP server (by CaseyRo) that exposes Readwise functions over standard HTTP endpoints [9]. This allows AI tools (or any HTTP client) to query and retrieve highlights or Reader documents via HTTP requests, which can simplify integration. It's an open-source project (TypeScript) focused on providing MCP-over-HTTP for easier debugging and integration [9]. (This project is smaller in adoption, but useful if your AI platform prefers HTTP calls over the MCP protocol).
    • Remote Readwise MCP (Python) – An unofficial Python-based MCP server for Readwise [10]. It offers similar capabilities to the above (primarily Reader document access) but implemented in Python, which may appeal to those in Python ecosystems. This server (e.g. xinthink/reader-mcp-server-py) supports listing and retrieving Reader documents [10]. Its community usage is more niche compared to the TypeScript solutions, but it remains a viable open-source option.
  • Maintenance: All the above MCP servers are open-source. The official MCP server is maintained by Readwise (commits as recent as Sep 2025), while the community servers are maintained by individual developers. As of late 2025, edricgsh's and Arnaldo's servers show active development and community engagement [5] [7].
  • Optional Features & Considerations: Some features (like managing RSS feeds in Reader) are not yet exposed via the public API. According to Readwise, the Reader API is currently limited to documents and will gain more endpoints over time [20]. This means subscribing/unsubscribing to feeds or creating feed folders must be done through the Reader app for now (no official API endpoints as of 2026). Likewise, downloading full article text can be achieved indirectly: the Reader API's list can return an html_content or a raw_source_url for each document when requested [20], which an agent can use to fetch the full text. Tools like the Readwise MCP servers also handle content extraction (e.g. converting HTML to clean text for the AI) [25] [26]. Finally, listing tags and basic metadata is supported (via the tags endpoint or MCP server functions) in most integrations, even if feed/category CRUD is absent.
  • In summary, to enable an AI agent (Cursor, Claude's code assistant, Codex, etc.) to interface with Readwise, you can choose from a range of solutions: a convenient CLI tool [1], specialized MCP servers for real-time AI context [4] [5], language-specific SDKs [12], or direct use of Readwise's REST APIs [16]. Official offerings exist for the MCP and the APIs, whereas community open-source projects fill in the gaps with additional capabilities (especially for Reader). Depending on your workflow and preference (command-line vs. programmatic, language ecosystem, real-time AI context needs), you can pick the appropriate tool. All options support the core features — saving to Reader, retrieving highlights, and assembling reading lists — while more advanced operations (feeds and category management) will become available as the Readwise API expands [20].

Toggl/AI/Report/26/01/AI control of Toggl - Options Jan 2026
  • Model Context Protocol (MCP) is a newer approach that allows AI or natural-language-driven clients (like ChatGPT plugins or Claude AI) to interact with services through a standardized interface. In the Toggl Track context, MCP servers act as an adapter on top of the Toggl API to interpret high-level commands (often in natural language) into Toggl actions. This can be useful if you want to control Toggl via conversational AI or integrate it into an AI agent workflow. Two notable MCP implementations exist for Toggl Track; narrative for each is on Toggl/MCP/Node/louis030195/toggl-mcp and Toggl/MCP/Python/jasleen19/toggl-mcp, under each page's AI/Response heading that cites this report.

      • Description: This is an unofficial MCP server for Toggl Track written in Node.js (available as an npm package @louis030195/toggl-mcp). It exposes a set of tools (commands) that an AI or any MCP client can call to perform time tracking operations[9]. The features supported include: starting and stopping time entries (timers), retrieving the current running entry, listing all time entries for today, listing all projects, deleting a time entry by ID, and even generating a weekly summary report (total hours tracked with breakdown by day and by project)[9]. Essentially, it covers time entry CRUD (create via start, read via queries, update via stop, delete by ID) and basic project listing[9]. It does not create new projects or clients (it can list projects so that you can reference them when starting timers).
      • Usage: Once the MCP server is running, you (or an AI agent) can issue natural language commands or JSON-formatted MCP requests such as: "Start tracking Project X – Design task for client Acme Corp" or "Stop the current timer", etc. The MCP server translates these into Toggl API actions. For example, the server defines tools like toggl_start (to start a new entry with a given description and project) and toggl_stop (to stop the running entry)[9]. The weekly summary tool (toggl_weekly) can be invoked to get a report of hours tracked this week or a past week[9].
      • Projects/Clients: This MCP interface allows listing projects (toggl_projects)[9] so that an AI can query available project names/IDs. It does not support creating or editing projects/clients – those would still be done via Toggl's API or interface outside MCP. In usage, you might start an entry with a project name, and the MCP server will look up the project ID via the Toggl API. "Managing projects" in this context means you can fetch and choose existing projects, not create new ones[9]. Client names may be passed when starting entries but there is no client CRUD[9].
      • Reports: The inclusion of the weekly summary command is a nice addition – it provides a high-level report of total hours and breakdowns by day and project for the week[9]. There's also a convenience tool toggl_today for listing today's entries and a toggl_last_week alias for last week's summary[9]. For more complex reporting (arbitrary date ranges, filtering), you would still use Toggl's Reports API directly. But for conversational interfaces, these built-in summaries cover common needs (e.g., "How many hours did I work this week on Project X?").
      • Usability & Notes: This Node-based MCP server is open source (MIT)[9]. It can be installed via npm and configured with your Toggl API token and workspace ID[9]. One caveat is that MCP servers in general are meant to be run as background services or integrated in AI platforms – you wouldn't use this as a typical user-facing app by itself. It's most useful if you plan to control Toggl through natural language (for example, using an AI assistant that supports MCP). The developer provides instructions for integrating with Claude AI and others[9]. In summary, the Toggl MCP (Node) is a handy bridge to make Toggl Track "AI-accessible," supporting all crucial time entry operations and simple reports[9].

Like the Node version, it leverages Toggl Track's API v9 to perform actions, exposing them as MCP tools. While detailed documentation is lighter than the Node version, the core functionality is similar: it allows an MCP client to start and stop time entries, query current or recent entries, etc., using structured prompts or natural language. Essentially, it wraps the Toggl API endpoints (start time entry, stop entry, get running entry) in an MCP-compatible interface[13].
      • Capabilities: This Python MCP server ensures full CRUD for time entries – you can create (start) entries, read data (e.g., list entries or get current entry), update (stop or edit running entry), and delete entries – through the MCP commands. It likely has equivalents to the Node version's tools, though named slightly differently. (For example, a command to start an entry, one to stop, one to fetch today's entries, etc.) Being maintained by "Toggl MCP Contributors," it seems to be a community effort to provide a Toggl integration in Python for the MCP ecosystem.
      • Projects/Clients: Based on what's known, this interface focuses on time entries primarily. There is no indication of project or client management features in the current version. It may allow specifying a project when starting an entry (so that the entry is associated with a project), but you would need to know the project name/ID up front. There isn't evidence of a "list projects" command in the Python MCP like the Node version has, so it might be limited in that regard (or the documentation is just sparse). For now, assume project and client CRUD are not directly exposed via this MCP server.
      • Reports: There's no mention of built-in reporting in the Python MCP server. It likely sticks to operational commands (tracking and retrieving entries). Any reporting (like totals) would have to be done by querying entries (e.g., "list my entries for today") and then summarizing on the client side. This is in contrast to the Node MCP which explicitly provided a weekly summary tool. The Python MCP server's goal appears to be enabling voice/AI control for basic Toggl operations rather than analytics.
      • Usability & Notes: The Python Toggl MCP server is open source (MIT license)[13]. It can be run with a tool like Uvicorn (an ASGI server) or integrated into an MCP Gateway. The README on PyPI provides sample configuration for Cursor (another MCP client) and Claude AI[13]. Essentially, you configure it with your TOGGL_API_TOKEN (and workspace) and then your AI assistant can invoke Toggl actions. If you are comfortable in Python and want to extend or tweak the MCP server, this is a good option. It's worth noting that MCP is a new and evolving protocol (born in late 2024[20]), so these Toggl MCP projects are on the cutting edge – great for AI integration, but they do assume you have a use case involving conversational or autonomous AI agents. For standard automation needs, a direct CLI or SDK might be simpler.
