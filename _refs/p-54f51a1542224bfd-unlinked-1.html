Claude/Code/Plugin/Marketplace/Auto-Update
  • Set an explicit version in each plugin's plugin.json and bump it (semver) on every release. A commit without a version bump delivers nothing to existing installs.
  • Trade-off: omitting version and falling back to the commit SHA makes every commit an update, which suits fast iteration but interacts badly with the fetch-not-pull bug and makes the deployed version hard to read at a glance. For a team marketplace, explicit semver is the safer default.
Dependency/Update/Automation
  • Dependency update automation is the practice of keeping declared third-party packages, tools, and libraries current with minimal human toil: bots open pull requests, policies choose semver vs pinning, CI proves green builds, and humans review only the diffs that matter.
  • Human gate for risk — Breaking semver, native binaries, and security-sensitive deps still warrant review even when bots draft the PR.

mise/Q/How can I run mise commands to update pinned global dev tools using aqua and a mise Task
  • Upgrade while rewriting pins: run mise/upgrade/--bump (alias mise up --bump). That installs newer versions and updates the version fields in the relevant mise.toml / config.toml files, keeping the same precision as before (for example a pin of 20 can become 22, not necessarily a full semver triple unless you already pinned that tightly). See the mise upgrade docs.
