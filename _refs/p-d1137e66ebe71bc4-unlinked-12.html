My/Pref/Dev/Tool/git/Worktree
  • why one shared location: keeping every tool's worktrees under the same <proj-root>/.worktrees/ path, rather than letting each tool pick its own default (e.g. .claude/worktrees/), preserves my ability to switch between tools without hunting for scattered worktree directories
My/Pref/Dev/Tool/Obsidian/Plugins in Git
  • Do not commit a plugin's manifest.json on its own. Obsidian rewrites it on every plugin update, so it churns, and it records the version the last person updated to without installing that version anywhere else.
  • Picks the newest release that is not a draft or prerelease, has manifest.json and main.js assets, and is at least 5 days old. The 5 days match minimum_release_age = "5d" in mise.toml, the same supply-chain delay I use for every other dependency (see My/Pref/Dev/Tool).
  • Ignore every data.json by default. It holds one person's choices, and some plugins keep tokens there.
My/Pref/Writing/Avoid double negatives

  • so a commit whose only staged file is that ignore file leaves zero targets and secretlint exits non-zero with "Not found target files". A hook cannot tell that apart from a real finding, so the first person to edit an ignore file reads a block as a detection and reaches for --no-verify. Nothing to scan is a pass; every other failure stands.

My/Pref/Writing/Do not hard-wrap prose in Markdown
  • A hard wrap also makes a diff lie about what changed. Editing one word in the middle of a paragraph re-flows every line after it, so the change arrives as a rewritten paragraph and review has to find the edit inside it.
My/Pref/Writing/Don't be an Attention Vampire; Lower the Drama
  • Don't say we can "kill two birds with one stone" if there's a way to communicate what you need without killing things. These days every YouTube video or x.com tweet is about how "X is the new Y killer." This type of framing is immature and not part of the world I want to bring about.
My/Pref/Writing/Give every sentence a subject that can do its verb
  • This holds in every document I read, an OpenSpec proposal and a heading included (see My/AI/Rule/How to Communicate Effectively With Me/Use Headings to Serve a Purpose).
My/Pref/Writing/Seek Inclusive Language
  • Every word is a vote for the future, so vote wisely: seek to use words that inspire hope and draw in all living beings into a circle of fruitful collaboration.
My/Pref/Writing/Use Plain language
  • Use active voice; see My/Pref/Writing/Give every sentence a subject that can do its verb.
  • The common AI failure is writing as if every reader already owns decades of specialized vocabulary. Don't require background the reader may not have.
My/Principle/Dispel Ambiguity
  • every surviving interpretation is a place the reader, user, or future maintainer can diverge from what you meant
My/Principle/Favor Readers Over Writers
  • the cognitive cost of deciphering dense code compounds across every future reader
My/Principle/Make Illegal States Unrepresentable/Discussion
  • making invariants part of the data model shifts enforcement from "every callsite must check" to "the type guarantees it"
My/Principle/Simplify/Create Uniform Interfaces/Discussion
  • callers can apply knowledge from one endpoint to every other endpoint without consulting docs
My/Principle/Simplify/Minimize Surface Area
  • every extra flag, field, or mode is a commitment to maintain and a source of unexpected interaction
