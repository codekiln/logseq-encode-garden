LazyVim/Q/How do I see more of a long filename in the snacks.nvim Explorer sidebar (<leader>e)?

Page reference

  • How do I see more of a long filename in the nvim/Plugin/snacks.nvim/Explorer sidebar (<leader>e)?

    • AI Answer

      • Short answer: the sidebar window is only 40 columns wide by default, and the Explorer picker shows filenames only (no path) with no ellipsis — long names simply get cut off at the window edge. Widen the sidebar layout in your nvim/Plugin/snacks.nvim opts.
      • Add this to the snacks.nvim plugin spec (e.g. lua/plugins/snacks.lua):
        • lua
          			  return {
			    "folke/snacks.nvim",
			    opts = {
			      picker = {
			        sources = {
			          explorer = {
			            layout = { layout = { width = 60 } },
			          },
			        },
			      },
			    },
			  }
      • This overrides only the explorer source's copy of the sidebar layout preset (width = 40 by default). To widen every picker that uses the sidebar layout preset (not just Explorer), override the preset itself instead: opts.picker.layouts.sidebar.layout.width = 60.
      • Confirmed by reading the plugin source directly (no official width-tuning doc page): lua/snacks/picker/config/sources.lua sets M.explorer.layout = { preset = "sidebar", preview = false } and formatters.file = { filename_only = true }; lua/snacks/picker/config/layouts.lua sets M.sidebar.layout.width = 40. The filename formatter (lua/snacks/picker/format.lua, M.filename) does not truncate or ellipsize when filename_only is set — the neovim window itself clips anything past its width.

LazyVim/Q/What are Telescope, fzf-lua, and aerial.nvim for symbol search, and how do they compare with Trouble.nvim?

  • What are nvim/Plugin/telescope.nvim, nvim/Plugin/fzf-lua, and nvim/Plugin/aerial.nvim for symbol search, and how do they compare with nvim/Plugin/trouble.nvim?

    • AI Answer

      • Short answer: nvim/Plugin/telescope.nvim and nvim/Plugin/fzf-lua are fuzzy-find pickers — type, filter, hit enter, the window closes. nvim/Plugin/aerial.nvim is a persistent outline sidebar that stays open while editing. nvim/Plugin/trouble.nvim is a persistent list/tree panel (closer to an IDE "Problems"/"Outline" panel) that can show symbols, diagnostics, references, and quickfix/loclist entries in one UI. All four drive "symbol search" through the same LSP textDocument/documentSymbol and workspace/symbol requests; they differ in UI paradigm, not in the underlying data source.
      • nvim/Plugin/telescope.nvim (Answer/Official from nvim-telescope/telescope.nvim): a general-purpose fuzzy finder framework. Its LSP extension exposes lsp_document_symbols (current buffer) and lsp_dynamic_workspace_symbols / lsp_workspace_symbols (project-wide). Selecting a result jumps to it and the floating picker closes.
      • nvim/Plugin/fzf-lua (Answer/Official from ibhagwan/fzf-lua): the same picker concept as telescope.nvim but wraps the actual fzf binary for matching/rendering, so it's typically faster on very large result sets. It ships equivalent lsp_document_symbols and lsp_live_workspace_symbols pickers — functionally interchangeable with telescope.nvim for this use case.
      • nvim/Plugin/aerial.nvim (Answer/Official from stevearc/aerial.nvim): not a fuzzy finder. It renders a live, nested tree of the current buffer's symbols (functions, classes, etc.) in a sidebar that tracks the cursor and stays open — closer to a code outline/minimap than a search box. It ships its own optional fuzzy picker for jump-to-symbol, but its primary role is the always-visible outline.
      • nvim/Plugin/trouble.nvim (Answer/Official from folke/trouble.nvim): a unified list/tree panel for LSP-sourced data — diagnostics, document/workspace symbols, references, definitions, and the quickfix/location list — with folding, filtering, and persistent context while moving between items. Its "symbols" mode is the closest analogue to aerial's outline, but rendered as a togglable panel rather than an always-visible sidebar, and shared with diagnostics/references rather than outline-only.
      • In this garden's actual LazyVim config: none of the telescope.nvim, fzf-lua, or aerial.nvim extras are enabled (see the My Note on LazyVim/Keyshort/Search and LazyVim/Keyshort/Code Action). General fuzzy pickers (files, grep, etc.) run on nvim/Plugin/snacks.nvim instead, and document symbol search is bound to <leader>cs (Document Symbols), which opens nvim/Plugin/trouble.nvim rather than a picker or an aerial sidebar — so cheat sheets written against the telescope.nvim/fzf-lua/aerial.nvim extras (e.g. describing a <leader>ss symbol picker) don't match the keys actually bound here.
LazyVim/Q/What is the difference between <leader>fb and <leader>fB for buffers?
What is the difference between <leader>fb and <leader>fB for buffers?AI Answer
  • In the nvim/Plugin/snacks.nvim picker, the one a stock install uses
    • lua
      			  { "<leader>fb", function() Snacks.picker.buffers() end, desc = "Buffers" },
			  { "<leader>fB", function() Snacks.picker.buffers({ hidden = true, nofile = true }) end, desc = "Buffers (all)" },
    • hidden = true skips the check on the first mark, nofile = true skips the check on the second. Both start off, so <leader>fb is the same picker with nothing waived. The marks are vim's 'buflisted' and 'buftype' settings, under :help buflisted and :help buftype.
    • Both keys behave the same in three other ways: they include the file you are currently in, they include files vim has unloaded from memory but still remembers, and they sort by what you touched most recently.
    • <leader>, opens the same list as <leader>fb — two keystrokes instead of three.

LazyVim/Tutorial/Search for a Phrase Across Files/Q/How do we know that rg is used for search in LazyVim?
How do we know that rg is used for search in LazyVim?AI Answer
  • LazyVim maps <leader>/ to LazyVim.pick("grep"). This setup registers nvim/Plugin/snacks.nvim/Picker as LazyVim's picker, and that picker's grep source builds the search command with cmd = "rg".
LazyVim/Tutorial/Search for a Phrase Across Files/Q/How does the picker split the phrase from the extra rg arguments?
How does the picker split the phrase from the extra rg arguments?AI Answer
  • The nvim/Plugin/snacks.nvim/Picker grep source parses the picker's input for the literal separator -- . Text before the separator becomes the search pattern; text after it is tokenized (respecting quotes) and appended to the rg command as additional arguments, alongside flags such as rg/-g and -t that the picker also sets from its own options.
LazyVim/Tutorial/Search for a Phrase Across Files/Q/What does the R indicate in the title of the Grep dialog?
What does the R indicate in the title of the Grep dialog?AI Answer
  • R marks the regex toggle's non-default state: regex matching is off, so the search is using fixed strings. The nvim/Plugin/snacks.nvim/Picker is configured to show the badge when its regex option is false.
LazyVim/Tutorial/Search for a Phrase Across Files/Q/Why does cd pages show a Messages notification but pwd shows nothing visible?
Why does :cd pages show a Messages notification but :pwd shows nothing visible?AI Answer
  • LazyVim's own ui.lua configures noice.nvim by default, not as an opt-in extra. Noice's default routing sends plain messages (the kind produced by both :cd and :pwd) to a notify-style view whose backend list is { "snacks", "notify" }, so it renders via nvim/Plugin/snacks.nvim/Notifier when available.
LazyVim/Tutorial/Search for a Phrase Across Files/Q/Why does searching for the tags line for Diataxis Tutorial require turning off Regex matching in rg?
Why does searching for tags:: [[Diataxis/Tutorial]] require turning off Regex matching in rg?AI Answer
  • Pressing <Alt-r> turns off regex matching. The nvim/Plugin/snacks.nvim/Picker then runs rg with --fixed-strings, so every bracket, slash, and letter in tags:: [[Diataxis/Tutorial]] must appear in that order.

  • LazyVim ships with a plugin called nvim/Plugin/flash.nvim, which was created by the Person/Folke Lemaitre and integrates very nicely with it.

    This plugin provides a code navigation mode that has been available in various vim plugins for many years, and has historically been quite controversial. A lot of long-time vim users think it breaks the vim paradigm. I won't go into the details as to why, but I will acknowledge that this was true in older iterations of the paradigm but is somewhat less true in modern versions such as nvim/Plugin/flash.nvim.
