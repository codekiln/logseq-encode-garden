Ableton/Keyshort/Q/What is the "zoom to selection" keyshort in Ableton Live?

Page reference

  • What is the "zoom to selection" keyshort in Ableton/Live?

    • AI Answer

      • Answer/Official from Live 12 Keyboard Shortcuts
      • Short answer: Z on both macOS and Windows. X zooms back out.
      • Where it applies:
        • Arrangement View: Z is "Zoom to Arrangement Time Selection" and X is "Zoom Back from Arrangement Time Selection".
        • Clip View editor: Z is "Zoom to Clip Selection" and X is "Zoom Back from Clip Selection".
      • Latching: the manual says Z toggles zooming into the Arrangement selection when you hold it, so holding Z zooms in and releasing it zooms back out. Tapping Z then X is the persistent version. The manual notes the momentary latching can be turned off with an Options.txt entry.
      • Computer MIDI Keyboard: when it is turned on, Z and X lower and raise its octave instead of zooming.

bat/Q/When using bat as a pager, is there a keyboard shortcut that brings up the keyboard shortcuts?

  • When using bat as a pager, is there a keyboard shortcut that brings up the keyboard shortcuts?

    • AI Answer

      • AI/Response
        • Short answer: Press h (or H) — this is the less help key, since bat delegates paging to less by default.
        • bat has no built-in interactive keyboard layer; all navigation belongs to the configured pager. The default pager is less, launched with flags like -R (preserve ANSI color), -F (exit if output fits on one screen), and -K (quit on Ctrl-C).
        • In less, h opens the built-in help screen listing every available command and key binding. From the less manual: "h or H Help: display a summary of these commands. If you forget all the other commands, remember this one."
        • To use a different pager: set BAT_PAGER or PAGER (e.g. export BAT_PAGER="less -R"). The help key then depends on whatever pager you configure.
        • Refs: bat README — Using a different pager, less man page

Ghostty/Q/Is it possible to quickly increase or decrease the Ghostty font size with a keyboard shortcut?

  • Is it possible to quickly increase or decrease the Ghostty font size with a keyboard shortcut? card

    • AI Answer

      • AI/Response
        • Short answer: Yes — Ghostty ships with default font-size keybindings that work without any configuration.
        • macOS defaults (super = ⌘):
          • Cmd+= → increase_font_size:1
          • Cmd+- → decrease_font_size:1
          • Cmd+0 → reset_font_size
        • Linux/GTK defaults (ctrl):
          • Ctrl++ → increase_font_size:1
          • Ctrl+- → decrease_font_size:1
          • Ctrl+0 → reset_font_size
        • Custom step size: The actions accept an integer argument for how many points to adjust per press. Example custom binding:
          • keybind = super+shift+period=increase_font_size:2
        • Cost of the default: super++ and super+= are handled by Ghostty itself and never reach the program running in the terminal, so ⌘+ cannot serve as a shortcut inside tmux — see tmux/Q/What expands every item in tree mode, and why does Cmd-plus resize the Ghostty font instead?
        • Sources: Keybind reference; Configuration reference
git/Alias/md-url
  • git git/Alias GitHub CLI yazi/Keyshort/Copy GitHub markdown link
    • git md-url — markdown link to a path's GitHub web view #card
      • Command: git md-url [--no-copy] <path>...
      • Context: User-defined alias in the chezmoi-managed ~/.gitconfig, backed by ~/.config/git/scripts/generate_markdown_path_link.zsh. Sits beside git md-commit (which links the most recent commit), so the family is enumerable with git md-<TAB>. Clipboard writes route through the sibling git copy-text alias, which picks pbcopy / wl-copy / xclip per platform.
      • Description: Emits [<repo>/<path-from-repo-root>](<github-url>) for each path given — files and directories alike — printing to stdout and copying to the clipboard. --no-copy prints only, for pipelines. Several paths yield one link per line. The URL targets the repository's default branch, never the checked-out branch, since a link into an unpushed branch is a 404 for everyone else.
      • Cost: one network round trip per invocation, ~0.7s, regardless of how many paths are passed. The default branch resolves offline from refs/remotes/origin/HEAD; the base URL comes from a single gh browse -n call and every link is concatenated onto it.
      • Fails loudly: not a repository, no GitHub remote, a path outside the repository, or a missing gh all produce a message on stderr and a non-zero exit, leaving the clipboard untouched. A wrong link is not obviously wrong at paste time, so copying nothing is better.
      • My Notes Bound in yazi as yazi/Keyshort/Copy GitHub markdown link (c then g). The script strips GITHUB_TOKEN / GH_TOKEN itself rather than relying on the gh shell wrapper in .zshrc — that wrapper only exists for interactive shells, so a script behind a git alias would otherwise get the raw binary with the tokens still set.
