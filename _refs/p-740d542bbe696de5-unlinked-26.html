Unix/Q/What is a named pipe in unix, and how do 1Password Environments use one to mount a .env?
  • A reader that opens the FIFO blocks until a writer opens it too, and the reverse. Each byte is read once; after one reader consumes it, it is gone.
  • Readers need no changes: dotenv-style loaders just open and read a file. The docs list Node dotenv, python-dotenv 1.1.2+, Go, Java, C#, PHP, Ruby, Rust, and Docker Compose.
  • Every process can read it — while unlocked, 1Password does not tell readers apart. Any process running as you, an AI agent included, can cat the values.

vim/Q/How can I check whether vim or neovim will yank to the unnamedplus (system) clipboard?
  • Read the option: In Ex mode run :set clipboard? (or :echo &clipboard). If you see clipboard=unnamedplus, yanks and deletes that target the unnamed register are also applied to the + register (the system clipboard on X11/Wayland/macOS when clipboard integration works). unnamed wires the unnamed register to * (primary selection on X11) instead of +.
  • Troubleshooting — registers output flashes then vanishes: Typical when noice.nvim (often with nvim-notify) shows msg_show output in a notify / mini view that auto-dismisses. Mitigations: enable preset long_message_to_split so long output opens a split you can read; add a route sending event = "msg_show" (or kind = "echo") to view = "split"; raise views.notify.timeout (milliseconds) or false where supported; run :Noice / :Noice history to reopen message history after the popup closes; temporarily :Noice disable to confirm stock msgarea behavior. Bypass the UI entirely: :redir @a | silent registers | redir END then :new :put a (or :put =execute('registers')) so the dump lives in a buffer.

yazi/Q/In yazi, if I launched without the shell wrapper, can I still cd to the current directory when I exit?
  • No direct mechanism. The --cwd-file flag must be passed at launch time — there is no way to add it retroactively to a running yazi session. Without it, yazi never writes the cwd file, so the parent shell has no file to read.
yazi/Q/In yazi, if nvim is my $EDITOR, is there a key which can open it up in my editor in read-only mode?

  • In yazi, if nvim is my $EDITOR, is there a key which can open it up in my editor in read-only mode?

    • AI Answer

      • AI/Response
        • Short answer: No built-in default key exists for this. Add a custom shell binding that calls nvim -R with the %h placeholder (hovered file path).
        • Why there's no default key: Yazi's default opener for text files runs ${EDITOR:-vi} %s (writable). The default keymap binds o / <Enter> to open (which triggers that opener), and O / <S-Enter> to open --interactive. Neither has a read-only variant out of the box.
        • Checking the default [mgr] keymap: e is not mapped; r is mapped to rename. So e alone is a clean, free key in [mgr].
        • Add a key binding in ~/.config/yazi/keymap.toml:
        • toml
          			  [[mgr.prepend_keymap]]
			  on   = "e"
			  run  = "shell 'nvim -R %h' --block"
			  desc = "Open hovered file in nvim read-only"
        • %h expands to the hovered file's path (shell-quoted automatically). --block suspends yazi until nvim exits.
        • Chord alternative: on = [ "e", "r" ] is a single chord binding (press e then r in sequence, like [ "g", "g" ]). It does not conflict with standalone r → rename since yazi only enters chord mode after the first key.
        • Alternative — use view: nvim ships a view alias that is identical to nvim -R:
        • toml
          			  [[mgr.prepend_keymap]]
			  on   = [ "e", "r" ]
			  run  = "shell 'view %h' --block"
			  desc = "Open hovered file in view (nvim read-only)"
        • Docs: keymap — shell, yazi-default.toml opener.edit
