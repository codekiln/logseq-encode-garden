LazyVim/Q/What are Telescope, fzf-lua, and aerial.nvim for symbol search, and how do they compare with Trouble.nvim?
  • Short answer: nvim/Plugin/telescope.nvim and nvim/Plugin/fzf-lua are fuzzy-find pickers — type, filter, hit enter, the window closes. nvim/Plugin/aerial.nvim is a persistent outline sidebar that stays open while editing. nvim/Plugin/trouble.nvim is a persistent list/tree panel (closer to an IDE "Problems"/"Outline" panel) that can show symbols, diagnostics, references, and quickfix/loclist entries in one UI. Logseq/Entity/UI/Area

  • UI Area

    • In this garden, UI Area pages model one named region of a product's interface — a panel section on hardware, or a view or bar in software — and list the controls and smaller areas inside it.

    • What counts

      • A region the product's own documentation names and that holds controls: Microfreak/UI/Oscillator, Ableton/Live/UI/Control Bar, Ableton/Live/UI/Arrangement View.
      • <Item>/UI is the root area for an item and covers its whole interface, the way <Item>/UG holds its Logseq/Entity/Book/User Guide.
      • A single knob, button, pad or field is a Logseq/Entity/UI/Control, not an area.
      • A small group of controls stays a heading on its area page rather than becoming a page, even when the documentation names it, such as the Transport Controls section of Ableton/Live/UI/Control Bar.

    • Atomic Design stages

      • A UI Area corresponds to an UX/Design/Atomic/L3 - Organism; a root <Item>/UI page or a full view such as Ableton/Live/UI/Arrangement View corresponds to an UX/Design/Atomic/L4 - Template.
      • A Logseq/Entity/UI/Control corresponds to an UX/Design/Atomic/L1 - Atom. A preset or a saved Live Set, which fills the interface with real values, corresponds to an UX/Design/Atomic/L5 - Page and is modeled by its own entity.

    • Identity and names

      • Place an area at <Item>/UI/<Area>, nesting a smaller area under the area that holds it: <Item>/UI/<Area>/<Sub-area>.
      • A hardware panel can also be mapped by position. Each side of the device is an area, <Item>/UI/Front or <Item>/UI/Rear; a side laid out in rows has one area per row at <Item>/UI/Front/Row/<NN Row>, numbered top to bottom, such as Microfreak/UI/Front/Row/02 Main.
      • Inside a row, or on a side without rows, each item takes a two-digit number counting left to right: 01 Matrix, 02 Paraphonic Button. A numbered group of controls is an area, such as Microfreak/UI/Front/Row/01 Top/01 Matrix; a numbered single control is a Logseq/Entity/UI/Control.
      • Use the name printed on the panel or used in the manual, in Title Case: Oscillator, Control Bar, Arrangement View, Scrub Area.
      • Search <Item>/UI and the item's older pages before creating an area. When the garden already has a page for the same region under another name, link it from the area page, and list the older name in alias:: when it has no page file of its own.

    • Page shape

      • Frontmatter: logseq-entity:: [[Logseq/Entity/UI/Area]]; up:: links to the containing area, and a root <Item>/UI page links up:: to the item. See Logseq/Frontmatter for shared conventions.
      • One bullet-wrapped H1 with the area's name, then one sentence saying where the area sits and what it is for, then a picture of the area when the user guide has one.
      • A ## Controls section links each Logseq/Entity/UI/Control in the area, in panel or screen order. A ## Areas section links smaller areas when there are any. Link rather than embed; control pages are short and many.
      • A ## Source section links the user guide or manual section that describes the area.

    • Examples

      • Microfreak/UI → Microfreak/UI/Oscillator
      • Microfreak/UI/Front → Microfreak/UI/Front/Row/01 Top → Microfreak/UI/Front/Row/01 Top/01 Matrix
      • Ableton/Live/UI → Ableton/Live/UI/Arrangement View and Ableton/Live/UI/Control Bar
      • A Launchpad page would follow the same shape at Launchpad/UI/<Area>, for example its grid of pads.
Logseq/Entity/UI/Control

  • UI Control

    • In this garden, UI Control pages model one thing a person operates on a product's interface — a knob, button, pad, fader, switch, field or slider — so any control can be linked by name.

    • What counts

      • A control the product labels or its documentation names: Microfreak/UI/Oscillator/Knob/Timbre, Ableton/Live/UI/Control Bar/Button/Arrangement Record.
      • On hardware, a physical control; in software, an on-screen control, including draggable markers such as a loop brace or a locator.
      • A menu command with no control on screen belongs under the item's menu pages, such as Ableton/Menu/Options/Follow, and a keyboard shortcut is a Logseq/Entity/Keyshort. A control page links to both when they exist.
      • A control corresponds to an UX/Design/Atomic/L1 - Atom.

    • Identity and names

      • Place a control at <Item>/UI/<Area>/<Kind>/<Name>, under the Logseq/Entity/UI/Area that holds it.
      • <Kind> is the noun the product's documentation uses for that control, singular and in Title Case: Knob, Button, Switch, Toggle, Field, Slider, Menu, Pad, Fader, Marker, Jack, Strip.
      • <Name> is the label printed on the panel or used in the manual.
      • On a panel mapped by position, a numbered single control carries its kind in its own name, <Row>/<NN> <Name> <Kind>, as in Microfreak/UI/Front/Row/01 Top/02 Paraphonic Button. A control in a numbered group keeps <Group>/<Kind>/<Name>, and when the group has only one control of that kind the name is left off: Microfreak/UI/Front/Row/01 Top/01 Matrix/Knob.
      • A control that selects among named modes has one page per mode beneath it, and a parameter that only exists in one mode has its page beneath that mode: Logseq/Entity/UI/Control/Setting.

    • Page shape

      • Frontmatter: logseq-entity:: [[Logseq/Entity/UI/Control]] and up:: to its area. See Logseq/Frontmatter for shared conventions.
      • One bullet-wrapped H1 with the control's name and kind, then one sentence on what it does.
      • A picture of the control cropped from the user guide's panel figure, kept on a Logseq/Entity/Asset/B2 page at <Control>/Asset/Panel/png.
      • Optional blocks, in this order, when they apply:
        • Behavior — how the control changes its value, from Logseq/Entity/UI/Control/Kind.
        • Values — its range or its positions.
        • Settings — links to its mode and parameter pages.
        • Gestures — links to its gesture pages.
        • Remote control — how another device reaches it, such as a MIDI CC number or a MIDI mapping.
        • Source — the user guide or manual section that describes it.

    • Examples

      • MicroFreak: Microfreak/UI/Oscillator/Knob/Type, Microfreak/UI/Oscillator/Knob/Timbre
      • Ableton Live: Ableton/Live/UI/Control Bar/Button/Arrangement Record, Ableton/Live/UI/Arrangement View/Button/Set Locator
      • Launchpad: a pad at Launchpad/UI/<Area>/Pad/<Name>; Launchpad/Custom/Mode/1 Arrangement describes one pad set up as a toggle.
Logseq/Entity/UI/Control/Kind

  • UI Control Kind

    • A proposal for describing how a Logseq/Entity/UI/Control changes its value, apart from the protocol that carries it. Not yet a preference.

    • Two separate questions

      • Form — what the control is physically or on screen: knob, button, pad, fader, field. The <Kind> segment of a control's page name records the form, in the product's own word.
      • Behavior — what happens to the value when the control is operated. The same form can behave in different ways: a Launchpad pad can be a toggle, a momentary button or a trigger, as in Launchpad/Custom/Mode/1 Arrangement.
      • MIDI is one way to carry a control's value to another device. A behavior describes the control itself; a MIDI CC number or a MIDI mapping goes under the control's Remote control block.

    • Proposed behaviors

      • Buttons

        • Momentary — on while held, off when released.
        • Trigger — fires one event when pressed and keeps no state, such as Ableton/Live/UI/Arrangement View/Button/Set Locator.
        • Toggle — alternates between two states on each press, such as Ableton/Live/UI/Control Bar/Button/Arrangement Record.
        • Multi-state toggle — steps through three or more states in a fixed cycle on each press.

      • Continuous controls

        • Unipolar — a value from zero up to a maximum, such as 0–127 or 0–100%.
        • Bipolar — a value centered on zero that runs from a negative minimum to a positive maximum, such as Length on Microfreak/UI/Oscillator/Knob/Type/Sample/Length, from -100 to 100.
        • Relative (endless) — sends increments and decrements with no fixed end; the device keeps the value.

      • Stepped controls

        • Selector — moves through a fixed list of named positions, such as Microfreak/UI/Oscillator/Knob/Type.
        • Numeric field — holds a number typed in or dragged, such as Ableton/Live/UI/Control Bar/Field/Arrangement Position.

      • Combined controls

        • Encoder with push — a rotary control whose press acts as a separate button.
        • Pressure — adds a continuous value to a pad or key while held, such as aftertouch.
        • Position on a surface — a fader, slider or touch strip whose value follows a position along a line, or an XY pad that gives two values at once.

    • Open questions

      • Whether each behavior gets its own page under this one, so a control page can link to it.
      • Whether a control page records its behavior in a property such as ui-control-behavior:: or in a body line.
      • How to model a control whose behavior depends on a mode, such as a knob that is bipolar in one oscillator model and unipolar in another.
Logseq/Entity/UI/Control/Setting

  • UI Control Setting

    • In this garden, UI Control Setting pages model one mode a Logseq/Entity/UI/Control selects, one parameter that exists only in such a mode, or one gesture that gives the control another function.

    • What counts

      • A mode: one named position of a selector, such as the oscillator model Microfreak/UI/Oscillator/Knob/Type/VAnalog.
      • A parameter: the name another control takes while that mode is active, such as Microfreak/UI/Oscillator/Knob/Type/VAnalog/Detune, which the Wave knob sets.
      • A gesture: a way of operating the control other than its plain use, such as pressing a knob, holding a button, or using the control while Shift is held: Microfreak/UI/Front/Row/01 Top/06 Save Button/Hold.
      • A plain value along a range, such as 64 on a knob, is not a setting page.

    • Identity and names

      • A mode sits at <Control>/<Mode>, beneath the control that selects it; a parameter sits at <Control>/<Mode>/<Parameter>.
      • A gesture sits at <Control>/<Gesture>, named Press, Hold or Shift. A gesture that combines two nests the second beneath the first: Microfreak/UI/Front/Row/01 Top/02 Paraphonic Button/Hold/Shift.
      • Use the names the display or manual shows.

    • Page shape

      • Frontmatter: logseq-entity:: [[Logseq/Entity/UI/Control/Setting]] and up:: to the control or mode above it; prev:: and next:: follow the order of modes in the manual when the modes are numbered.
      • One bullet-wrapped H1, then one sentence on what the setting does.
      • A parameter page names the control that sets it, with a link.
      • A Source line links the user guide or manual section.

Logseq/MCP/Server/Survey/Report
  • Direct Node/CLI Tools: Libraries and command-line utilities (often Node.js or ClojureScript-based) that read the Logseq graph files or database directly (e.g. via Datascript) without the Logseq UI. These enable custom queries and automations, sometimes allowing writes by modifying the Markdown/Org files.
  • Access to Multiple Graphs: Logseq itself can only open one graph at a time in the UI, and similarly the local HTTP API operates on that one graph. The MCP servers don't yet provide a seamless multi-graph switch (you'd have to stop Logseq and reopen a different graph, or run multiple Logseq instances on different ports). The ergut server lists a list_graphs function, but using it still requires switching context for subsequent operations. By contrast, logseq-query (lq) was built with multi-graph in mind – it lists all your local graphs and lets you target any of them for queries. So for cross-graph reporting (without merging them), lq is handy. In principle, one could run multiple MCP server instances on different ports, each connected to a different Logseq graph (if you launch multiple Logseq processes), but this is not a common or officially documented practice.
Logseq/Publish/Explanation/Options for Hosting Larger Files
  • Bulk upload via web or UI: Some services provide web dashboards to upload files (Cloudflare R2 allows direct file upload in their dashboard, Backblaze B2 has a web interface, etc.), but these are not ideal for large files or many files at once. A GUI like Cyberduck or Mountain Duck (desktop applications) can connect to various storage services and let files be dragged-and-dropped. Cyberduck is open source and supports S3, Backblaze B2, etc., which might be handy if a more visual approach is desired. It can even generate shareable links.
Logseq/Q/Can the graph view be disabled?
  • Short answer: No built-in setting disables the global graph view in the released file-based version. There is no Settings-UI toggle, config.edn flag, or feature flag for it. The accidental triggers can be removed instead — disable the keyboard shortcut and hide the sidebar link. The heavy Pixi.js/WebGL render only runs when you navigate to the /graph route, so removing the entry points avoids opening it (and the crash) by accident.
  • The unreleased database version adds a sidebar-navigations show/hide UI for nav items; that does not exist in the file-based release, so do not rely on a sidebar toggle.
