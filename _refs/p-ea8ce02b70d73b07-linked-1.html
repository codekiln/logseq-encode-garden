2025-12-11 Thu
  • Rust learning
    • Rust/format - documented the format! macro for string formatting
    • Cargo/nexttest
      • I've started using this in Person/codekiln/GitHub/langstar.
        • It surprised me here
          • My question:

            • In python and js, tools like linters would typically be locked alongside the libraries and specified in the package manager. Does rust really differ from these that much?

          • ChatGPT/Response
            • cargo-nextest is a binary tool (cargo subcommand), not a Rust library. Binary tools must be installed via cargo install, not added to Cargo.toml dev-dependencies.
            • Yes — Rust really does differ here. The difference is structural:
              • Cargo only manages libraries you compile into your project. Cargo.toml is a crate manifest, not a general dependency manifest. Unlike JS (package.json) or Python (requirements.txt), it doesn't manage binary tools.
              • Rust ecosystem assumes tools are installed globally via cargo install, Nix, Docker, or OS package managers. This matches systems languages like Go/C++/Zig, not Python/JS.
              • Version-locking tools happens outside Cargo via devcontainer.json, Dockerfiles, Nix flakes, CI scripts, or a tools/ workspace crate.
            • Bottom line: Cargo intentionally separates build tools from build inputs. For reproducible tooling, use devcontainer/Docker/Nix/CI scripts, not Cargo.toml.

Alacritty

Page reference

  • Alacritty is a cross-platform, GPU-accelerated terminal emulator written in Rust
    • Emphasizes simplicity and performance; intentionally minimal feature set
    • Originally authored by Person/Joe Wilm; now maintained by a community of contributors

    • Platform

      • macOS, Linux, Windows, and FreeBSD

    • Language

      • Rust

    • Image Protocol

      • Supports the Kitty/Graphics/Protocol (added ~2024)
      • Relevant for tools like yazi that display inline images

    • Nix

      • Available in nixpkgs as pkgs.alacritty
      • Idiomatic home-manager module: programs.alacritty
        • Supports generating alacritty.toml config declaratively
        • nix
          			  programs.alacritty = {
			    enable = true;
			    settings = {
			      font.normal.family = "JetBrains Mono";
			      window.opacity = 0.95;
			    };
			  };
        • font.normal.family uses JetBrains/Font/Mono Nerd.

    • Notable Features

      • GPU rendering via OpenGL/Metal
      • Vi mode for keyboard-driven selection and navigation
      • No tabs or splits built-in — intentional; delegates to tmux/zellij
      • Config via a single alacritty.toml file

Deno
Deno
  • A "secure-by-default" Runtime for JavaScript, TypeScript, and WebAssembly. It is a Rust program that embeds the V8 engine, ships as a single executable, and includes its own tooling for formatting, linting, testing, and bundling.
DenoImplementation
  • Deno is mostly a Rust program. The code you write runs inside V8, but the runtime around it is written in Rust: the scheduler, permission system, module loader, filesystem and network access, process management, the Node.js compatibility layer, the command-line interface, and much of the Web API.
DenoImplementation
  • deno_core is the lower-level Rust/crate that embeds V8 in Rust; Deno is built on top of it.
