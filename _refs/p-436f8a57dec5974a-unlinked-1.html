Arturia/MicroFreak/Idea/Rust CLI Preset Manager

  • Why Elektroid is the right reference

    • Elektroid already ships mature MicroFreak support (since v3.1): preset, sample, and wavetable transfer, with the reverse-engineering acknowledged as legitimate by an Arturia staff member — see Arturia/Forum/24/05/MIDI Control Center alternative for MicroFreak on Linux.
    • An Arturia staff reply in that thread notes the MiniFreak (a different, newer instrument) dropped MIDI configuration entirely. That doesn't affect the MicroFreak line this idea targets.
  • Elektroid's src/connectors/microfreak.c + microfreak.h + microfreak_sample.c (GPLv3, dagargo/elektroid) document the MicroFreak SysEx protocol in detail:
    • Arturia manufacturer ID 00 20 6B, MicroFreak family/model bytes, a firmware-major-version-5 gate in the handshake.
    • Preset = a 0x23-byte header plus 146 parts of 32 bytes each.
    • Sample and wavetable directory entries are 28-byte header structs (address, size, checksum, name, id).
    • Samples transfer in 4096-byte blocks using 7-bit/8-bit MIDI-safe packing, with a documented memory-fragmentation model and a defragment operation.
    • A storage-stats query reports free space; transfers carry a checksum.
  • Elektroid's layering: MIDI/SysEx transport (generic identity handshake, send/receive with timeout and cancellation) → device protocol (MicroFreak-specific message framing) → data model (a generic byte-blob container) → CLI dispatch.
  • elektroid-cli is already GTK-free (~1150 lines, buildable standalone via the ELEKTROID_CLI_ONLY build option) and shares all of the above with the GUI. Its verb set (ld, info, df, ls, ul/dl/rdl, send/receive) is a workable starting command surface, trimmed to the MicroFreak's three storage domains.
  • The midir crate covers macOS (CoreMIDI), Linux (ALSA), and Windows (WinMM) behind one API, so the same transport code runs on all three without Elektroid's separate ALSA/RtMidi backend split.
  • Elektroid ships both unit tests (test/tests_microfreak.c) and per-filesystem integration shell scripts. Unit-test the message framing and packing in isolation, then integration-test against a real device (or recorded SysEx fixtures) per storage domain.

Logseq/Entity/Preset/Synth/Microfreak
  • The saved-header inventory reads slot, name, category and initialization status. It cannot detect a same-name edit to oscillator, filter, envelope, modulation or sequence settings. The Elektroid header decoder supplies the protocol evidence.
  • Elektroid’s preset download and serialization retain the preset payload for export: up to 146 blocks of 32 bytes. Supported payloads contain labeled raw parameter records for oscillator, filter, envelopes, LFO, modulation routes and preset settings. Repeated live reads matched the corresponding MIDI Control Center export byte for byte; the parameter inspection documentation records the framing and remaining interpretation limits.

Microfreak/CLI/Preset metadata over USB
  • Direct preset renaming is feasible through MIDI SysEx over USB. Elektroid implements the write sequence; the garden already has Python/RtMidi readers and full-preset backup support.
  • Elektroid MicroFreak connector provides preset listing, renaming, downloading and uploading. Its preset operation tables do not implement deletion.
  • microfreak_preset_rename reads a saved preset header with operation 0x19, mode 0. The response uses operation 0x52.
  • Device slot addresses are zero-based; user-facing slots are 1–512. Name storage supports 14 characters. Elektroid accepts spaces, letters, digits, period, underscore and hyphen, replaces unsupported characters with periods, and truncates long names. A custom CLI could reject invalid input and show the accepted name before writing.
  • Elektroid's rename selects the preset afterward. That can replace an unsaved edit in the active sound; device validation should determine whether selecting the preset is required for persistence or only for refreshing the display.
  • Update name: directly supported by Elektroid's header write sequence.
  • Create: import a complete preset or copy an existing preset into a chosen slot. Elektroid implements full preset upload; slots are fixed storage locations rather than newly allocated records.
  • Delete: reset a slot to an initialized preset. Elektroid can serialize and upload initialized presets, but its preset connector exposes no delete operation. The reset behavior and persistence need device testing before exposing deletion.
  • Test against the connected instrument's firmware. The inspected Elektroid connector requires firmware major version 5; this is an implementation constraint, not proof that other versions cannot support the protocol.
