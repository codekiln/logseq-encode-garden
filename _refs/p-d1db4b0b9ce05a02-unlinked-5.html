tmux/Keyshort/Pane/Resize Pane
  • Ghostty's built-in defaults bind alt+arrow_left=esc:b and alt+arrow_right=esc:f (readline word-jump). These ship regardless of macos-option-as-alt and take priority over Option-as-Meta. tmux's M-Left/M-Right expect xterm sequences \033[1;3D/\033[1;3C — not ESC b/ESC f — so they never fire.
  • The fix (overriding Ghostty's defaults with keybind = alt+arrow_left=esc:[1;3D) breaks word navigation at the terminal, which is more valuable. Accepted limitation on macOS.

tmux/Q/How do I activate M-1 through M-7 to select a tmux pane layout?
  • In tmux binding notation, M- is the Meta modifier, which maps to Alt (or Option on macOS) — not Command. Prefix Cmd+1 sends a key tmux does not recognize for these bindings.

  • macOS terminal requirement

    • The terminal emulator must forward Option as a Meta keypress. In iTerm2: Preferences → Profiles → Keys → set Left Option key to Esc+ (or Meta). In Terminal.app: Use Option as Meta key is not supported natively — consider switching to iTerm2.
tmux/Q/What expands every item in tree mode, and why does Cmd-plus resize the Ghostty font instead?
  • Key/Meta on macOS is ⌥, and only when the terminal is told to send it that way. macos-option-as-alt = true in the Ghostty config makes ⌥⇧= send ESC then +, which tmux reads as M-+. Ghostty ships no built-in alt+ binding for + or =, so nothing intercepts it on the way through — unlike alt+arrow_left and alt+arrow_right, which do collide (see tmux/Keyshort/Pane/Resize Pane).
  • No Ghostty change is called for. macos-option-as-alt = true is already delivering Key/Meta; unbinding super++ would cost font-size control and still would not help, because tmux is waiting on ⌥, not ⌘.

vim/Q/How can I check whether vim or neovim will yank to the unnamedplus (system) clipboard?
  • Read the option: In Ex mode run :set clipboard? (or :echo &clipboard). If you see clipboard=unnamedplus, yanks and deletes that target the unnamed register are also applied to the + register (the system clipboard on X11/Wayland/macOS when clipboard integration works). unnamed wires the unnamed register to * (primary selection on X11) instead of +.
  • Neovim — provider, not only a compile flag: nvim still uses 'clipboard' the same way, but it talks to the OS through a clipboard provider (e.g. pbcopy / pbpaste on macOS, xclip / xsel on X11, wl-copy / wl-paste on Wayland). Run :checkhealth and open the clipboard (or provider) section: failures there explain unnamedplus set in config while + never updates or paste-from-OS breaks.
  • Troubleshooting — checkhealth OK for pbcopy but visual yank skips macOS clipboard: OK only means Neovim can invoke the clipboard tool. It does not set 'clipboard' to unnamedplus. With the default (empty clipboard), y in visual mode fills " / 0, not +, so Cmd+V outside the editor stays unchanged. Fix: set clipboard=unnamedplus / vim.o.clipboard = 'unnamedplus' in config, or yank explicitly with "+y. Right after a yank, use :echo string(vim.fn.getreg('"')) vs getreg('+') or a full :registers dump to see where the text went.
  • Troubleshooting — plain nvim OK, visual yank “doesn’t work” only under tmux: First verify inside tmux that "+y updates + (:echo getreg('+')). If "+y works but y alone does not, you still need unnamedplus (or always "+y). If "+y also fails in tmux while checkhealth is green, run :messages after the yank (Neovim surfaces provider errors there), then test pbpaste from a shell in the same tmux pane after echo test | pbcopy — if the shell cannot round-trip pasteboard while attached to that tmux session, the editor inherits the same limitation (macOS sometimes tied tmux + pasteboard quirks; older setups used reattach-to-user-namespace).

xargs
  • xargs reads whitespace-separated tokens from stdin and runs a utility with those tokens as arguments, often in several invocations so each command line stays under ARG_MAX (man xargs documents the implementation on your OS; macOS ships BSD xargs).
  • -I replstr (common idiom: -I {}) runs the utility once per input item (or per -L group), replacing replstr in the template. On BSD/macOS this mode implies -x (stop if a single expansion would overflow -s); see man xargs.
  • GNU xargs historically ran the utility once even when stdin was empty unless --no-run-if-empty (often -r) was set. BSD/macOS xargs usually runs nothing on empty input; -r exists for compatibility with GNU scripts but may be a no-op—check man xargs on the machine you run on.

  • macOS notes

    • Terminal emulators (Terminal.app, iTerm2, Warp) start login shells by default on macOS, unlike most Linux distros.
    • /etc/zprofile runs path_helper, which reconstructs $PATH from /etc/paths and files in /etc/paths.d/. PATH additions placed in ~/.zshenv are made before path_helper and may be reordered. Additions in ~/.zprofile come after and stick at the front.
