Claude/Desktop/Q/Is it possible to use AWS Bedrock to power Claude Desktop?
  • Short answer (as of 2026-05-28): Yes. Claude/Desktop can route model inference through Amazon Bedrock in your AWS account via third-party inference configuration (the same Cowork / 3P path used for enterprise Bedrock deployments). This is distinct from the Claude/Code CLI’s CLAUDE_CODE_USE_BEDROCK=1 env-var flow, but serves the same goal: use Bedrock instead of Anthropic-hosted inference endpoints.
  • Enterprise rollout: IT can push the same keys (inferenceBedrockRegion, inferenceBedrockProfile, inferenceBedrockBearerToken, SSO fields, inferenceModels, optional gateway URL) via MDM (Jamf, Intune, Group Policy). AWS describes Claude Cowork in Amazon Bedrock as inference in your account/regions with optional LLM gateway routing (AWS ML blog, Apr 2026).
  • Prerequisites: Bedrock model access in the chosen region (bedrock:InvokeModel, streaming invoke as needed), valid inference profile IDs in inferenceModels for profile/SSO auth, and a Desktop build that includes 3P Bedrock (feature landed in 2026; tracked publicly from anthropics/claude-code#32668).

Course/Reweaving Project/Syllabus/2027 Spring

  • Reweaving Ourselves: Leadership in a World on Fire — Spring 2027 Syllabus

    • Overview

      • Wednesday evenings, 4–7 p.m., in Cambridge, Massachusetts; twelve dated sessions from January 27 through April 21, 2027.
      • Instructor: Person/Rebecca Henderson, John & Natty McArthur Professor at Harvard University.
      • Teaching assistance and book scholarship enquiries: Person/Ray Carp.
      • The document identifies itself as a draft syllabus for Spring 2027. Its filename carries the version label Oct-26; the document does not state a publication date.

      • Purpose

        • An interdisciplinary conversation among university students and practitioners about living through interconnected social and ecological crises, choosing a life’s purpose, and finding useful ways to act.
        • The course examines whether disconnection from oneself, other people, and nature helps explain these crises, and whether personal and collective inner work can contribute to systemic change.
        • Readings, shared practices, and practitioner visits connect personal experience with institutions and social change. Intended outcomes include a sustaining personal practice, a better understanding of how systemic change happens, and possible directions for one’s own life.

    • Requirements

      • Attend every class, apart from an absence approved in advance or a genuine emergency.
      • Submit six responses to the readings, each no longer than 500 words. Responses are due approximately every other week on Monday evening before Wednesday’s class; prompts arrive a week beforehand. Specific submission dates are not listed in the draft.
      • Join a small coached learning circle for an hour each week to support mutual learning and explore applications in everyday life. The draft anticipates virtual meetings but does not finalize the format.
      • Spend at least fifteen minutes daily on a grounding or centering practice. Options include time in nature, journaling, gratitude, Tai Chi, and meditation.

      • Experiential Practice

        • Shared exercises include deep listening, working with grief and difficult emotions, considering other perspectives, and noticing reactions to disagreement or challenging ideas.
        • Exercise participation is voluntary. Some experiences may be challenging, and participants share responsibility for a supportive setting. Anyone who feels unsafe or uncomfortable is asked to contact Henderson or another teaching-team member for support.

DevContainer/Secrets/Report/26/01/Secrets Management in JetBrains DevContainers
  • The reality: by default devcontainers do not inherit the parent process environment in VS Code. A user found that even running VS Code under op run did not pass the variables into the container's environment[15]. They attempted a direct hack by constructing a vscode-remote://dev-container+... launch command with op run, but it still didn't inject the vars. This led to a feature request to support launching devcontainers with the parent environment[16] [17]. As of early 2026, this isn't solved in VS Code yet – and JetBrains IDEs have a similar limitation. JetBrains doesn't provide a built-in way to say "include my host env when creating the Dev Container." So using op run on the JetBrains client or ijdevc CLI likely won't magically populate the remote container's variables.
  • In summary, multi-environment projects manage secrets by: not committing them, using environment variables as the common mechanism, and leveraging each platform's strengths (GitHub Secrets for Codespaces, external vault CLI for local/JetBrains, etc.). The process isn't yet uniform across IDEs, which is why we see developers creatively combining tools to fill the gaps. As of 2026, JetBrains' Clone-from-VCS devcontainers still require a bit of DIY for secrets, whereas platforms like Codespaces and CodeCanvas have more automated injections. Keeping an eye on updates (e.g., new Dev Container CLI features or JetBrains IDE improvements) is wise – this area is actively evolving to reduce friction and improve security for secret management in dev environments.

Git/restore/--staged

  • How to unstage files in git without modifying or removing files #card

    • git restore --staged

      • It ONLY unstages files from the staging area (removes them from what would be committed)
      • It does NOT delete or modify any actual files
      • It does NOT lose any changes
      • The changes will still be there, just moved back to "Changes not staged for commit"
      • It's the newer, safer equivalent to  git/reset/HEAD which Git introduced to make the commands more intuitive.
      • My Notes git restore is for "restoring working tree files" - "restore specified paths in the working tree with some contents from a restore source" - "the command can also be used to restore the content in the index with --staged"
