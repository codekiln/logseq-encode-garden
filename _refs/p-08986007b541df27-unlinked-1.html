git/How To/Discard Changes to Working Dir
  • Run git clean -fd (git/clean/--force git/clean/--directory) to also remove untracked directories
  • Add the -d flag: git clean -fd
git/Q/What's the git command that will remove untracked and unignored files to bring it up to HEAD?
  • Full working tree match to HEAD: run git reset --hard HEAD to discard changes to tracked files (staged and unstaged), then git clean -fd for untracked non-ignored paths. One-liner: git reset --hard HEAD && git clean -fd.
LazyVim/Q/Does LazyVim integrate with rg?
  • Health check: :checkhealth lazyvim verifies rg alongside git, fd, lazygit, fzf, and curl (lua/lazyvim/health.lua). A missing rg is reported as an error, not a warning.
  • The default picker: nvim/Plugin/snacks.nvim's grep source builds its command as rg with --color=never --no-heading --with-filename --line-number --column --smart-case --max-columns=500 plus --glob=!.git; hidden, ignored, follow, and ft picker options map onto --hidden, --no-ignore, -L, and -t. Its file source auto-detects fd first, then rg --files, then find. Snacks' own health check errors out if rg is absent, because Snacks.picker.grep() has no fallback.
  • With editor extras enabled: the nvim/Plugin/telescope.nvim extra prefers rg --files --color never -g !.git for its file finder and falls back to fd/find only if ripgrep is missing; the nvim/Plugin/fzf-lua extra likewise drives rg for grep. So the answer holds whichever picker is in use.

yazi/Q/Is there a way to make yazi display files differently based on the gitignore status?
  • Caveat — fd hides gitignored files by default: yazi uses fd for directory listing and fd itself respects .gitignore, so gitignored files won't appear in the listing at all unless you configure yazi to show them. There is no built-in show_gitignored toggle; the workaround is to pass --no-ignore to fd via manager config or to accept that the badge only shows up on files fd does list. See issue #1655 for context (closed as not planned).
