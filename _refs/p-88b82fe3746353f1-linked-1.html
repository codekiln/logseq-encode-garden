Agent/Skills/Support in Multiple Tools

Page reference

Agent Skills: Support Across Multiple ToolsOverview
  • The Agent/Skills open standard defines what a skill file contains but does not mandate where skill directories live. Each vendor ships a native directory (.claude/skills/, .gemini/skills/, etc.), and .agents/skills/ is the recommended cross-client interoperability path. The gap between these two conventions is the central challenge of multi-tool skill management.

AI/Agent/Harness

Page reference

AI agent harnessOverview
  • An agent harness is the surrounding software that turns a raw AI/LLM into a working AI/Agent: the loop that sends prompts, parses responses, invokes tools, feeds results back, and decides when to stop.
AI agent harnessContext
  • Related but distinct terms: an AI/Agent/Framework is a library for building harnesses (LangGraph, AutoGen, etc.); a harness is the resulting runtime that actually drives an agent's loop, whether built on a framework or from scratch.
AI/Agent/Hook
AI Agent Hook
  • A hook is a deterministic event handler that an AI/Agent host runs around tool execution, session lifecycle, file changes, prompting, compaction, or subagent start and stop. Where a prompt persuades, a hook always fires, and it can block.
AI Agent Hook
  • Unlike Agent/Skills, hooks have no open specification. There is nothing to cite but each vendor's own reference, and the references do not agree.
AI/Agent/Manager
Managing Agent
  • An AI Agent that manages other agents or is responsible for AI/Agent/Orchestration of other agents.
AI/Agent/Skill
AI Agent Skills
  • This page is for the "idea" of how to supply AI/LLM based AI/Agents with "Skills."
AI Agent Skills
  • For the Standard and its reference implementations, see Agent/Skills
AI/Agent/Subagent
Subagent
  • Like AI/Agent/Hook and unlike Agent/Skills, there is no open specification — only each vendor's reference.
Subagent
  • Related but distinct: AI/Agent/Multi is about orchestrating agents; a subagent is the unit being orchestrated.
