GitHub/Issue/Q/What are GitHub issue artifacts?

  • What are GitHub/Issue artifacts?

    • AI Answer

      • Answer/Official from Using artifacts with issues
      • Short answer: GitHub issue artifacts are named content attached to an issue, giving plans, research, decisions, reference links, and interactive HTML a durable place alongside the work. Artifacts can be shared by URL, and edits create version history.
      • The supported formats are:
        • Markdown document (generic): research notes, investigation results, or design documents.
        • Plan (plan): an implementation plan in Markdown.
        • Link (link): a named link to something elsewhere, such as a discussion, prototype, or Slack or Teams thread.
        • HTML file (embedded_html): a self-contained HTML page, such as an interactive prototype, visualization, flowchart, or diagram.
      • In the issue menu: “Add link” attaches a named URL, “Create artifact” creates a Markdown document, and “Create HTML artifact” creates an HTML document.
      • GitHub Actions artifacts are a separate feature: they store files produced by workflow runs. Issue artifacts keep context attached to an issue.
      • Issue artifacts are in public preview on GitHub.com and GitHub Enterprise Cloud. GitHub displays HTML source first; preview runs user-provided code in a restricted sandbox and may allow it to send content to external sites, so preview only HTML you trust.
GitHub/Project/Concept/Terminal Status

  • How to determine which GitHub/Issue/Status closes the issue in a Project

    • Overview

      • GitHub Projects allows custom status fields to track issue progress
      • Status fields are created by GitHub and cannot be renamed
      • There is no explicit "terminal status" configuration in GitHub Projects

    • What Closes an Issue

      • Issues are closed through actions, not through Project status:
        • Manually closing the issue
        • Merging a PR that closes the issue (using keywords like "closes #123")
        • Using the GitHub API to close the issue
      • The Project status field is independent of whether an issue is closed

    • Status Field in Projects

      • Status is a single select field that can be customized with options
      • You can add/edit/remove status options
      • Status changes don't automatically close issues
      • Example project:
        • Backlog
        • Prep/Checkout
        • Prep/Gather Requirements
        • Prep/Researching
        • Prep/Planning
        • Work/Ready for Implementation
        • Work/In Progress
        • Work/Review/Needed
        • Work/Review/In Progress
        • Work/Review/Pre-Merge Checks
        • Completed

    • Best Practices

      • Use status to track workflow state, not completion
      • For completion tracking, use:
        • The issue's closed/open state
        • Milestones
        • Labels
      • Consider automating status updates based on issue events

      • About Projects
      • About Issues
