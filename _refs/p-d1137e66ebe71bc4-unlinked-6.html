ChatGPT/Tool/Idea/Script/To Clean Up Output of Canvas/Report/Deterministic Markdown Formatters
  • Lists: By default, ordered lists are renumbered to use 1. for every item (a "non-numbering" style to minimize diffs). This means mdformat will output:
    				  1. Item A  
				  1. Item B  
				  1. Item C

    for any ordered list, regardless of the original numbers. This approach avoids renumbering all lines when an item is inserted. However, consecutive numbering is available via a --number flag or config if you prefer actual 1,2,3 numbering. Bullet lists are standardized to use - (and will alternate -/* if you have adjacent bullet lists).

  • Final Advice: Determine your highest priorities – e.g., diff friendliness (then Flowmark or mdformat with all-1. lists is helpful), typographic precision (Flowmark with smart quotes), or simplicity and convention (Prettier or mdformat defaults). Then adopt the tool that best matches, and configure it in pre-commit so that every commit has beautifully formatted Markdown. Each of the top tools has documentation and active communities if you run into edge cases. After initial setup, you'll enjoy consistent Markdown styling without any manual effort – just like Black does for your Python code.

Claude/Code/Settings
  • User — ~/.claude/settings.json, which resolves to %USERPROFILE%\.claude on Windows. Applies to every project on the machine and is not shared.
  • Since 2.1.211 the local file lives at the git repository root, resolved through worktrees, so it covers every subdirectory. Older locations are still read. It stays in the starting directory in three cases: outside a git repository, when the repository root is the home directory, and in Agent SDK sessions.
  • autoMode — customize the auto mode classifier through allow, soft_deny, hard_deny, and environment arrays. Include the literal "$defaults" to inherit the built-in rules at that position. classifyAllShell set true suspends shell allow rules so every command is classified. Example: {"soft_deny": ["$defaults", "Never run terraform apply"]}.
  • disableAllHooks — disable every hook, and status line execution with them.
  • statusLine — a command whose output becomes the status line, receiving session context as JSON on stdin. padding insets it, refreshInterval re-runs it every N seconds on top of event-driven updates, and hideVimModeIndicator suppresses the built-in -- INSERT -- marker for a script that renders vim mode itself. Example: {"type": "command", "command": "~/.claude/statusline.sh"}. See the status line documentation.
  • enableAllProjectMcpServers — approve every MCP server declared in the project's .mcp.json automatically.
  • sandbox.network.allowedDomains / deniedDomains — egress allowlist and blocklist, both accepting wildcards. Denied domains always win, and merge from every scope.
  • env — environment variables applied to every session. Example: {"FOO": "bar"}.
  • remoteControlAtStartup — start the Remote Control bridge every session. autoUploadSessions mirrors sessions to claude.ai as view-only, and disableRemoteControl turns Remote Control off entirely.
  • User subagents live in ~/.claude/agents/ and are available in every project.
  • Environment variables can be set in the shell or under the env key in settings.json, which is the way to apply a set of them to every session or roll them out to a team.
  • MCP allow and deny lists — allowedMcpServers and deniedMcpServers gate servers by name, command, or URL pattern across every scope, with the denylist winning.

Claude/Desktop/Scheduled Task/Q/Is there a declarative, programmatic way to manage Claude Desktop scheduled tasks that's scoped to a specific repo?
  • create_scheduled_task(taskId, prompt, description, cronExpression | fireAt) creates a task; update_scheduled_task(taskId, ...) does partial updates (prompt, description, schedule, enabled, notification); list_scheduled_tasks() returns every task's id, schedule, enabled state, and SKILL.md path; delete_scheduled_task(taskId) removes one.
  • That turns "define scheduled tasks declaratively for a repo" into: commit a manifest in the repo (task id, schedule, description, prompt — the same shape as the SKILL.md frontmatter + body Desktop already writes) plus a short instruction telling Claude to reconcile it — call list_scheduled_tasks, diff by taskId, create_scheduled_task for anything missing, update_scheduled_task for anything changed. Opening the repo and asking Claude to run that reconciliation once leaves every machine with the same tasks, without ever hand-filling the New Routine form.
  • Shape: {"scheduledTasks": [{"id", "cronExpression", "enabled", "filePath", "createdAt", "model", "cwd", "useWorktree", "lastRunAt", "approvedPermissions": [...]}], "recordedSkips": {}} — one array for every task on the machine across all repos, disambiguated only by each entry's own cwd. list_scheduled_tasks doesn't surface cwd at all, consistent with the tool being scoped by the calling session rather than by filtering that field.
