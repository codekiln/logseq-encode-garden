FormalCo/Blog/26/01/Using Proxies to Hide Secrets from Claude Code

  • Using Proxies to Hide Secrets from Claude/Code

  • Unrestricted access to secrets: Claude Code has default access to environment variables (like ANTHROPIC_API_KEY) and files (.env, etc.) in the project directory, which can include sensitive credentials
  • Formal Connector & Native Identity Decoupling: Organizations can use Formal's infrastructure (Connectors, Resources, Native Users) so that Claude Code is never given direct access to admin-level API keys; rather, credentials are injected only when necessary via policy enforcement
  • Fine-grained policies: Policies can restrict which endpoints Claude Code can access (e.g. path "/v1/messages"), log every request, and enforce least privilege
  • Never provide secrets inside the Claude Code process when avoidable. Use dummy credentials for development, and let proxies or orchestrators add the real ones outside Claude's context
  • Set HTTP_PROXY / HTTPS_PROXY environment variables so that all HTTP traffic from Claude Code is intercepted
  • Use proxy add-ons: for example, intercept calls to api.anthropic.com, replace dummy/invalid API key from Claude with the real key only at the proxy boundary. Thus, Claude works as if its dummy key is valid, never touching the real key
  • Secrets never enter Claude's context window; reduces risk of leaks or misuse
  • Provides visibility into Claude's external communications
  • Some actions may not be possible if the API key is invalid from Claude's perspective or if endpoints have dynamic behavior

Google/Drive/AI
  • Every option for pointing Anthropic's Claude at Google Drive sorts along two axes, and a comparison that collapses either one is misleading. The first is read versus write: search and retrieval are mature and available nearly everywhere, while writing splits further into file-level writes (create, upload, move, trash, share) and content-level writes (change a paragraph in an existing Doc, set a range of cells in an existing Sheet). The second is which surface Claude is running on — claude.ai in a browser, Claude/Desktop, Claude/Cowork, Claude/Code in a terminal, or the Messages API. An option that exists on one surface frequently does not exist on another.
  • The short form of the whole landscape: nothing Anthropic ships can edit the contents of an existing Google Doc or Google Sheet. That capability exists only where something calls Google's Docs and Sheets APIs directly — a community MCP server, or Claude Code running code you supply.
  • Verified. The Google Workspace connectors help article documents the Drive connector's capabilities as four read items and four write items. Read: "Search and retrieve Google Docs from your Drive"; "Look up file metadata and preview directly without searching first"; "Read Sheets, Slides, PDFs, images, and MS Office files"; "View file permissions and list recent changes to your Drive." Write: "Upload any file type, with optional auto-convert to Google formats"; "Create folders"; "Share, move, and trash files in Google Drive"; "Save Claude-generated files directly to your Drive."
  • Verified — the list contains no in-place edit. Nothing in that set addresses the contents of an existing Google-native file. Every write is file-level or produces a new file. The connector directory entry is narrower still, naming only share, move and trash as writes, and stating that the connector "does not support adding comments, converting xlsx to sheets, or converting pptx to slides."
  • Verified — two Drive integrations are documented separately, with different scope. Alongside the connector, the Google Drive integration page documents a narrower document-picker for chats and projects: Google Docs only, up to 10MB, text extraction only, with Google Sheets and Google Slides both marked "Not currently supported," and images, comments and suggestions not extracted. Its stated availability is Pro, Max, Team and Enterprise. Which of the two a given surface exposes is not reconciled anywhere in the documentation.
  • Verified — auth is per-person OAuth, gated by the org on Team and Enterprise. "You must authenticate directly with your Google account before using these connectors." On Team and Enterprise, "an Owner or Primary Owner must enable these connectors at the organization level before individual users can authenticate," and "owners decide whether members can allow these actions to run without asking each time." Claude mirrors existing Google Workspace permissions rather than widening them.
  • Verified — connectors reach Claude/Code, but Drive must be authorized on claude.ai first. Per Claude Code's MCP documentation, servers added in claude.ai "are automatically available in Claude Code," and appear in /mcp marked as coming from claude.ai. That inheritance requires the active credential to be a claude.ai subscription login — it does not happen under ANTHROPIC_API_KEY, Amazon Bedrock, Google Cloud's Agent Platform, or a token from claude setup-token. Some Anthropic-hosted connectors, named as Microsoft 365, Gmail and Google Calendar, "don't support local OAuth from Claude Code because the upstream identity provider only accepts the redirect URL that claude.ai registered."
  • Inferred — Google Drive is very likely in that same category. Drive is not named in the list, but it is an Anthropic-hosted Google connector authorized through the same claude.ai OAuth redirect as Gmail and Google Calendar. The practical consequence either way is the same: connect Drive in claude.ai's connector settings, and it appears in Claude Code afterwards.

Create and edit files with Claude states that "code execution and file creation is available to all Claude users (Free, Pro, Max, Team, and Enterprise) on the web, Claude Desktop, and Claude Mobile." Claude produces .xlsx, .pptx, .docx and PDF files in a private code-execution environment, with a 30MB per-file ceiling. The announcement offers "Download your completed files or save directly to Google Drive."

It uses connectors with per-tool modes of "Always allow," "Needs approval," or "Blocked," and creates and edits files including "spreadsheets with working formulas."

Claude for Excel is "generally available to Pro, Max, Team, and Enterprise plans," updates cell values while keeping formula relationships intact, and performs native operations including sort, filter, pivot table edits, conditional formatting and data validation. Word, PowerPoint and Outlook add-ins exist alongside it.

Anthropic's current documentation does not mention any Google Workspace add-on, so its status, maintenance, and provenance cannot be confirmed from first-party sources. Configure the Drive MCP server instructs you to create your own OAuth web-application credential with https://claude.ai/api/mcp/auth_callback as the redirect URI, request the drive.readonly and drive.file scopes, then add it under Settings → Connectors as a custom connector with your own client ID and secret. herdr/Explanation/Where Input Box Text Comes From
  • A Claude/Code pane that has finished a turn usually has a line of text sitting in its input box, and nobody typed it. It is a prompt suggestion: Claude Code's own prediction of what the user would type next, generated by the agent in that pane from that pane's conversation, and parked in the box until a keystroke accepts it.
  • Read from the 2.1.228 binary: the generator forks the live conversation, appends a single instruction headed [SUGGESTION MODE: Suggest what the user might naturally type next into Claude Code.], denies the model every tool, and writes nothing to the transcript.
  • The generator discards its own output when it runs over 12 words or 100 characters, spans more than one sentence, is a question, carries newlines or asterisks, opens in Claude's voice (Let me, I'll, Here's), is evaluative (looks good, thanks), or is the bare word done.
  • Accepting it takes a deliberate keystroke: Tab or an arrow key accepts the suggestion for editing. Claude Code 2.0.70 added Enter as accept-and-submit, and 2.1.136 fixed Enter auto-submitting on an otherwise empty input.
  • The faint rendering is a Claude Code implementation detail observed through herdr, not a herdr feature. Anyone who reads it as a herdr contract will watch the wrong changelog.
  • The claude detection manifest's live_prompt_box rule reads that region for a line starting ❯ and calls the pane idle. herdr agent explain <target> prints the matched rule and the region's text.
  • Eight entries across 363 versions of the changelog Claude Code ships mention prompt suggestions — the /config toggle (2.0.71), the accept keys (2.0.70, 2.1.136), cache regressions (2.1.49, 2.1.50, 2.1.62), and an interaction with output styles (2.1.141). None of them mentions how a suggestion is rendered.
  • So the rendering is undocumented styling, not a published contract. A Claude Code release that restyles the suggestion — italic instead of faint, a colour, a different placeholder mechanism — would change it silently, with nothing erroring.
  • Where the suggestion is wanted as data rather than as pixels, Claude Code already exposes it explicitly: in print/SDK mode, --prompt-suggestions emits a prompt_suggestion message after each turn carrying the predicted next user prompt. That is a real interface with a name. The gap is only for reading an interactive pane from outside, and closing it properly would mean asking Claude Code — not herdr — either to stop rendering generated and typed text identically but for one attribute, or to expose the distinction outright.
  • /config carries a Prompt suggestions toggle, which writes promptSuggestionEnabled to the user-level Claude Code config; absent or true means enabled. CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION overrides it in the environment, and --prompt-suggestions sets it per invocation.
  • "This is a herdr signal." herdr forwards a cell attribute that Claude Code chose to set. Both halves of the mechanism live in Claude Code: what to suggest, and how to paint it.
