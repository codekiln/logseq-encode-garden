LEG Display DetailLessons from 2026-08-25 Tue
  • git grep -E gives \b no meaning, so the pattern matches nothing and exits 1. That reads like a genuine no-match, and a tool answering false costs more than one that errors. git grep -P in single quotes is the fix. Separately, printf, echo -e and $'...' substitute a real 0x08 byte before git runs, which defeats -E, -F and -P alike, and quoting a heredoc delimiter does not protect a Python string literal against the same substitution.   • Deliverables go on tracked paths, and whether tmp/ is one of them is a fact about the repository rather than about the fleet. Check it per checkout with git ls-files tmp/, which lists what is actually tracked; do not carry the answer between repos. git check-ignore does not answer this — it reports nothing for a tracked file, with exit 1, which reads the same as no rule matching at all, so --no-index is needed to audit a pattern: git/Q/Why does git check-ignore report nothing for a tracked file?.
    • Where tmp/ is ignored, a secret scan that skips ignored paths is bypassed entirely by git add -f on a tmp/ file.
    • Where it is not, there is no bypass and no privacy either: in this garden .gitignore carries no tmp rule, three notes under tmp/ are tracked, and anything written there is published. Scan a working note for credential-shaped strings before committing it.
