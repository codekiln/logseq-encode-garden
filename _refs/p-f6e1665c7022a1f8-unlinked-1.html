1Password/How To/Add Password Expiration

  • How To Add Password Expiration to an Item in 1Password

    • Overview

      • This guide shows you how to add a password expiration date and reminder to an item in 1Password.
      • For users who want to track when passwords or other sensitive items expire and receive notifications before they do.

    • Prerequisites

      • 1Password installed and set up on your device
      • An existing item in 1Password that you want to add an expiration date to
      • Access to edit the item

    • Steps

      • 1. Open 1Password

        • Launch the 1Password application on your device

      • 2. Select the Item

        • Navigate to and select the item you want to add an expiration date to
        • This can be a password, credit card, or any other sensitive item

      • 3. Edit the Item

        • Click the "Edit" button to modify the item's details

      • 4. Add a Date Field

        • Add a custom field to the item
        • Set the field type to "date"
        • This is required before the expiry reminder option will appear

      • 5. Set the Expiration Date

        • Enter your desired expiration date in the date field you just created

      • 6. Configure the Reminder

        • Once the date field is added, the expiry date reminder option will appear
        • Set how far in advance you want to be reminded before the item expires

      • 7. Save Changes

        • Click "Save" to apply the expiration date and reminder settings
        • 1Password's Watchtower feature will now alert you as the expiration date approaches

    • Troubleshooting

      • If you don't see the expiry reminder option: Make sure you've added a custom field of type "date" first
      • If the reminder doesn't appear: Verify that the date field is properly set and saved
      • If Watchtower isn't showing alerts: Check your 1Password notification settings

AWS/Secrets Manager/Secret/Rotation
  • Every template on that list requires the secret to be an AWS/Secrets Manager/Secret/KeyValue whose JSON matches the expected credential schema (username, password, host, ...) — never a plain AWS/Secrets Manager/Secret/SecretString. CreateSecret API reference, the "For database credentials" paragraph: "For database credentials you want to rotate, for Secrets Manager to be able to rotate the secret, you must make sure the JSON you store in the SecretString matches the JSON structure of a database secret."
  • createSecret — generate the new value (e.g. a random password) and store it with put_secret_value, tagged AWSPENDING. Quote from that page: "Then it generates a new secret value ... Next it calls put_secret_value to store it with the staging label AWSPENDING."
  • On an AWS/Secrets Manager/Secret/KeyValue secret, a correctly written createSecret step reads the current AWSCURRENT JSON first and writes back the complete object with only the target field (e.g. password) changed. Secrets Manager itself performs no such merge — that is the function's own job, and it is exactly the job fnox skips, per the hazard noted below.

Brave/How To/Turn off Password Manager

  • How To Turn off Password Manager in Brave

    • Overview

      • This guide shows you how to disable Brave's built-in password manager
      • Useful if you're using a third-party password manager like 1Password, NordPass, or Bitwarden
      • Prevents Brave from prompting to save passwords or automatically signing you into websites

    • Prerequisites

      • Brave browser installed on your computer
      • Access to Brave settings

    • Steps

      • 1. Open Brave Settings

        • Click the three-line menu icon (☰) in the upper-right corner of the Brave browser window
        • Select "Settings" from the dropdown menu

      • 2. Navigate to Password Manager

        • In the Settings menu, click on "Autofill and Passwords"
        • Then select "Password Manager"

      • 3. Disable Password Saving and Auto Sign-in

        • In the Password Manager settings, toggle off "Offer to save passwords"
        • Toggle off "Auto Sign-in"
        • Brave will no longer prompt you to save passwords or automatically sign you into websites

    • Optional: Remove Previously Saved Passwords

      • If you have previously saved passwords in Brave and want to remove them:

      • Delete Individual Passwords

        • In the Password Manager settings, you'll see a list of saved passwords
        • Click on each saved password entry you wish to remove
        • Click the "Delete" button to remove the selected password

      • Delete All Saved Passwords at Once

        • Click the three-line menu icon (☰) in the upper-right corner
        • Select "Settings", then "Privacy and Security"
        • Click on "Clear browsing data"
        • In the dialog box, set the "Time range" to "All time"
        • Check the box for "Passwords and other sign-in data"
        • Ensure other data types are unchecked if you don't wish to delete them
        • Click "Clear data" to remove all saved passwords

    • Troubleshooting

      • If you don't see the "Autofill and Passwords" option: Make sure you're using a recent version of Brave browser
      • If toggles don't appear: Try refreshing the Settings page or restarting Brave
      • If passwords still appear: Clear your browsing data as described in the optional steps above

Manual desktop sign-in can reduce exposure, but should not be described as a verified equivalent.
  • The documented password-private alternative: OpenAI's cloud browser sign-in flow pauses for a secure form. Credentials go directly to the remote browser and are not visible to the model. Fill that secure form yourself from 1Password where supported; never send the credential through chat. The cloud browser does not inherit the local 1Password extension. The desktop browser and cloud browser are different environments, so the cloud guarantee cannot simply be applied to desktop autofill.
  • Remaining uncertainty: A current, explicit OpenAI or 1Password statement covering password-field redaction, browser inspection, and autofill in the desktop built-in browser is needed before claiming that passwords cannot reach the model there. Keeping the password private also leaves the signed-in account's content and permitted actions available to the agent.

Mac/OS/Q/How does Touch ID for sudo (PAM) work?
  • What Touch ID adds — Apple ships a PAM module, typically referenced as pam_tid.so, that can satisfy an auth step by prompting for Touch ID (or another Local Authentication method you have enabled, such as Apple Watch approval on some setups). When that line is active and PAM reaches it with a sufficient (or similar) control, a successful biometric (or watch) check can count as authentication instead of typing your account password.
  • Why sudo_local (macOS Sonoma 14+) — Older instructions edited /etc/pam.d/sudo directly; macOS updates could replace that file. From Sonoma onward, Apple’s default sudo PAM file can include a local file (/etc/pam.d/sudo_local) so administrators enable Touch ID in sudo_local (often by copying sudo_local.template and uncommenting the pam_tid.so line). That keeps the change in a file meant to persist across upgrades instead of re-editing the stock sudo stack after each update. Six Colors: In macOS Sonoma, Touch ID for sudo can survive updates · Apple: Enter administrator commands in Terminal on Mac (general sudo behavior; password vs Touch ID is configured locally via PAM)

pmset/mise/Task/lid-awake/install-sudoers

  • Allow the Lid-Awake Switch Without a Password

    • Installs a sudoers rule so pmset/mise/Task/lid-awake/enable and pmset/mise/Task/lid-awake/restore run without a password prompt.

    • Invocation

      • Run it in a terminal; it asks for sudo once and refuses to run without a TTY.
        • sh
          			  mise run pmset:lid-awake:install-sudoers
			  mise run pmset:lid-awake:install-sudoers --remove

    • Side effects

      • Writes /etc/sudoers.d/pmset-lid-awake, mode 0440, owned by root:wheel. The rule lets the current user run /usr/bin/pmset -a disablesleep 1 and /usr/bin/pmset -a disablesleep 0 with NOPASSWD. Every other sudo command still asks for a password.
      • Checks the rule with visudo -cf before installing it, and the whole sudoers configuration with visudo -c after. A failed second check removes the file.
      • --remove deletes the file.

    • Trade-off

      • Any process running as the user can switch lid-close sleep without a prompt. Touch ID for sudo asks for a fingerprint each time instead, applies to every sudo command, and needs pam_reattach to work inside tmux.

    • Source and help

      • sh
        		  mise run pmset:lid-awake:install-sudoers --help
