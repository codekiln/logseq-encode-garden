  • Reddit/User/SaulFontaine says that there is an order to the prompting components for AI/LLMs, and that later prompts that try to modify behavior can be "shadowed" by earlier prompts. They are specifically referring to OpenAI here.

    • Here is roughly how the pieces get stitched together from highest to lowest priority:

      • 1 - OpenAI's built-in system prompt ("You are ChatGPT, a large language model trained by OpenAI...")

      • 2 - Customer-supplied system message (if you are using the API and inject one)

      • 3 - Developer message(s) (the instructions the product team gave)

      • 4 - Memory/context layers (persistent memories, user bio)

      • 5 - User-preference prompts (your typography and style rules)

      • 6 - Recent conversation turn(s)

      • 7 - Current user query

      • 8 - OpenAI's rollout-level "finalizing" instructions and decoding defaults

    • It looks like the typography rules you supply at step 5 can get overshadowed by the built-in system prompt at step 1 or by step 8's decoding defaults (where smart-quote normalization lives). To permanently override that you need to elevate your ASCII-only rule into the very first system message. For example:

    • System message: All output must use only ASCII punctuation. Do not apply any smart-quote or typographic substitutions. Replace any U+2018, U+2019, U+201C or U+201D characters with the ASCII single quote (') or double quote (") before finalizing output.

Ableton/Live/Report/26/09/Open-source options for controlling Live 11 from coding agents
  • Remote Scripts are the pragmatic but unsupported-at-the-API-level alternative. Ableton explicitly tells users how to install third-party Remote Scripts into the User Library and select them as a Control Surface. [2] The scripts can execute Python inside Live and interact with Live's internal object model. This is very powerful, and hardware-control-surface implementations have depended on it for years, but it creates exactly the engineering problem you alluded to with devices such as the Launchpad: projects are coupling themselves to Python modules and behaviors that are not documented by Ableton as a stable general-purpose SDK. AbletonOSC's source is representative: ControlSurface, _Framework, and Live are imported directly. [12]
  • Wouter Stierhout's project has the best default capability/network combination I found. It exposes explicitly typed operations rather than Python eval, validates inputs, binds the Live-side socket to loopback, documents the lack of authentication, supplies pinned package invocation examples, backs up replaced scripts, maintains a server/Remote-Script version handshake, and runs tests and linting in CI. [5] The reason I stop short of calling it the overall safest choice is maturity: roughly 20 commits and a tiny user population cannot tell you as much about weird edge cases as years of use can. [5]

  • Live analyzes sounds to support two features: Similarity Search, which lists Core Library and User Library items that sound like a reference, and Similar Sample Swapping, which replaces samples in Drum Rack, Simpler or Drum Sampler.
  • Analysis runs in the background on new user audio files and can be paused from the Status Bar. Core Library content comes pre-analyzed.

  • Every device can save its settings as a preset. Presets live in the User Library, apart from any Set.
Ableton/Live/UG/03 Live Concepts/21 Saving and Exporting
  • Dragging a Session clip to the User Library saves it as a Live Clip (Ableton/File/.alc), which keeps the clip settings and the track's instruments and effects. Useful for drum patterns with their kit, loop variations, and ideas set aside for later. See Ableton/Clip/How To/Save to Library.
Ableton/Live/UG/04 Browser/04 Filters and Tags/02 Tags
  • Background sound analysis auto-tags user samples up to 60 seconds long with the best-matching tag. Turn this off with Enable Auto Tags in the Filter View menu, or change or remove auto tags in the Tag Editor.
Ableton/Live/UG/04 Browser/07 Places
  • Places holds Packs, the User Library, the Current Project and folders you add. Library Settings can also show Splice, Cloud and Push.
    • Packs: the Core Library, installed Packs, and Pack updates and downloads.
    • Splice: the Splice sample catalog.
    • Cloud: Sets synced from Ableton/Note and Move.
    • Push: files on a Push 3 in Standalone Mode.
    • User Library: your saved presets, defaults, grooves, samples, Live Clips and more.
    • Current Project: the open Project's files.
    • User folders, added with Add Folder….
  • Ableton/Live/UG/04 Browser/07 Places/06 User Library

    • 4.7.6 User Library

      • The User Library stores your presets, defaults, Live Clips, templates and more, in its own location so it can be backed up or shared.
      • Default location: ~/Music/Ableton/User Library (Mac) or \Users\<username>\Documents\Ableton\User Library (Win). Change it with "Location of User Library" in Library Settings.
      • It starts with Clips, Defaults, Grooves, Presets and Samples folders; add or remove folders as you like.

      • 4.7.6.1 ABL Assets

        • Assets from Move and Note Sets synced through Ableton Cloud.

      • 4.7.6.2 Chord Banks

        • Chord banks saved for the Stacks MIDI Tool.

      • 4.7.6.3 Clips Folder

        • Live Clips (Ableton/File/.alc); drag a clip here to save it. MIDI clips keep notes, automation and device settings. Referenced samples are saved with the clip while "Collect Files on Export" is set to Always, the default.

      • 4.7.6.4 Defaults Folder

        • Saved defaults for tracks, devices, effects, Slicing to MIDI and more, recalled each time the device loads.

      • 4.7.6.5 Grooves Folder

        • Custom grooves (Ableton/File/.agr). Extract one from any clip by dragging it to the Groove Pool or with Extract Groove. See Ableton/Live/UG/14 Grooves.

      • 4.7.6.6 Presets Folder

        • Instrument, Max for Live, MIDI effect and audio effect presets (Ableton/File/.adv), with any referenced samples.

      • 4.7.6.7 Samples Folder

        • Samples referenced by saved presets and tracks, with separate subfolders for recorded and processed samples.

      • 4.7.6.8 Templates Folder

        • Template Sets and the custom default Live Set.

      • 4.7.6.9 Managing Files in the User Library

        • File → Manage Files, then Manage User Library, shows its contents and any missing or external files.
  • Ableton/Live/UG/04 Browser/07 Places/08 User Folders

    • 4.7.8 User Folders

      • Add your own folders, such as sample collections on external drives, by dropping them into Places or with Add Folder. Live scans them, with a spinning wheel while it works.
      • Adding doesn't move the folder. A moved, renamed or disconnected folder shows grayed out; use Locate Folder, or Remove from Sidebar to forget it.

      • Note/Info Add specific content folders, not whole drives; very large folders slow indexing and may be re-indexed at every launch.
