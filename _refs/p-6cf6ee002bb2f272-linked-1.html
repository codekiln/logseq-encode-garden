2025-12-11 Thu
Rust learningCargo/nexttest
  • I've started using this in Person/codekiln/GitHub/langstar.
    • It surprised me here
      • My question:

        • In python and js, tools like linters would typically be locked alongside the libraries and specified in the package manager. Does rust really differ from these that much?

      • ChatGPT/Response
        • cargo-nextest is a binary tool (cargo subcommand), not a Rust library. Binary tools must be installed via cargo install, not added to Cargo.toml dev-dependencies.
        • Yes — Rust really does differ here. The difference is structural:
          • Cargo only manages libraries you compile into your project. Cargo.toml is a crate manifest, not a general dependency manifest. Unlike JS (package.json) or Python (requirements.txt), it doesn't manage binary tools.
          • Rust ecosystem assumes tools are installed globally via cargo install, Nix, Docker, or OS package managers. This matches systems languages like Go/C++/Zig, not Python/JS.
          • Version-locking tools happens outside Cargo via devcontainer.json, Dockerfiles, Nix flakes, CI scripts, or a tools/ workspace crate.
        • Bottom line: Cargo intentionally separates build tools from build inputs. For reproducible tooling, use devcontainer/Docker/Nix/CI scripts, not Cargo.toml.

CursorAI/How To/Share Cursor Project Rules Across Repositories and Users
How to share CursorAI/Project Rules across multiple projects and users

  • Steps (adapted from Person/codekiln/GitHub/logseq-cursor-rules README.md)

    • 1. Create the rules directory if applicable

      • First ensure you have a .cursor/rules directory in your project:
        • bash
          				  mkdir -p .cursor/rules

    • 2. Add the rules as a git submodule

      • Add the repository containing your cursor project rules as a submodule:
        • bash
          				  git submodule add <repository-url> .cursor/rules/<rules-directory-name>
        • Example:
          • bash
            					  git submodule add git@github.com:username/my-cursor-rules.git .cursor/rules/my-cursor-rules

    • 3. Commit the changes

      • bash
        			  git add .cursor/rules/<rules-directory-name> .gitmodules
			  git commit -m "feat: add cursor project rules as submodule"
