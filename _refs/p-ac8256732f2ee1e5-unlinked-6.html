Game/Video/Dev/ECS
  • ECS models a simulation as entities (identities), components (data attached to those identities), and systems (logic that runs over entities matching a component shape).
  • Components are data — components usually store state only; behavior emerges from how systems read and write that state.
  • “ECS is just OOP with different names” — not really; the important shift is separating identity, data, and behavior so systems compose across entity kinds.
  • “All ECS implementations look the same” — false; some emphasize data-oriented storage and schedulers, while others stay minimal and library-like.
  • “Using ECS automatically makes a game faster” — false; the payoff depends on the workload, data layout, and whether the architecture actually fits the problem.

    • About PATs

      • Personal access tokens are an alternative to using passwords for authentication to GitHub when using the GitHub API or the command line.
      • Personal access tokens are intended to access GitHub resources on behalf of yourself.
      • To access resources on behalf of an organization, or for long-lived integrations, you should use a GitHub App. For more information, see About creating GitHub Apps.

      • Types of personal access tokens

        • GitHub currently supports two types of personal access tokens:
          • fine-grained personal access tokens
          • personal access tokens (classic)
        • GitHub recommends that you use GitHub Fine-Grained PATs instead of GitHub Personal Access Token (Classic) whenever possible.

  • Not documented, but stated publicly by a Docs engineer — the reverse direction inlines rather than references. Google/Sheet/Q/Does Google Sheets have a way to sort by more than one column at once?
  • Answer/Official from Sort & filter your data, SORT function, and SORTN
  • Short answer: Yes, on the web, through one specific dialog. Highlight the cells, then Data > Sort range > Advanced range sorting options, choose the first column and its direction, and click Add another sort column for each further level. That dialog is the only documented multi-column sort in the interface — the right-click commands on a column letter sort by one column only, and the Android and iPhone apps document nothing beyond a single key.
  • Verified — the full documented sequence. Sort & filter your data, under Sort data in alphabetical or numerical order, gives these steps for the web version: "Highlight the group of cells you'd like to sort." / "If your sheet includes a header row, freeze the first row." / Click Data > Sort range > Advanced range sorting options (the article renders that path with arrow icons between the three menu items). / "If your columns have titles, click Data has header row." / "Select the column you'd like to be sorted first and choose a sorting order." / "To add another sorting rule, click Add another sort column." / Click Sort.
  • Verified — header handling is two separate steps. Freezing the first row comes before opening the dialog; Data has header row is ticked inside it. The documentation lists both and explains neither, so do not assume one substitutes for the other.
  • Verified — the multi-column dialog lives only on the range path. Advanced range sorting options appears in the article exactly once, inside the Data > Sort range sequence. The whole-sheet section does not reference it and offers no equivalent.
  • Inferred — how to get a multi-column sort over all the data. Select the rows you want reordered and use the range path; there is no documented whole-sheet route to a second sort key. Google does not describe this substitution, and the selection is what makes it safe or not: a range sort reorders only the cells inside the selection, so selecting some columns of a table and not others leaves the rest of each row behind.
  • Verified — SORTN adds a row limit to the same multi-key sort. SORTN "Returns the first n items in a data set after performing a sort," with signature SORTN(range, [n], [display_ties_mode], [sort_column1, is_ascending1], ...). Its later pairs are "Additional columns and sort order flags used if a tie happens, in order of precedence" — the same precedence model, described from the tie-breaking side.
  • Verified — a sort key may be a column outside the data being sorted. Both pages state that sort_column can be "the index of the column in range or a range outside of range containing the values by which to sort," provided that range "must be a single column with the same number of rows as range." The dialog has no equivalent of this.
  • Inferred — the formula answers a different question than the dialog. SORT and SORTN produce a sorted copy in the cells holding the formula; the dialog rewrites the cells in place. Google's function pages do not draw this contrast, but it follows from these being formulas. Pick the formula when the sorted output should update as the source changes, and the dialog when the stored data itself should be reordered.
  • Verified — a filter view is per-person and includes sorting. Created with Data > Create filter view, then "Sort and filter the data," then Save View. The article lists "Filter or sort a spreadsheet you don't have edit access to" among what filter views are for, and notes "You can only apply one filter view at a time."
  • Could not confirm — whether a filter view's sort takes more than one column. The only instruction is "Sort and filter the data." The article never shows the sort interface inside a filter view and never mentions Add another sort column in that context. Nothing here establishes that the multi-column dialog is reachable from a filter view.
  • Whether tables have their own multi-column sort. Use tables in Google Sheets says only that "Each view can have its own unique configurations to filter and sort" and links back to the same Sort & filter your data article rather than describing a table-specific sort dialog.
