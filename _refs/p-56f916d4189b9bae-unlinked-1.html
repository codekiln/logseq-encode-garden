    • manual install in XDG/EnvVar/XDG_CONFIG_HOME

      • make sure that $XDG_CONFIG_HOME exists
        • mkdir -p $XDG_CONFIG_HOME
      • make a symbolic link from the XDG config home for tmux/Config to the locally cloned oh-my-tmux config file
        • ln -s ~/.tmux/.tmux.conf "$XDG_CONFIG_HOME/tmux/tmux.conf"

        • cp ~/.tmux/.tmux.conf.local "$XDG_CONFIG_HOME/tmux/tmux.conf

      • make sure a config dir for tmux exists
        • mkdir -p ~/.config/tmux

        • ln -s ~/.tmux/.tmux.conf ~/.config/tmux/tmux.conf
      • copy oh-my-tmux's default tmux/Config/local to the dotconfig dir
        • cp ~/.tmux/.tmux.conf.local ~/.config/tmux/tmux.conf.local

tmux/Q/How can I enable vi keys for everything in tmux from the command prompt without editing the config?
  • These commands change the running tmux server; they do not touch ~/.tmux.conf. The settings disappear when the server stops (tmux kill-server or system reboot). To make them permanent, add the same two set -g lines to your config and reload with Prefix r (or tmux source-file ~/.tmux.conf).

tmux/Q/Is there a keyshort to jump back to my previous window, even in a different session, after using prefix w to open the session picker?
  • gpakosz/.tmux's own .tmux.conf already does the two underlying pieces separately: bind BTab switch-client -l (last session) and bind Tab last-window (last window), confirming both primitives are ordinary bindable commands, not special-cased behavior.
  • For anything smarter than a fixed chain — e.g. only running last-window when the session actually changed, or tracking the exact previously active pane rather than tmux's own single last-session/last-window pointers — a plugin would use run-shell to call a script, and persist its own state between key presses with user options (set -g @my_var ..., read back via #{@my_var} or show-options -gv). The same .tmux.conf uses this exact user-option pattern (e.g. @battery_percentage, @battery_charge) to cache values across separate command invocations.
  • A TPM-installed plugin is just a .tmux-suffixed shell script that a user's config sources via run-shell, and which calls bind-key/set-hook itself — no different in kind from hand-written bind-key lines in .tmux.conf.

tmux/Q/What does it mean to zoom a tmux pane, and how do you zoom out?
  • Verify your session: Run tmux list-keys and look for resize-pane -Z (or search for z in the prefix table) to confirm nothing in oh-my-tmux or .tmux.conf remapped it.
  • Optional status hint: Add something like #{?pane_zoomed,[Z],} to status-left or status-right in .tmux.conf if you want a persistent on-screen flag (see FORMATS in tmux(1)).

tmux/Status Line/Q/Why does my status-right repeat the same session name instead of listing every session?
  • Nothing in ~/.config/tmux/tmux.conf sets status-left or status-right — that file only sets terminal features, passthrough, and update-environment. No theme, no plugin manager, no set -ag line, and no config reload appending to the option.
  • That script's other fingerprints are still on the server: status-left opens with its two-letter project tag, and set-titles-string still names the other project. ~/.config/tmux/tmux.conf never reverts them, because unset-at-runtime options only return on a new server or an explicit unset.
