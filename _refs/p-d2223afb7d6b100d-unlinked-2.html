  • Ableton File Types – Conceptual Overview

    • Overview

      • Ableton Live uses a variety of proprietary file types to represent sets, clips, presets, and metadata. Some are human-readable (XML or JSON), others are binary. Understanding these formats is essential for workflows involving version control (e.g., Git).

    • Context

      • Many Ableton users want to store projects in Git for collaboration, history, and diffs. The challenge is that some file types are opaque binaries, while others can be normalized for text-based diffs. Knowing which is which helps decide what to commit, ignore, or preprocess.

    • Key Principles

      • Textual formats (XML/JSON) are git-friendly with proper filters.
      • Binary formats (analysis files, waveforms, grooves) are not useful to version and can be regenerated.
      • Archive formats (packs) should be treated as immutable binaries.
      • Programmatically generated files (e.g., .asd) should be excluded since Live will recreate them.

    • File Types & Internal Structure

      • Ableton/File/.als
        • Purpose: Live Set (entire project/arrangement).
        • Format: gzipped XML.
        • Speculation: Unzipping yields structured XML with tracks, devices, automation.
        • Git: Store in repo. Use a textconv filter to decompress for diffs.
        • See-Also:
          • GitHub/codekiln/ableton-live-git-hooks
      • Ableton/File/.alc
        • Purpose: Live Clip (saved audio or MIDI clip + device chain).
        • Format: gzipped XML.
        • Git: Same as .als. Useful to store; enables clip reuse and diffs.
        • See Also:
          • GitHub/codekiln/ableton-live-git-hooks
      • Ableton/File/.adg
        • Purpose: Device Group (Rack preset).
        • Format: gzipped XML.
        • Git: Store; use gzip -cd filter for text diffs.
      • Ableton/File/.adv
        • Purpose: Device Preset (single Instrument/Effect preset).
        • Format: likely gzipped XML (similar to .adg).
        • Git: Store; verify format. Use same filter strategy as .adg.
      • Ableton/File/.amxd
        • Purpose: Max for Live Device (custom patch).
        • Format: JSON with a non-JSON binary header.
        • Git: Store; configure Git diff driver to skip header (e.g. awk '(NR>1)'). This exposes JSON for readable diffs.
        • See Also: Person/Zack Steinkamp/blog/posts/2022-02-15-git-diff-amxd-max
      • Ableton/File/.ask
        • Purpose: Live Skin (UI color theme).
        • Format: XML.
        • Git: Store; Git can diff directly.
      • Ableton/File/.alp
        • Purpose: Live Pack (compressed bundle of sets, samples, presets).
        • Format: zipped archive.
        • Git: Treat as binary. Store only released versions; not suitable for diffs.
      • Ableton/File/.asd
        • Purpose: Sample Analysis File (tempo, warp markers, waveform cache).
        • Format: binary metadata.
        • Git: Do not store; regenerated by Live.
      • Ableton/File/.ams
        • Purpose: Ableton Meta Sound (Operator waveforms for Sampler/Simpler).
        • Format: binary.
        • Git: Store only if custom waveforms are part of creative assets; otherwise ignore.
      • Ableton/File/.agr
        • Purpose: Groove File (timing/humanization template).
        • Format: binary.
        • Git: Store if custom grooves are central to project; diffs not possible.

    • Misconceptions

      • Myth: All Ableton files are binary and unsuitable for Git.

        Reality: Many are gzipped XML or JSON and can be made git-friendly with filters.

      • Myth: .asd files must be backed up.

        Reality: They’re metadata caches and should be ignored in source control.

    • Recommendations for Git

      • Store with filters: .als, .alc, .adg, .adv, .amxd, .ask.
      • Ignore: .asd (auto-regenerated).
      • Store as binary: .alp, .ams, .agr (no useful diffs).
      • Use custom diff drivers:
        • .als/.alc/.adg/.adv: gzip -cd.
        • .amxd: strip header, parse JSON.
        • .ask: plain XML diff.

    • See Also

      • Person/Zack Steinkamp/blog/posts/2022-02-15-git-diff-amxd-max
      • GitHub/codekiln/ableton-live-git-hooks

Ableton/Live/UG/17 Routing and IO/05 Internal Routings
  • Track A sends to B through A's Output Type. Suits many-to-one setups such as submixes or several MIDI tracks sharing an instrument. Soloing B still plays everything feeding it.
  • Track B takes from A through B's Input Type. Suits one-to-many setups such as layering, where several tracks tap one source.
Ableton/Live/UG/17 Routing and IO/05 Internal Routings/02 Making Use of Internal Routing
  • Or set each track's Output Type to Sends Only and use a send, so a return track acts as the submix.
  • Point a second MIDI track's Output Type at the instrument track, and choose the instrument itself (not Track In) as Output Channel. Both tracks then play one instrument, so sound changes affect both.
  • To mute each part separately, move the original clips to a third track and leave the instrument alone on its track, with Input Type set to No Input so it has no Arm button.
  • A multi-timbral instrument plays a different part on each MIDI channel. Extra MIDI tracks feed its parts by pointing Output Type at the instrument's track and Output Channel at each part's channel; audio tracks tap its individual outputs.
  • A vocoder on a strings track needs a speech signal at its sidechain input: create a "Speech" track whose Output Type is the strings track and whose Output Channel is the vocoder's sidechain. Vocoder plug-ins with their own carrier synth go on a MIDI track and are fed the same way.
  • To double a strings part with brass, add a MIDI track with a brass instrument whose Input Type taps the strings track at Post FX. MIDI from another track is tapped after its MIDI effects and just before its instrument, so the brass gets the same notes.

Ableton/Live/UG/29 Audio Effect Reference/02 Auto Filter
  • Auto Filter applies a choice of filter types and analog-modeled filter circuits, moved by an LFO and an envelope follower. The envelope follower can track the filtered signal or an external sidechain.
  • Ableton/Live/UG/29 Audio Effect Reference/02 Auto Filter/01 Filter Types

    • 29.2.1 Filter Types

      • Filter Type offers ten filters:
        • Low-pass — cuts above the cutoff; 12 or 24 dB slope
        • High-pass — cuts below the cutoff; 12 or 24 dB
        • Band-pass — passes a band around the cutoff; 12 or 24 dB
        • Notch — cuts a narrow band; 12 or 24 dB
        • Morph — sweeps from low-pass through band-pass to high-pass; 6, 12, 24 or 48 dB
        • DJ — one bipolar control: above zero removes lows, below zero removes highs, with resonance rising toward ±100%
        • Comb — a series of peaks or notches across the spectrum; flanger-like when modulated
        • Resampling — resamples at a rate set by the cutoff, giving aliasing and degradation
        • Notch + LP — a notch plus a low-pass roll-off; 12 or 24 dB
        • Vowel — emphasizes formants so the sound resembles a voice
      • Freq sets the cutoff. The DJ filter has Control instead; Vowel has Pitch, which shifts the formants in semitones.
      • Res sets emphasis at the cutoff; it does nothing on Resampling. Vowel has Formant instead, moving through the vowels a, e, i, o, u.
      • Morph, on Morph, Comb, Notch + LP and Vowel:
        • Morph filter — low values low-pass, middle band-pass, high values high-pass
        • Comb — from peaks (low) to notches (high) at multiples of the cutoff
        • Notch + LP — moves the notch closer to the low-pass cutoff as the value rises, reaching it at 100%
        • Vowel — increasingly evens out the formant gains
