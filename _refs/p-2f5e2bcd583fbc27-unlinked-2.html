Slack/How To/Copy Channel Members to Another

  • How To Copy Members from One Slack Channel to Another

    • Goal

      • Duplicate the member list from one Slack channel into another.

    • Preconditions

      • Slack workspace access with permission to add people to both channels.

    • Procedure

      • 1. Open the Source Channel

        • Navigate to the Slack channel you want to copy members from.
        • Slack - copy name of channel - Stack Overflow

      • 2. Copy Member Details

        • Click the channel name at the top.
        • Go to the Settings tab.
        • Click Copy member names or Copy member email addresses (if available).
        • Copy member names and email addresses from a conversation - Slack

      • 3. Open the Destination Channel

        • Navigate to the Slack channel where you want to add the members.
        • How to add someone to Slack channel? - CLRN

      • 4. Add Members

        • Click the channel name at the top.
        • Select Add people.
        • Paste the copied names or emails into the field.
        • Click Add.
        • Add people to a channel - Slack

    • Troubleshooting

      • If you don’t see the copy option, you may lack permissions or need to use a different browser.
      • Slack supports adding up to 1,000 people at once.

    • References

      • How to Use Slack for Work - Lifewire
      • Slack™ Member Extractor - Microsoft Edge Addons

Slack/Q/Is there any ability to add some kind of a portal between a Microsoft Teams chat and a Slack channel so that messages published to one would get published to the other?
  • SlackBridge — per its Capterra listing, messages posted in either app appear in the other. It uses Slack OAuth 2.0 and the Microsoft Graph API, needs no coding, and can link several Teams tenants to one Slack workspace. The claims come from the vendor listing, which has very few reviews.
  • Mio — a paid service that translates each platform's API calls and delivers the message to the other side. Its Microsoft Teams connector works in both directions.
  • Power Automate has a Slack connector with a post-message action. Messages are capped at 4000 characters, and calls are throttled to 100 per connection per 60 seconds. Pair it with a Teams trigger to push Teams messages into Slack. A mirror in the other direction needs a second flow.
  • ClearFeed's Teams and Slack integration guide notes that most Slack-and-Teams integrations are one-way alerts or meeting links, not shared conversation context.
tmux/Q/Why doesn't prefix Alt-Left or Alt-Right resize the inner horizontal split in a nested tmux layout (outer top-bottom split and lower left-right split), while Alt-Up or Alt-Down still move the outer boundary?
  • Short answer: The tmux/Keyshort/Pane/Resize Pane bindings are still calling resize-pane on the active pane. In a nested layout they only move the immediate vertical border between the two bottom panes. If that border cannot move—most often because the other bottom pane is already at tmux’s minimum width—the command no-ops, which looks like “resize doesn’t work.” Alt-Up / Alt-Down still move the outer (full-width) horizontal divider, where there is usually more slack in rows than you have spare columns in the bottom row, so those resizes are more likely to succeed.
  • Minimum pane size: tmux enforces a minimum width and height for panes (on the order of a few cells; see discussion around PANE_MINIMUM in tmux issue #1480). If bottom-left is already as narrow as allowed, you cannot steal more columns for bottom-right, so both horizontal nudges can appear dead until you first give slack (e.g. widen the left pane with the opposite horizontal resize, or resize from the other pane).
  • Asymmetric slack: After a top/bottom split, the bottom row may be short in height but still wide; the limiting factor for horizontal resize is columns shared with the sibling, not the whole window. Vertical resize of the outer split uses full window width and many rows, so it succeeds more often even in the same session.
