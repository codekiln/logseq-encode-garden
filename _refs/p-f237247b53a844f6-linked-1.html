yazi/Q/In yazi, how can I integrate zoxide and fzf beyond the z (fzf-only) picker?

Page reference

  • In yazi, how can I integrate zoxide and fzf beyond the z (fzf-only subtree) picker?

    • My Notes

      • When I press Z, I do get the pop-up and it does appear to do the Zoxide thing.

    • Answer

      • Keyshort: yazi/Keyshort/Plugin/fzf/Fuzzy pick subtree (z), yazi/Keyshort/Plugin/Zoxide/Open interactive picker (Z)
      • AI/Response
        • Yes — Yazi already ships both. The z key runs the built-in fzf plugin (fuzzy pick files and directories under the current directory or among selections). The Z key runs the built-in zoxide plugin, which opens zoxide’s interactive UI; that UI uses fzf as its picker, so you get the same kind of “zoxide + fzf” flow as in the shell, but scoped to Yazi’s navigation (Builtins | Yazi — fzf.lua / zoxide.lua).
        • Requirements for Z: install zoxide and fzf, and initialize zoxide for your shell so its database is populated and tools can use it (per zoxide installation). If Z does nothing or errors, check those dependencies first.
        • Optional: record directories in zoxide when Yazi cds by enabling update_db in ~/.config/yazi/init.lua: require("zoxide"):setup { update_db = true } (Builtins | Yazi — zoxide.lua options).
        • If you want the shell’s exact widget (e.g. your zi binding): run a blocking shell from Yazi (e.g. shell with --block) that executes your zoxide+fzf script, then return to Yazi — that hands the full terminal to fzf for one shot (keymap — shell). Prefer the built-in Z when you only need to jump and stay inside Yazi.
