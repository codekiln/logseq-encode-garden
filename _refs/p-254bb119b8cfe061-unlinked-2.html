vim/Q/How can I check whether vim or neovim will yank to the unnamedplus (system) clipboard?
  • Neovim from Lua: vim.o.clipboard and vim.go.clipboard both reflect the global 'clipboard' value; :lua print(vim.o.clipboard) matches :set clipboard?.
  • Neovim quick probe in Lua: :lua vim.fn.setreg('+', 'nvim-clipboard-test') then paste outside the editor; or :lua print(vim.fn.getreg('+')) after yy with unnamedplus — should echo the yanked text when the provider works.
  • Troubleshooting — no visible echo from commands: :set clipboard?, :lua print(...), and :echo has('clipboard') usually print a one-line echo in the message area (easy to miss when cmdheight is 1, another UI plugin steals echoes, or the line scrolls away). Try :set cmdheight=3, rerun :set clipboard?, or :echomsg 'clipboard=' .. &clipboard and then :messages. For Lua, :lua vim.notify(vim.inspect(vim.o.clipboard)) (with nvim-notify) or :put =execute('set clipboard?') drops text into the buffer so you cannot miss it.
  • Troubleshooting — single-register output looks empty: For :reg + and :reg ", (1) :registers with no args is easier than single-register forms; watch for -- More -- and advance the pager. (2) :reg " must end with exactly one " (the register name); an extra " turns it into a different command / error. (3) Empty + may print no line for + in a short listing—use string(getreg(...)) or :put =... so emptiness shows as '' or a blank inserted line. (4) UI plugins (noice.nvim, etc.) sometimes reroute or auto-dismiss multiline :registers output—fall back to :echo string(...) / :put =... or :lua vim.print({ ... }).

vim/Q/What is the difference between the leader key and the local leader key?
  • In my LazyVim config: LazyVim sets mapleader = " " (Space); I additionally override maplocalleader = " " in config/options.lua (LazyVim otherwise leaves maplocalleader at vim's default of \). Practical effect: any filetype plugin's <LocalLeader> mapping shows up under <Space> for me too, instead of under \ — one fewer prefix to remember, at the small cost that a global <leader>x and a filetype's <localleader>x could now collide in the same buffer since they share a prefix.

yazi/Q/In yazi, how can I integrate zoxide and fzf beyond the z (fzf-only) picker?
  • Yes — Yazi already ships both. The z key runs the built-in fzf plugin (fuzzy pick files and directories under the current directory or among selections). The Z key runs the built-in zoxide plugin, which opens zoxide’s interactive UI; that UI uses fzf as its picker, so you get the same kind of “zoxide + fzf” flow as in the shell, but scoped to Yazi’s navigation (Builtins | Yazi — fzf.lua / zoxide.lua).
  • Optional: record directories in zoxide when Yazi cds by enabling update_db in ~/.config/yazi/init.lua: require("zoxide"):setup { update_db = true } (Builtins | Yazi — zoxide.lua options).
