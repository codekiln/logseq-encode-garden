yazi/Q/Does yazi have a git integration that copies a file path relative to the repository root? If so, what is the keyshort?

  • Does yazi have a git integration that copies a file path relative to the repository root? If so, what is the keyshort?

    • Answer

      • AI/Response
        • No — not as a built-in “git integration.” Stock yazi does not define a copy variant that is relative to git rev-parse --show-toplevel. The manager copy action only supports path (the file’s URL, i.e. the usual absolute filesystem path), dirname, filename, and name_without_ext, plus optional --separator (unix vs platform default) — there is no git_root (or similar) option in the documented action (keymap — mgr.copy).
        • Default path-copy keybindings (preset chord c then second key; “c ⇒ c” means press c, then c again): c ⇒ c copies the file path; c ⇒ d parent directory path; c ⇒ f filename; c ⇒ n filename without extension (Quick Start — Copy paths). Those are the shipped shortcuts for clipboard path operations; none of them is “relative to repo root.”
        • Practical workaround: bind shell to run a one-liner that computes a path relative to the repo root (e.g. realpath / git rev-parse / python -c …) and pipes to pbcopy on macOS or wl-copy / xclip on Linux, or use a community plugin if you want a maintained implementation (search the Yazi resources / plugin ecosystem for “git” / “relative path” plugins).

yazi/Q/How can I maximize the preview pane so I can use glow in a bigger space?
  • Goal: from Yazi, open the highlighted file in glow as a pager using the full terminal, then return to Yazi. The Answer below spells out the minimal config; the trick is Yazi’s blocking shell, not the preview column width.
  • Simplest way — glow in a blocking shell: Assign a shortcut that means: run a command on the file under the cursor, give it the full terminal, and do not show Yazi again until that command exits. In Yazi you do that with the shell action plus the --block flag. The placeholder %h becomes the hovered file’s path. Use glow -p so glow runs as a pager (long files scroll inside glow). Docs: shell.
  • 1. Open (or create) your Yazi keymap file: ~/.config/yazi/keymap.toml.
  • 			  [[mgr.prepend_keymap]]
			  on   = [ "g", "l" ]
			  run  = "shell 'glow -p %h' --block"
			  desc = "Glow pager for hovered file (full terminal)"
  • 3. Restart Yazi. Point at a markdown file, press the shortcut, read in glow, quit glow (often q). You should return to Yazi.
  • Optional — bigger preview column only: The narrow preview panel on the right is separate from this full-terminal trick. To widen only that panel (still not full-screen), edit ~/.config/yazi/yazi.toml, section [mgr], key ratio, three numbers meaning parent column, file list, preview — e.g. [0, 1, 3] hides the parent column and gives preview more room (ratio). That is optional; it does not replace shell … --block for full-terminal glow.

yazi/Q/In yazi, if I launched without the shell wrapper, can I still cd to the current directory when I exit?
  • No direct mechanism. The --cwd-file flag must be passed at launch time — there is no way to add it retroactively to a running yazi session. Without it, yazi never writes the cwd file, so the parent shell has no file to read.
  • Going forward: always launch yazi via the y wrapper function (which passes --cwd-file) instead of calling yazi directly. See yazi/Q/In yazi, if I navigate to a directory, is there a way to exit yazi into that directory?.
yazi/Q/In yazi, if I navigate to a directory, is there a way to exit yazi into that directory?
  • Yes — use the official shell wrapper function (conventionally named y). It launches yazi with --cwd-file, which makes yazi write its working directory to a temp file on exit. The wrapper then reads that file and cds your shell to it.
  • bash
    				  function y() {
				    local tmp="$(mktemp -t "yazi-cwd.XXXXXX")" cwd
				    yazi "$@" --cwd-file="$tmp"
				    if cwd="$(command cat -- "$tmp")" && [ -n "$cwd" ] && [ "$cwd" != "$PWD" ]; then
				      builtin cd -- "$cwd"
				    fi
				    rm -f -- "$tmp"
				  }

    • Answer

      • AI/Response
        • Yazzi is almost certainly yazi (the Rust terminal file manager).
        • Move to another folder: select the entry (Space, or use visual mode v), press x to yank (cut), navigate to the target directory (h / j / k / l or arrows), then p to paste. That moves the file or directory from the source path to the destination.

Zoom H5/UG/08 Recording/02 Mode Overview
  • The H5 has two recording modes, MULTI FILE and STEREO FILE. They create different file types and allow different recording formats.

  • MULTI FILE mode

    • The L/R inputs from the XY mic or another input capsule record to the L/R tracks. Inputs 1 and 2 record to tracks 1 and 2. Each track is saved as a separate file.
    • Because every input has its own file, the playback volume and panning of each one can be changed independently after recording.
    • Only 44.1 kHz or 48 kHz WAV, at 16 or 24 bits, can be recorded in this mode.
    • Linking Inputs 1 and 2 records them together as one stereo file. A recording with the link on creates two stereo files: one from the L/R inputs and one from Inputs 1/2.
    • MULTI FILE mode: one file per track, mixed for monitoring

  • STEREO FILE mode

    • Whichever of the L/R inputs and Inputs 1/2 are selected record together into a single stereo file. Each pair is switched on or off as a pair: Zoom H5/UG/08 Recording/05 Inputs and Levels.
    • Only two tracks can be recorded, but any recording format can be chosen: Zoom H5/UG/12 Tools/08 Rec Format. This includes 96 kHz WAV at 16 or 24 bits, and MP3.
    • Use this mode for the highest audio quality or for smaller files.
    • STEREO FILE mode: one stereo file

  • MULTI FILE mode creates one file per selected input. nnnn is the project number.

Zoom H5/UG/08 Recording/12 Backup Rec
  • Along with the normal recording, the H5 records a second file from the L/R input at a level 12 dB lower. If the main recording distorts because the level was set too high, the backup can be used instead.

  • Note/Info The backup file takes the original name with _BU added. A recording named ZOOM0001_TrLR.wav gets the backup ZOOM0001_TrLR_BU.wav.

  • Note/Info No backup file is created if the L/R input is not selected.

  • Note/Info To play a backup, select and play the file whose name ends in _BU. In MULTI FILE mode, assign it to a track as described under "Assigning files to tracks" in Zoom H5/UG/08 Recording/13 Overdubbing. In STEREO FILE mode, pick it from the file list: Zoom H5/UG/09 Playback/02 Select from Lists.

Zoom H5/UG/08 Recording/13 Overdubbing
  • Overdubbing works only in MULTI FILE mode, with 44.1 kHz or 48 kHz WAV formats.
  • Only projects recorded in MULTI FILE mode can be overdubbed.
  • An overdub never overwrites the file already on a track. It creates a new file named after the track with a two-digit take number, such as ZOOM0001_TrLR-01.WAV. Any file can later be assigned to any track.
  • An overdub on track 1 adds a file to the project folder
  • Mixdown combines overdubbed recordings into one stereo file: Zoom H5/UG/10 Project and File Editing/04 Mixdown.

Zoom H5/UG/09 Playback/01 Basic Playback
  • Select the project or file to play, or move to a mark: press Back or Forward.
  • Mute or unmute tracks, in MULTI FILE mode only: press a track button. A lit green indicator means the track plays; an unlit one means it is muted.

  • Note/Info Invalid Project! or Invalid File! means the selected project or file has a problem.

  • Note/Info No Project! or No File! means there is no project or file that can be played.

  • A project or file can hold up to 99 marks.

  • 1. Press MENU, then use the scroll button to select PROJECT (MULTI FILE mode) or FILE LIST (STEREO FILE mode).
  • 2. Use the scroll button to select the project or file to play, then press the scroll button.
    • Project and file lists

    • Note/Info Pressing PLAY/PAUSE here also starts playback of the selected project or file.

  • The selected project or file starts playing.

Zoom H5/UG/09 Playback/03 Playback Mode
  • The playback mode decides what plays after the selected project or file.
  • PLAY ONE — plays only the selected project or file.
  • PLAY ALL — plays from the selected project or file through to the last one.
  • REPEAT ONE — plays the selected project or file over and over.
  • REPEAT ALL — plays every project or file in the selected folder over and over.
Zoom H5/UG/09 Playback/04 Pitch
  • 1. Press MENU, then use the scroll button to select PROJECT (MULTI FILE mode) or FILE LIST (STEREO FILE mode).
  • 2. Use the scroll button to select the project or file to adjust, then press the scroll button.

  • Note/Info In MULTI FILE mode, the pitch change applies to the whole project. It cannot be set for each track.

  • Note/Info In MULTI FILE mode, each project keeps its own pitch setting. In STEREO FILE mode, one setting applies to every file.

Zoom H5/UG/09 Playback/05 Speed
  • 1. Press MENU, then use the scroll button to select PROJECT (MULTI FILE mode) or FILE LIST (STEREO FILE mode).
  • 2. Use the scroll button to select the project or file to adjust, then press the scroll button.

  • Note/Info In MULTI FILE mode, each project keeps its own speed setting. In STEREO FILE mode, one setting applies to every file.
