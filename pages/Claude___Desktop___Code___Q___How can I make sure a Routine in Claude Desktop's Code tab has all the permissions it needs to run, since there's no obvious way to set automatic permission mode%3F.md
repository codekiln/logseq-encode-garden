- # How can I make sure a [[Claude/Routine]] in [[Claude/Desktop/Code]] has all the permissions it needs to run, since there's no obvious way to set automatic permission mode?
	- ## [[AI Answer]]
		- **Short answer:** It depends which of the two things Desktop's **Routines** page created. A **Cloud** routine has no permission-mode picker at all — that's by design, not a gap: cloud routines always run autonomously with no approval prompts, and their reach is bounded by repositories, the cloud environment, and connectors instead. A **Local** scheduled task does have a permission-mode picker and a per-task "always allow" approval list — if that's the control that seems to be missing, it's likely because **Cloud** was picked instead of **Local** when the routine was created.
		- [[Answer/Official]] from [Automate work with routines](https://code.claude.com/docs/en/routines) and [Schedule recurring tasks in Claude Code Desktop](https://code.claude.com/docs/en/desktop-scheduled-tasks):
		- **Cloud routines** (Desktop → **Routines** → **New routine** → **Cloud**): "Routines run autonomously as full Claude Code cloud sessions: there is no permission-mode picker and no approval prompts during a run." What a cloud routine can reach is scoped by the **repositories** selected (and their branch-push rule), the **environment**'s network access and variables, and the **connectors** included — not by a permission mode.
		- **Local scheduled tasks** (Desktop → **Routines** → **New routine** → **Local**): these do have a permission mode. The instructions form "includes pickers for the permission mode and model," set per task at creation or edit time; allow rules from `~/.claude/settings.json` also apply to scheduled-task sessions.
		- **Getting a Local task to run with full automatic permission:** if a task runs in **Ask** mode and hits a tool it isn't allowed to use, the run stalls in the sidebar until approved. To avoid that: click **Run now** right after creating the task, watch for permission prompts, and choose **"always allow"** for each one — future scheduled runs then auto-approve those same tools without prompting. Saved approvals can be reviewed or revoked later from the task's **"Always allowed"** panel on its detail page.
		- **One caveat:** MCP tools an organization set to `ask`, or any tool marked `requiresUserInteraction`, always prompt and never offer an always-allow option — a task calling one of those stalls on every run regardless of permission mode.
		- **Bottom line:** not finding a way to set automatic permission is expected for a Cloud routine — there's nothing to configure, since it's already unattended. For a Local scheduled task, the setting exists; the durable "no more prompts" state comes from one manual **Run now** with "always allow" clicks, not from a single toggle.
