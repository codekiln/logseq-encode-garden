	- ## Volume is relaying
		- A chief absorbs a subagent's findings, not only its questions. A long, well-organized briefing that arrives with its decisions already made is the weeds moved rather than cleared, and being correct, complete, and legible is no defense.
		- The check before reporting: what decision does this need from the human? What turns on no decision gets digested to its outcome, or left out. A verification trail belongs on the page it verified, not in the report.
	- ## What belongs in this graph, and what does not
		- This garden is public, and a chief reads other repos' panes all day. A repo name picked up that way is not knowledge about [[Person/codekiln]] — it is somebody else's private context passing through, and a page here is the wrong place for it. Write the pattern and leave the repo unnamed.
	- ## Commits went to one agent
		- Three agents and the human were writing into the single checkout at `~/ghq/github.com/codekiln/logseq-encode-garden`. `encode-garden-scribe` took the journal and the commits, and the agents writing pages handed files over rather than running `git add` themselves. One stager gives one commit per finished thing instead of a sweep that bundles somebody else's half-written page.
		- Staging has an order as well as an owner. Reading a diff establishes what a file held at that moment, and `git add` runs after — so in a shared checkout an edit landing in between is committed unreviewed, and nothing reports it. Stage first, read `git diff --cached`, then commit, and the window closes.
	- ## Text in an input box is not the human
		- An idle agent may render a suggested follow-up where a typed line would sit, drawn from its own last turn. It is the machine talking to itself, and it is not evidence of human input in either direction — not consent, and not a reason to wait.
		- The tell is the rendering, and it is a property of the content rather than of the box. Generated text is emitted dim, wrapped as `ESC[2m … ESC[0m`; text that arrived as real input carries no styling, and neither does an idle pane's empty box. So the test is that dim wrapper around content, never the presence or absence of styling — read it as "no styling means a human typed it" and an idle pane's empty box becomes human input. `herdr agent read <name> --source visible --format ansi` shows the wrapper; a plain-text read flattens it away.
		- The give-away in the content is that each suggestion paraphrases the recommendation its own agent had just made. Six panes here carried one at once, each mirroring the report above it, and none of them were the human's. Six people do not half-type into six panes simultaneously, and the base rate was the cheapest check available.
		- The box is drawn in every state. During a turn it is drawn **empty**, with its prompt marker coloured grey — `ESC[38;2;153;153;153m` — so a mid-turn read comes back blank because the box holds nothing, not because the box is missing. That grey marker is itself a tell: it separates a working pane's empty box from an idle one's, which carries no styling at all.
		- An empty box otherwise says nothing. A suggestion **may** appear once an agent is idle or done, and often none appears — three idle panes read at one moment gave two dim suggestions and one genuinely empty box. So emptiness alone distinguishes neither a pane with no suggestion from a pane read too early, nor either from a pane whose occupant simply has nothing pending.
		- An agent cannot run this check on itself: it is working by definition while it looks, so it never sees the idle state it is asking about.
		- One pane carried the same string before and after a working interval with nothing typed in between. That looked like corroboration that a person had left a line sitting there. It is the opposite — an unchanged string across a working interval, with no one at the keyboard, is what a regenerated suggestion looks like. The observation that felt like confirmation was the tell, read backwards.
		- Treating that text as a reason to hold has a cost that never surfaces. A supervisor that will not prompt its own agents does not fail — it quietly absorbs their work into its own context, and from outside it only looks slow. Six panes sat idle here on that mistake, and a seventh agent was started purely to route around one of them.
		- That shape generalizes past input boxes: **a safety rule that silently collapses delegation back into the supervisor is worse than no rule**, because nothing reports the collapse.
		- Where the text really is the human's, it is still not authorization — a line nobody has pressed enter on is one its writer is free to rewrite or drop. Authority comes from a sent message or from delegated authority over the work. Where neither covers the case, the size of the decision settles it: small and reversible proceeds, while anything that sets a convention or is expensive to undo waits. An entity type with dozens of instances is the second kind.
		- Confirm intent over the cross-session channel, which reaches an agent without touching its box at all.
	- ## A closed pane is not lost work
		- Two panes in this workspace were closed before the cleanup started, and what those sessions concluded turned out to be already filed as pages. The check ran against the sessions' own transcripts rather than the panes: `~/.claude/projects/<project>/<session-id>.jsonl` holds one JSON object per line, and its `customTitle` field names what the session was about. 86 of those transcripts exist for this graph.
		- So harvest a session while its pane is still open, and read the transcript when one closes first.
