- Findings for [#348 Analyze B2 asset links across the garden and gitpa](https://github.com/codekiln/logseq-encode-garden/issues/348), which gathers the facts behind [#347 Link B2 assets by relative path and publish them as public URLs](https://github.com/codekiln/logseq-encode-garden/issues/347). Code links point at garden commit [590b8ea](https://github.com/codekiln/logseq-encode-garden/tree/590b8eae1278111d9dc0d52da8bab1a06634b477) and gitpa commit [2efc165](https://github.com/codekiln/gitpa/tree/2efc165606d4293d51e353ca633c059859a4846e).
- ## Inventory
	- About 1,500 garden pages link about 800 distinct B2 files, nearly all through `https://s3.us-east-005.backblazeb2.com/logseq-encode-garden/<file>`. Most file names contain spaces, written as `%20`. Most of the files are MicroFreak preset `.bin` files and manual screenshots; the rest are session recordings, MIDI files and a few photos.
	- gitpa's proxied pages link a subset of the same files. gitpa links no file that the garden leaves unlinked, so the garden's mount covers every gitpa link.
	- Every linked file is a public object at the bucket root, except a handful of links in log pages written before the naming settled:
		- `GitP/A/Log/26/10/04 Sun`, `…/Dvc for Knowledge Gardens/Plan` and `…/Podcast/Plan` link the September 24 recording through the older `https://f005.backblazeb2.com/file/logseq-encode-garden/…` form. Two of those names have no object behind them, and two keys sit under `gitpa/episodes/` rather than at the bucket root. These are historical log entries; the migration can leave them as written.
		- Two placeholders inside documentation (`<new…`, `<page-derived…`) look like links to the scanner and are examples.
	- Only two public objects have no page linking them: `GitP___A___Session___26___10___24-Sat___Asset___MIDI___Full.mid` and `IMG_0528.PNG`.
	- About two in five linked files have a DVC pointer in `assets/.remote/`. The rest, mostly the preset `.bin` files and about 70 screenshots, exist only as public objects, so DVC cannot restore them. Each needs `asset:add` (download, add, push) before its page switches to a relative link, or `asset:fetch` needs to fall back to the public URL.
	- Four WAV pages already link `../assets/.remote/<file>` by relative path. Their files are DVC backups with no public object. They move into the garden's mount folder along with everything else.
	- The bucket holds about 5.5 GB: about 1.4 GB of public objects at the root and about 4 GB of DVC cache under `dvc/`. A full local copy of every linked file is about 1.4 GB plus the WAVs, which fits on the Mac with room to spare.
	- The root checkout currently holds six local copies under `assets/.remote/`: three MP3s, two WAVs and one MIDI file.

- ## Where gitpa rewrites links
	- The website build reads the proxied graph through [prepare in prepare_site.py](https://github.com/codekiln/gitpa/blob/2efc165606d4293d51e353ca633c059859a4846e/scripts/prepare_site.py#L99-L157). The rewrite belongs where `prepare` loads each page body, before [listener_body](https://github.com/codekiln/gitpa/blob/2efc165606d4293d51e353ca633c059859a4846e/scripts/prepare_site.py#L55-L73) runs: `listener_body` accepts only `https://` links in an asset page and stops with "Expected one public media URL" on a relative one.
	- `prepare` ends with [shutil.copytree(source, output)](https://github.com/codekiln/gitpa/blob/2efc165606d4293d51e353ca633c059859a4846e/scripts/prepare_site.py#L154). `copytree` follows symbolic links by default, so on the Mac it would copy the whole garden folder behind `assets/.remote/logseq-encode-garden` into the temporary graph. The copy needs to skip `assets/.remote/`.
	- [compile_episode in audio_chapters.py](https://github.com/codekiln/gitpa/blob/2efc165606d4293d51e353ca633c059859a4846e/scripts/audio_chapters.py#L10) finds the recording with an `https://` pattern. The website build calls it on the prepared graph, after the rewrite. `test_source_publication` calls it on the checked-in page directly, so that test needs the rewrite applied first.
	- The feed reads the checked-in graph directly in [load_episodes in build_rss.py](https://github.com/codekiln/gitpa/blob/2efc165606d4293d51e353ca633c059859a4846e/scripts/build_rss.py#L76-L119). Both MP3 patterns there, on the episode page and on its asset page, require `https://`, so the rewrite runs on each body before those patterns.
	- Tests to extend: `test_prepare_site`, `test_build_rss`, `test_audio_chapters` and `test_source_publication`.
- ## What CI reads
	- No CI step in gitpa reads a local media file. The feed takes each enclosure's length and type from a HEAD request to the public URL ([audio_metadata](https://github.com/codekiln/gitpa/blob/2efc165606d4293d51e353ca633c059859a4846e/scripts/build_rss.py#L48-L54)). Chapters come from page text. The only local file a build reads is the podcast artwork under `gitp-garden/assets/gitp/`, which Git tracks.
	- The garden's site build runs `lsg publish` on the checkout itself ([main in mise-tasks/site/build](https://github.com/codekiln/logseq-encode-garden/blob/590b8eae1278111d9dc0d52da8bab1a06634b477/mise-tasks/site/build#L140-L176)). It has no step that edits page text. The rewrite needs a temporary copy of `pages/` and `journals/` with links rewritten, handed to `lsg` in place of the checkout, and that copy also leaves out `assets/.remote/` so a local build publishes no media.
- ## Proxy sync
	- [add_page in core.py](https://github.com/codekiln/gitpa/blob/2efc165606d4293d51e353ca633c059859a4846e/gitp-garden/mise-tasks/logseq/entity/proxy/page/lib/core.py#L402-L417) copies the target of every `../assets/` link into the destination. The garden's copy of the task matches gitpa's.
	- For a link under `../assets/.remote/<mount>/`, the sync copies no file. It looks up `<mount>` in the source garden's mount file and writes a borrowing declaration into the destination's mount file: the same `path` and `public`, with `source` naming the owning garden. A link into a mount the source does not declare stops the sync and names the page and the mount.
	- A borrowing declaration that already matches is left alone. One whose `path` or `public` differs stops the sync, since the destination's published URLs would change.
- ## A clean checkout
	- An agent working without local copies or B2 credentials sees links to missing files. The mount file maps each link to its public URL, so the agent can read or download any public file over HTTPS. `asset:fetch` needs the encrypted fnox cache in the main checkout and stops early without it.
	- Logseq in such a checkout shows broken images until the files are fetched.
- ## Path convention
	- A page links `../assets/.remote/<owning garden>/<file>`, with spaces written as `%20`. `<file>` is the page-derived name and the object's key at the bucket root.
