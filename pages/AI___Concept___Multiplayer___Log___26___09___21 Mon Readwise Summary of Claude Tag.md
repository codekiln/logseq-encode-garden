- # [Can you summarize some of the things I've heard and read about team-based agents such as Slack Tag and having agents added to slack channels?](https://readwise.io/chat/conversations/01m32hkk590q49pvzdg74pse43)
	- [[AI Answer]]
		- Based on your highlights, the rise of team-based agents represents a fundamental shift from "single-player" AI tools to [multiplayer or team agents](https://readwise.io/bookreview/63025623/?highlight=1047806463) that function as shared teammates within a company's existing communication channels.
		- Here is a summary of how these agents are transforming team workflows:
		- ### 1. The Shift to Multiplayer Collaboration
			- While early AI interactions were focused on individual productivity—like building a personal chief of staff—modern agents are designed to live at the [intersection where teams come together](https://readwise.io/bookreview/63025623/?highlight=1047806463). These [persistent Slack teammates](https://readwise.io/bookreview/61695516/?highlight=1029402859) have access to the entire context of a channel, meaning they can understand the history of a project without being manually briefed by every user. This allows a [teammate to pick up](https://readwise.io/bookreview/61695516/?highlight=1029401866) exactly where someone else left off, as the agent maintains a continuous memory of the work.
		- ### 2. Claude Tag and Persistent Teammates
			- A primary example of this trend is [Claude Tag](https://readwise.io/bookreview/63025623/?highlight=1047806463), which allows users to summon a version of Claude that is not tied to any single individual. Instead, it functions as an [organization-centric agent](https://readwise.io/bookreview/61791140/?highlight=1030620210) with its own permissions, tool access, and persistent memory. These agents can [take initiative](https://readwise.io/bookreview/61695516/?highlight=1029401866) by following up on quiet threads, flagging relevant information, and managing long-horizon tasks. In practice, companies are using them for everything from [incident response and bug triage](https://readwise.io/bookreview/61695516/?highlight=1029402859) to writing and shipping actual code directly from a Slack thread.
		- ### 3. Slack as a Collaborative IDE
			- For many engineering teams, Slack is evolving into a [collaborative development surface](https://readwise.io/bookreview/58802703/?highlight=996172072) that rivals traditional coding environments. Using tools like [Cursor's cloud agents](https://readwise.io/bookreview/58802703/?highlight=996162805), developers can kick off investigations in a channel, tag specific people for input, and have the agent produce [PR-ready artifacts](https://readwise.io/bookreview/58802703/?highlight=996162805) visible to everyone. This democratizes the development process; for instance, Anthropic reported that [65% of their product team's code](https://readwise.io/bookreview/61837082/?highlight=1031389023) now originates from Slack-triggered workflows, allowing non-technical team members to participate in the "multiplayable" code creation process.
		- ### 4. Specialized Coworker Agents
			- Beyond general assistance, your highlights mention the use of specialized [coworker agents](https://readwise.io/bookreview/60717656/?highlight=1019232659) that handle functional roles. For example, an editorial team might use an agent named [Andy](https://readwise.io/bookreview/60717656/?highlight=1019232659) to collect "nuggets" of story ideas from Slack threads and turn them into newsletter drafts. Other specialized agents can act as [always-on product managers](https://readwise.io/bookreview/60862149/?highlight=1020762123), maintaining a "memory.md" file that tracks priorities and tags humans when their input is needed for recurring tasks.
		- ### 5. Headless Software and the Agentic OS
			- This evolution is part of a broader move toward [headless software](https://readwise.io/bookreview/59974345/?highlight=1010373002), where the goal is to have work happen inside the conversation rather than forcing humans to log into separate dashboards. Salesforce and Slack are positioning themselves as an [agentic OS](https://readwise.io/bookreview/55644061/?highlight=948289419) where the [conversation is the interface](https://readwise.io/bookreview/59974345/?highlight=1010372879). In this model, agents call APIs and run commands in the background, surfacing only the necessary approvals and decisions within the Slack channel. This allows for [human-agent collaboration](https://readwise.io/bookreview/60717656/?highlight=1019232660) where agents handle the stable, repeatable layers of work while humans manage the creative and strategic end-results.
