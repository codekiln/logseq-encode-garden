	- Keep production notes, asset records, entity definitions, and reusable proxy automation in logseq-encode-garden. Gitpa owns episode selection, listener presentation, RSS, and website deployment. A resync reproduces source page bodies under the same names while preserving destination properties.
	- ## Findings
		- [Gitpa PR #12 — publish sessions from garden proxies](https://github.com/codekiln/gitpa/pull/12) contains matching session and asset proxies. The session and asset proxy bodies match their sources in [garden PR #178 — use session pages as episode sources](https://github.com/codekiln/logseq-encode-garden/pull/178). The source PR remains open, so these pages are not yet available in the main garden. The November source is `GitP/A/Session/24/11/19-Tue`; the different path quoted in the review does not identify that page.
		- Gitpa lacks the proxied Asset/B2, Podcast/Episode, and Proxy/Page definitions. Its sync command follows embeds and GitP asset links, but does not carry entity definitions or task implementations. The current Proxy/Page definition describes manual syncing without a reusable script.
		- [Mise Task](https://github.com/codekiln/logseq-encode-garden/blob/main/pages/Logseq___Entity___Mise___Task.md) already exists as `Logseq/Entity/Mise/Task`. Extend this entity to cover portable implementations and their dependencies.
		- The review also reports [clutter, failed audio/GIF rendering, and unavailable source pages](https://github.com/codekiln/gitpa/pull/12#discussion_r4182600404), plus a [broken homepage query](https://github.com/codekiln/gitpa/pull/12#discussion_r4182628597). The query includes `[(get ?props :public) true]`, which treats `true` as a result binding. Asset links currently name the public `logseq-encode-garden` bucket. Check anonymous asset access to determine whether hosting or rendering causes the media failures.
		- Anonymous checks on October 5 returned `200` for every episode asset, `audio/mpeg` for recordings, and `image/gif` for artwork. MP3 range requests returned `206` with `Content-Range`. The public assets are available; browser rendering still needs verification.
