		- A claim about [[tmux]] session names went out having been tested only against targets that named a window explicitly, `session:0`. None of the three lacked evidence; all three had it one command away.

	- ## A guard can be committed, correctly aimed, and never have run
		- This graph declares a pre-commit identity guard in a tracked `lefthook.yml`, whose own opening comment says it exists to keep personal and employer identifiers out of a public graph. It had never executed. `lefthook install` writes dispatchers into `.git/hooks`, that directory held nothing but the stock samples, and its mtime predated the commit that added the guard by twelve days — so the guard was declared, tracked, and inert for seventy-five days while the thing it was written to prevent happened.
		- `.git/hooks` is not tracked, which makes this the default state of every fresh clone rather than a slip in one checkout. A repository can only ship the declaration; whether it runs is per-clone and invisible from the repository.
		- The reason it is worse than having no hook at all is that it inspects clean. A missing hook is visible to anyone who looks; a tracked config naming the exact failure mode reads as protection from every place a person would check, including the commit that introduced it. **The reading is `ls .git/hooks`, not the config file.**

	- ## An exemption can read as applied and do nothing
		- Suppressing a check on one line has two silent failure modes here. An in-file directive written with a colon before its reason is ignored entirely. A directive on a file's final line is ignored when the file has no trailing newline, which is the state of 491 of 800 pages sampled in this graph.
		- Both produce the same artefact: an annotation that is present, correctly spelled, carrying a good reason, on the right line, and dead. It survives review because reviewing it means reading it, and reading it is exactly what makes it look right.
		- This is the same defect as a redaction tool that reports clean after removing one of five identifiers — a mechanism certifying an outcome it did not produce. Having met it twice from opposite directions, the rule is to re-run the check after suppressing it, never to annotate and move on.
