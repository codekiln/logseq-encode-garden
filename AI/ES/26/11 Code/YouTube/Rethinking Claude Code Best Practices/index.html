  • Rethinking Claude Code Best Practices — Lydia Hallie, Anthropic

    • Person/Lydia Hallie of the Claude/Code team at Anthropic gave this talk on the main stage of AI/ES/26/11 Code on 2026-11-11 Wed. Technical difficulties interrupted the live talk, so she recorded it again at home that day. The AI Engineer channel published the recording.
    • Lydia starts from a Claude Code session of early 2026 (Opus 4.5, manual approvals, a CLAUDE.md full of "IMPORTANT") and shows, for each step a person used to do, whether the model, the harness, or the environment now does it.

    • Video

        • Key takeaways

          • 02:46 Start from today's defaults: Anthropic/Model/Claude/5/5/Opus and auto mode, which became the default permission mode in August 2026.
          • 03:19 Cut CLAUDE.md down to what Claude can't see from the code. "IMPORTANT" and "never do this!" lines now push the model off track, which means more tool calls and worse results. /doctor prompt-audit checks CLAUDE.md and skills for what the current model no longer needs.
          • 04:48 When auto mode still blocks routine work, describe your trusted repos, buckets and domains in plain English in the autoMode block of your settings. The classifier reads that text.
          • 05:46 Auto mode blocked 89% of dangerous commands in Anthropic's August study, against 14% caught by people, so about one in ten still went through. Deny rules are the guarantee: Claude Code checks them before the classifier, which never sees a matching call.
          • 06:32 Decide what needs a rule by asking "if Claude gets this wrong once, can I take it back?" Wrong code can be reverted, so leave it to the model. Losing uncommitted changes or exposing a secret can't be taken back, so write a rule.
          • 07:56 Permissions decide whether a tool call runs. A sandbox limits what the command and its child processes can read, write and reach, and the operating system enforces it, so a compromised dependency inside npm test can't open .env. The sandbox covers shell commands only; Read, Edit, WebFetch, MCP servers and hooks run outside it.
          • 09:10 Run long sessions in a cloud session (Claude/Code/Cloud Session). Each one gets its own machine with a fresh copy of the repo and keeps running with the laptop closed. .env, SSH keys and the GitHub token aren't there, API keys go in as network secrets, and network access is limited by default. Keep auto mode on and commit deny rules to the repo, because pushed commits and sent messages outlive the disposable machine.
          • 10:54 Set up verification points that pass or fail along the way: tests, a build, a screenshot. In the prompt, say what done looks like, ask for tasks that each have a test, and ask to see the test output.
          • 12:07 Use hooks for checks that must run: lint after every edit (PostToolUse), the changed area's tests when a task completes (TaskCompleted), the whole suite at the end (Stop). Exit with code 2 to send Claude back to fix it; with exit code 1 the task is marked completed anyway.
          • 14:00 Once many sessions run, CI matters most, because it runs the same checks on every PR. CI auto-fix lets Claude fix failing checks, and merge when ready lets GitHub merge low-risk PRs once checks pass.
          • 14:39 Tier human review by risk. On her team Claude reviews every PR first, from a fresh context with a separate group of agents to double-check each bug, and then: "smaller changes like docs or copy, they don't need a person ... ordinary product changes just need one reviewer and then risky changes might need two."
          • 15:10 Hand session starts to an orchestrator. Claude Code projects (beta) take one request, split it into threads that are new sessions, verify what comes back, and manage context automatically. Use a model that decides and judges, like Fable, for the main session, and one that does the work, like Opus 5.5, for the threads.
          • 17:02 To try it, give Claude a task much bigger than usual, make sure CI catches what you care about, configure the cloud environment's network access, secrets and setup script, then start in the cloud and see where sessions get stuck.
