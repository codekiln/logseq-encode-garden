  • Can you summarize some of the things I've heard and read about team-based agents such as Slack Tag and having agents added to slack channels?

    • AI Answer
      • Based on your highlights, the rise of team-based agents represents a fundamental shift from "single-player" AI tools to multiplayer or team agents that function as shared teammates within a company's existing communication channels.
      • Here is a summary of how these agents are transforming team workflows:

      • 1. The Shift to Multiplayer Collaboration

        • While early AI interactions were focused on individual productivity—like building a personal chief of staff—modern agents are designed to live at the intersection where teams come together. These persistent Slack teammates have access to the entire context of a channel, meaning they can understand the history of a project without being manually briefed by every user. This allows a teammate to pick up exactly where someone else left off, as the agent maintains a continuous memory of the work.

      • 2. Claude Tag and Persistent Teammates

        • A primary example of this trend is Claude Tag, which allows users to summon a version of Claude that is not tied to any single individual. Instead, it functions as an organization-centric agent with its own permissions, tool access, and persistent memory. These agents can take initiative by following up on quiet threads, flagging relevant information, and managing long-horizon tasks. In practice, companies are using them for everything from incident response and bug triage to writing and shipping actual code directly from a Slack thread.

      • 3. Slack as a Collaborative IDE

        • For many engineering teams, Slack is evolving into a collaborative development surface that rivals traditional coding environments. Using tools like Cursor's cloud agents, developers can kick off investigations in a channel, tag specific people for input, and have the agent produce PR-ready artifacts visible to everyone. This democratizes the development process; for instance, Anthropic reported that 65% of their product team's code now originates from Slack-triggered workflows, allowing non-technical team members to participate in the "multiplayable" code creation process.

      • 4. Specialized Coworker Agents

        • Beyond general assistance, your highlights mention the use of specialized coworker agents that handle functional roles. For example, an editorial team might use an agent named Andy to collect "nuggets" of story ideas from Slack threads and turn them into newsletter drafts. Other specialized agents can act as always-on product managers, maintaining a "memory.md" file that tracks priorities and tags humans when their input is needed for recurring tasks.

      • 5. Headless Software and the Agentic OS

        • This evolution is part of a broader move toward headless software, where the goal is to have work happen inside the conversation rather than forcing humans to log into separate dashboards. Salesforce and Slack are positioning themselves as an agentic OS where the conversation is the interface. In this model, agents call APIs and run commands in the background, surfacing only the necessary approvals and decisions within the Slack channel. This allows for human-agent collaboration where agents handle the stable, repeatable layers of work while humans manage the creative and strategic end-results.
